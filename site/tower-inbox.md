# 待辦分頁與塔台設定

塔台要你決定的事、要你親手做的事，不再只是一段會被新輸出捲走的對話。這一頁說明右側欄的「待辦」分頁、塔台分頁建議的 claude 設定，以及選用的 `bat-hooks` plugin。 {.ct-intro}

## 待辦分頁 {#inbox}

「待辦」在右側欄，預設排在「塔台」分頁左邊，收合時的圖示是 📥。它把需要你處理的事集中成一份清單；可以像其他側欄分頁一樣移到左側或主區。 {.ct-lead}

### 需要的版本 {#versions}

待辦分頁需要 BAT 與 Control Tower 都支援「BAT ↔ CT 契約 v2」：Control Tower **6.1.0** 以上，加上支援契約 v2 的 BAT（各功能的最低版本見[版本對照](./compatibility)）。塔台開工時會向 BAT 宣告它用的是契約 v2。

任一邊太舊時，待辦分頁只顯示塔台選擇器與一行說明，告訴你該升級哪一邊；下面的清單、回合訊息卡與通知保護都停用，其他功能照舊。分頁標題會出現 `!`。

| 你看到的說明 | 原因 | 怎麼辦 |
|---|---|---|
| 塔台的 Control Tower 沒有宣告契約 v2 | 塔台的 Control Tower 比 6.1.0 舊，或塔台不是用 Control Tower 開的 | 升級 Control Tower，再重新開啟塔台 |
| 塔台使用的契約比這版 BAT 新 | BAT 比 Control Tower 舊 | 升級 BAT |
| `_tower-state.md` 還是 v1 | 塔台已宣告契約 v2，但這個工作區的狀態檔還沒更新 | 等塔台開工時寫入；一直看到時，確認工作區資料夾就是塔台所在的專案，或在塔台執行 `*sync` |
| 這個工作區沒有 Control Tower | 找不到 `_ct-workorders/`，也沒有已宣告的塔台分頁 | 不需要處理 |

「等你回答對話框時不送通知」（塔台停在權限確認、提問時，Worker 的通知先保留）不受版本限制，舊版 Control Tower 也有。

### 各區塊 {#sections}

區塊順序固定，從「一定要你處理、會擋住流程」排到「參考用」。沒有內容的區塊只留一行標題，有內容的可以摺疊，摺疊狀態記在這台電腦上。

| 區塊 | 內容 | 你可以 |
|---|---|---|
| ⏸ 待你決定 | 塔台寫下、要你做決定的事，附上它來自哪張工單、哪個斷點；對應的工單會標「暫停中」 | 點選項後送出，或自由回答一行 |
| 🙋 待你執行 | 要你親手做的事（例如實機驗收、在 BAT 以外執行的指令），以及待驗收的 BUG | 複製指令、回報完成或失敗、開啟 BUG |
| ⏰ 到期提醒 | 已到期或 7 天內到期的提醒 | — |
| 👷 Worker 等你 | 停在權限確認或提問的分頁、有通知在待送的分頁、被中斷的分頁 | 切到分頁、恢復被中斷的分頁 |
| 💬 塔台訊息 | 塔台每回合最後一則訊息一張卡片 | 展開閱讀、釘選、全部已讀、清除 |
| 📋 塔台待辦 | 塔台的長期待辦（`todo`），長的項目摺疊成第一行 | 展開閱讀 |
| 📊 數量 | 未結 BUG、進行中 PLAN、未結工單的數量 | 點一下開啟指揮塔的對應頁面 |

- 分頁標題的數字是前四區的件數；塔台訊息的未讀數不算進去，只顯示在「💬」區標題與塔台縮圖，不會催你。
- 塔台分頁的縮圖多兩個標示：`⏸N` 是待你決定的件數，`💬N` 是未讀的塔台訊息，點一下開啟待辦分頁。工作區列表也會顯示 `⏸N`。
- 同一個工作區有好幾個塔台時，分頁頂端可以選要看哪一個。
- BAT 只讀 Control Tower 的檔案，不會改寫它們。指揮塔總覽的「待辦」改成一行「到待辦分頁查看」；版本不符時總覽照舊列出完整待辦。

### 怎麼回答 {#answer}

按下送出時，BAT 對塔台分頁送一行純文字，例如 `U-3：B`、`A-2：完成`、`A-2：失敗 安裝檔打不開`，和你自己在塔台輸入完全相同。塔台讀到後處理，處理完的項目會從清單消失，移到「最近已結」。

- **選項**：點選項再按「送出」，送出的是選項代號。選項格式不對時改成自由回答。
- **自由回答**：在欄位輸入一行，按 Enter 或「送出」。
- **指令**：🙋 的「複製指令」只會複製，BAT 永遠不替你執行。
- **塔台在忙時**：塔台正在等你回答對話框，或輸入框有你打到一半的字時，回答不會打斷它，而是排進縮圖的「📨 待送」，你處理完後自動送出。每一筆下方會顯示結果：已送出、已排入待送、或沒送出的原因。
- **好幾個塔台**：工作區有多個塔台時，該筆下方會讓你選要送給哪一個。
- **Claude Agent 面板當塔台**：工作區沒有已宣告的塔台分頁、而 `_tower-state.md` 是契約 v2 時，這個工作區的 Claude Agent 面板都算塔台，回答會放進面板送出。面板輸入框已經有字時不會送，請先送出或清掉。

你也可以直接在塔台分頁輸入同樣的一行，結果一樣。

### 推薦選項與放棄 {#recommended-dismiss}

Control Tower **6.2.0** 以上的塔台會標出它推薦哪個選項，也讓你放棄不想做的決定、略過不想做的驗收。

- **推薦**：塔台推薦的選項旁有「推薦」標記，而且已經先幫你選好，同意就直接按「送出」；想選別的，點別的選項就好。選項說明裡的「（推薦）」字樣照原樣保留。
- **放棄一筆**（⏸ 待你決定）：按「放棄…」，可以在欄位寫原因或新方向（選填），再按「送出放棄」。送出的是 `U-3：放棄` 或 `U-3：放棄 改走另一個方案`。塔台不套用任何選項，相關工單維持暫停；有寫新方向時，塔台照你的文字重新對齊。
- **略過一筆**（🙋 待你執行）：按「略過…」，原因選填，送出 `A-2：略過` 或 `A-2：略過 這版不驗`。略過不是失敗：塔台把它記成「未驗（使用者略過）」，不會開 BUG。
- **一次處理好幾筆**：每筆前面有勾選框。勾好後按區塊上方的「放棄勾選（N）」或「略過勾選（N）」；要整區都不做就按「全部放棄」或「全部略過」。送出前會先列出這次要送的編號讓你確認，可以再寫一段共用的原因。每個區塊送一行，例如 `U-1、U-3、U-4：放棄 整批不做`。
- 「全部」以你按下送出那一刻畫面上列出的編號為準，不會順帶處理之後才出現的項目。
- 這些按鈕只在塔台的 Control Tower 支援時出現（6.2.0 以上）；較舊的塔台看不到，畫面和以前一樣。
- 塔台正開著選單問你同一件事時，從這裡送出的回答會先排進「📨 待送」，選單關掉後才送；如果你已經在選單裡回答了，塔台會回一行「編號已結」，不會重複處理。

### 塔台訊息 {#messages}

塔台每回合結束時，最後一則訊息會變成一張卡片，讓你回頭找「它剛剛總結了什麼、問了什麼」，不用在終端裡往上捲。

- 釘選的卡片在最上面，其餘新的在上；展開就算已讀，長的卡片先顯示開頭。
- 以「⏸ 待你決定：」或「🙋 待你執行：」開頭的行會加亮，方便一眼找到；真正的待辦仍以上面的清單為準。
- 卡片只存在 BAT 的記憶體裡：每個塔台最近 30 張，另可釘選 10 張；塔台分頁關閉或重開 BAT 後就沒有了。看起來像密碼或權杖的內容會先遮罩。
- **Codex 塔台**沒有卡片：BAT 不讀 Codex 的對話內容，這一區固定顯示一行說明，其他區塊照常。
- **claude 太舊**：claude 2.1.47 以上才會在回合結束時交出最後一則訊息。用系統安裝的舊版 claude 時，這一區會提示升級，或到「設定 › 進階 › Claude Runtime」改用 BAT 內附的 claude。

### 通知不打斷你 {#notify-protection}

契約 v2 的塔台另外有三種保護，Worker 回報時不會打亂你正在做的事：

- **不搶畫面**：Worker 的通知送進塔台時，畫面不捲動、選取的文字不會被清掉、焦點不會跳到塔台分頁。
- **不混進你打到一半的字**：塔台輸入框有你還沒送出的文字時，通知先排進「📨 待送」，等你送出或清掉再送。保留超過 5 分鐘會跳一次系統通知；急的話可以在縮圖的「📨 待送」選單按「立即送出」，通知會接在你的文字後面一起送出。
- **你在閱讀時延後**：你往上捲、選取文字或用滾輪時，通知延後到停手 10 秒才送，最長延後 60 秒。全螢幕介面往上捲之後，通知會等到你按鍵、在塔台裡點一下、切到別的分頁或捲回底部才送（同樣最長 60 秒）。

## 塔台分頁建議設定 {#tower-settings}

塔台常常一邊收 Worker 的回報、一邊讓你往回看它的總結。用 claude 當塔台時，建議在塔台分頁做下面的設定： {.ct-lead}

| 設定 | 怎麼做 | 效果 |
|---|---|---|
| 全螢幕介面 | 在塔台輸入 `/tui fullscreen` | claude 改用全螢幕介面，對話有自己的捲動區 |
| 關掉 Auto-scroll | `/config` → 「Auto-scroll」關閉（只在全螢幕介面有這個選項） | 你往上捲時，新輸出不會把畫面拉回底部 |
| Focus view | 在全螢幕介面輸入 `/focus` | 只顯示你的輸入、摘要與回應，每回合的總結比較好找 |

- 這些都是 claude 自己的設定，BAT 不會替你改，也不會替你開全螢幕介面。
- 全螢幕介面下，BAT 看不到 claude 內部的捲動，只看得到滾輪與 PageUp：往上捲之後，通知會等到你按鍵、在塔台裡點一下、切到別的分頁或捲回底部才送，最長等 60 秒。「捲回底部」是依滾輪量估算的，可能和 claude 實際的位置不同；還沒到底就被當成捲回時，通知會在停手 10 秒後送出。

## `bat-hooks` plugin（選用） {#bat-hooks}

BAT 靠 claude 的 hooks 知道塔台與 Worker 在等你回答、回合開始與結束、claude 已啟動；塔台訊息與「等你回答時不送通知」也靠它們。 {.ct-lead}

### 大多數情況不用裝 {#bat-hooks-when}

BAT 開的 Claude CLI 分頁（縮圖列「+」選單的 Claude CLI、「以塔台開啟 Claude」、塔台派出的 Worker）會自動帶入 BAT 的 hooks，不用做任何事。只有下面三種情況 BAT 帶不進去：

- 在一般 shell 分頁裡手打 `claude`，包含在 WSL、SSH、Docker 視窗裡手打
- 這個 Agent 的自訂啟動參數已經有 `--settings`
- 「設定 › 進階 › BAT MCP」已關閉（hooks 跟著 BAT MCP 一起關）

這時塔台開工會看到 `hooks: none (<原因>)`，契約 v2 的塔台縮圖出現 `🪝✕`，待辦分頁頂端多一行說明。你可以照說明改回由 BAT 開啟，或安裝 `bat-hooks` plugin。

### plugin 做什麼 {#bat-hooks-what}

`bat-hooks` 是 BAT 在 GitHub 上提供的 Claude Code plugin。它只有一個小程式：在 BAT 的分頁裡，執行**這個分頁所屬 BAT** 的 hook 腳本，所以永遠與 BAT 同版；不在 BAT 裡時立即結束、什麼都不做。

- plugin 不含任何權杖；BAT 不會替你安裝，也不會改 claude 的設定。
- 需要 `node` 在 PATH 上。遠端主機沒有安裝 node 時，claude 會把它當成 hook 錯誤（不影響使用）。
- BAT 自動帶入的 hooks 與 plugin 同時存在時，以自動帶入的為準，每個事件只算一次。
- claude 自己的設定關掉 hooks（`disableAllHooks`、組織的 managed 設定、專案的 `.claude/settings*.json`）時，plugin 一樣不會執行，請依提示處理你自己的設定。

### 安裝、升級、移除 {#bat-hooks-install}

在要用的那台主機上執行 claude 的指令；遠端主機要在遠端執行。

```bash
# 安裝
claude plugin marketplace add gowerlin/better-agent-terminal
claude plugin install bat-hooks@better-agent-terminal

# plugin 比 BAT 舊時（塔台看到 plugin-outdated）
claude plugin update bat-hooks@better-agent-terminal

# 移除
claude plugin uninstall bat-hooks@better-agent-terminal
```

- 升級 BAT 不用動 plugin；只有新版 BAT 增加了 hook 事件時，塔台會提示 `plugin-outdated`，再執行上面的 update。
- 只解除安裝 BAT 時，plugin 會變成什麼都不做、不會報錯，建議一併移除。

### 塔台開工時的 `hooks:` 行 {#hooks-line}

| 塔台看到 | 意思 |
|---|---|
| `hooks: ok (injected, set <n>)` | BAT 自動帶入的 hooks 正常（`<n>` 是 hook 事件清單的版本） |
| `hooks: ok (plugin, set <n>)` | 由 `bat-hooks` plugin 提供，正常 |
| `hooks: ok (plugin, set <n>, plugin-outdated)` | plugin 的事件清單比 BAT 舊，請執行 update |
| `hooks: none (<原因>)` | 沒有 hooks，原因與修法見待辦分頁頂端的說明 |
| `hooks: n/a (codex)` | Codex 塔台不使用 claude hooks |

這一行只在塔台以 Control Tower 6.1.0 宣告契約 v2 時出現。

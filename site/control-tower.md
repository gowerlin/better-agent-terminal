# 與 Control Tower 協作

這一頁說明 Better Agent Terminal（BAT）與 BMad Control Tower 一起用時，每一步發生什麼、BAT 提供什麼、你要做什麼。 {.ct-intro}

::: info Control Tower 目前未公開提供
BAT 的派工、回報、提問與查詢介面都是公開的，你可以拿來接上自己的流程，見[BAT 提供的整合點](#integration)。
:::

## Control Tower 是什麼 {#what}

Control Tower 是一套以檔案驅動的多 Agent 開發流程：一個分頁當塔台負責想清楚，其他分頁當 Worker 負責做。 {.ct-lead}

<dl class="ct-concepts">
<div>
<dt>塔台</dt>
<dd>和你對齊需求、開工單、派工、驗收、做決定的那個 Agent 分頁。它不自己寫程式。</dd>
</div>
<div>
<dt>Worker</dt>
<dd>一張工單一個 Worker 分頁。Worker 只帶那張工單的脈絡上工，做完回報塔台。</dd>
</div>
<div>
<dt>工單</dt>
<dd>一個 Markdown 檔，寫清楚目標、範圍、驗收條件與禁止事項；Worker 的回報也寫在裡面。</dd>
</div>
<div>
<dt>決策紀錄</dt>
<dd>塔台做過的每個決定和理由。它也是 repo 裡的檔案，和程式碼一起進版控、一起 review。</dd>
</div>
</dl>

塔台與 Worker 都是一般的 Claude Code 或 Codex 分頁，照著同一套流程規則工作。Control Tower 定規則；BAT 提供讓規則跑起來的終端機、分頁、通知與權限。兩邊各自開發，以 BAT 公開的介面接在一起。

想看 Control Tower 本身的完整介紹（四級能力、工單狀態、自我學習、多塔台協調等），見[功能導覽](./control-tower-tour)。

Control Tower 定規則，BAT 提供跑道、無線電和雷達。 {.ct-lead}

最後一列是塔台最重要的習慣，下一節說明原因。

## 塔台的分工原則 {#tower-principles}

塔台管全局，Worker 管細節；問題依性質送到對的人手上。 {.ct-lead}

### 塔台刻意不讀程式碼

塔台把注意力留給全局：進度、相依關係、做過的決定。需要看程式碼時，它派一張分析工單，讓 Worker 去讀、把結論寫回來，自己只讀結論。所以塔台可以撐完一整批工單，每個 Worker 也都從乾淨的脈絡開始。

要知道 Worker 做到哪裡，塔台用 BAT 的唯讀查詢看狀態與輸出，不必自己進分頁。這是塔台自己守的分工；BAT 的權限只管分頁能用哪些 BAT 功能，不管塔台讀不讀程式碼。

### 「做什麼」問塔台，「怎麼做」問 Worker

<CardTable caption="問題該問誰" :columns="['問題', '問誰', '例子']" :rows="askWhoRows" />

Worker 執行中遇到需要決定的事，會用 BAT 的提問通道直接問塔台；範圍內的選擇由塔台回答，其餘才轉給你（見[Worker 問塔台](#questions)）。

## 自主程度與斷點 {#autonomy}

自主程度決定塔台自己推進多少；不管選哪一檔，斷點出現時都會停下來問你。 {.ct-lead}

<CardTable caption="自主程度對照" :columns="['自主程度', '塔台', '你', 'Worker 有問題時']" :rows="modeRows" />

### 一定會停下來問你的時候

- 範圍要擴大
- 刪除，或其他不可逆的操作
- 對外發布：push、發版
- 需要你的偏好才能決定的選擇
- 連續失敗（見[卡住就停](#messy)）

斷點出現時，塔台在自己的分頁裡停下來問你，Worker 不會替你做這些決定。

## Worker 問塔台 {#questions}

Worker 有問題時不必停下來等你：先問塔台，塔台答得了的就答，答不了的才轉給你。 {.ct-lead}

<QuestionFlow />

- **只在 yolo 模式使用**：其他自主程度下，Worker 直接在自己的分頁裡問你。
- **問答不落地**：問題與答案只存在 BAT 的記憶體裡，收到時先遮罩看起來像祕密的內容；日誌只記長度與結果，不記內容。
- **你打字不會打斷提問**：在等答覆的 Worker 分頁裡輸入，不會取消它的問題，也不會清掉「? 在等塔台答覆」。
- **BAT 重開後**：還沒答覆的問題會消失，Worker 改走工單通道。

## 現實比計劃更混亂時 {#messy}

計劃趕不上變化時，塔台有固定的處理方式，不會讓你在一團亂的對話裡追進度。 {.ct-lead}

<FeatureGrid set="messy" />

就算 BAT 重開，只要背景的 Terminal Server 還在執行，你可以選擇保留原本的分頁，Worker 接著做。

臨時插隊、問題一層一層冒出來、兩邊都要改，這三種情況的完整經過見[實戰案例](./cases)。

## 平行與 worktree 隔離 {#parallel}

要讓好幾個 Worker 同時開工，先確認它們不會互相踩到；真的要平行，就讓每個 Worker 在自己的分支上做。 {.ct-lead}

### 先比對會動到的檔案

每張工單都寫明會動到哪些檔案。派工前，塔台先比對這些清單，有重疊就提醒你，或排成先後順序。

### 每個 Worker 一個 worktree

派工時選擇隔離，BAT 會在 repo 旁邊建一個獨立的 git worktree，分支叫 `ct/T1024`，Worker 就在裡面工作，主 checkout 不受影響。BAT 不替你合併，也不替 worktree 安裝相依套件：合併由塔台安排，相依套件由 Worker 依專案的說明安裝。

<StoryIllo kind="branches" />

### 合併前先看狀態

塔台可以向 BAT 查每條隔離分支的狀態，Worker 分頁關掉之後也查得到：

- 比主線領先多少、落後多少
- worktree 裡有沒有未提交的變更
- 改了哪些檔案，其中哪些不在工單列的範圍內
- 兩邊都往前走時，合併會不會衝突、衝突在哪些檔案

落後 0、也沒有未提交的變更，就能直接快轉合併；其他情況先更新分支，或另派一張合併工單。這些查詢都是唯讀的，BAT 不會替你 checkout、合併或 commit。

## 看得見每個 Agent {#visibility}

不用一個一個點進分頁，也知道每個 Agent 在做什麼、在等誰。 {.ct-lead}

### 分頁標題就是身分

塔台分頁叫 `Claude CLI · Tower`，Worker 分頁叫 `Claude CLI · Worker · T1024`、`Codex CLI · Worker · T1025`。前面是 Agent，後面是工單編號。你自己改過名字的分頁，BAT 不會改回去。

### 縮圖直接標出誰在等誰

<StoryIllo kind="thumbnails" />

同時有好幾種狀態時，依「⚠️ 在等你」、「? 在等塔台答覆」、「✓ 已回報」的順序顯示最需要處理的那一個；沒有符號就是還在執行。按右鍵「關閉已回報的 Worker 分頁」時，只有 ✓ 的分頁會被關掉，在等你或在等塔台的都會留著。

### 等人回答偵測

Worker 停在權限確認、停下來問你問題，或在等你填表單時，BAT 都能知道（支援範圍見下表），塔台查狀態時會看到它「在等人」，而不是誤以為它還在工作。

<CardTable caption="各 Agent 支援的偵測" :columns="['', 'Claude CLI', 'Codex CLI', '其他 CLI']" :rows="detectRows" />

### 唯讀 MCP 查詢

BAT 開的 Claude CLI 與 Codex CLI 分頁會自動掛上一組唯讀的 MCP 工具：查自己是誰、列出看得到的分頁、查狀態、讀輸出、等狀態變化、查 worktree 狀態、列出提問、等提問的答覆。讀輸出時，看起來像祕密的內容會先遮罩。看得到什麼由分頁的權限決定（見下一節）。不想要可以在「設定 → 進階」關掉。

## 權限模型 {#permissions}

每個分頁拿到的是自己的專屬權杖，能用哪些 BAT 功能，由它是塔台還是 Worker 決定。 {.ct-lead}

<CardTable caption="塔台與 Worker 能用的 BAT 功能" :columns="['', '塔台', 'Worker']" :rows="permissionRows" />

- 權限預設拒絕：表上沒列的，兩邊都不能用。
- BAT 本身的伺服器權杖不會放進任何分頁；分頁結束，它的權杖就失效。
- 塔台要在一般分頁裡啟動。在 Worker 分頁裡開塔台，拿到的是 Worker 的權限，不能派工。
- 這些限制只管分頁能用哪些 BAT 功能。塔台與 Worker 本身是你電腦上的 Agent，它們能讀寫哪些檔案，仍由 Agent 自己的權限設定決定。

## 支援的 Agent 與遠端 {#agents}

Claude Code 與 Codex 都能當塔台，也都能當 Worker；本機與遠端用的是同一套流程。 {.ct-lead}

- **混著用**：一個塔台可以同時派出 Claude Code 與 Codex 的 Worker。派工時可以指定 Agent；沒指定時，先用工作區設定的預設 Agent，沒設就用「設定」裡的預設，都沒有就用 Claude Code。
- **偵測能力**：啟動確認與等人回答偵測，Claude CLI 分頁都支援，Codex CLI 需要 0.163.0 以上（見[等人回答偵測](#visibility)）。
- **遠端**：WSL、SSH、Docker 視窗裡的塔台與 Worker，用同一套派工、回報、提問與權限；每個遠端分頁一樣拿到自己的權杖。遠端那一側也要能執行 Control Tower。

## 越用越懂你的專案 {#learning}

第一天它照工單做事；第三個月，它照你的專案做事。 {.ct-lead}

### 說一次，之後每張工單都記得

你的團隊規矩，例如 API 一律用 POST、review 固定檢查哪幾項、某個資料庫版本有效能問題，只要跟塔台說一次，它就會記下來。之後派出的每張工單都會帶上相關提醒，不必每開一個 Agent 就重講一遍。

這和 BAT 的工作區設定是兩回事：BAT 記住的是每個工作區的預設 Agent、啟動參數與環境變數；團隊規矩由塔台記。

### 經驗會長大

塔台會從做完的工單裡整理出觀察，好用的做法一步步升級：

<GrowthLadder detailed />

### 你教的東西不會被升級蓋掉

你教給塔台的規則，和 Control Tower 本身分開存放。Control Tower 升級時不會動到它們，而且你的規則優先於預設。

### 規則可以帶到下一個專案

另一個專案用得很順的規則，可以搬進新專案。塔台會先列出哪些是新增、哪些有衝突、哪些會跳過；有衝突時問你要保留哪一版，你同意之後才寫入。

### 十分鐘問答，塔台就照你的習慣做事

第一次用時，塔台會用幾題選擇題問你：commit 的習慣、哪些小事不必開工單、Worker 做完要不要自動 commit、模糊的問題要先研究還是直接討論。答案會寫成這個專案的工作規則。

### 教戰手冊：什麼情境用什麼做法

規定清單只說規定是什麼；教戰手冊同時寫出為什麼這樣做、遇到哪種情況選哪個、專案裡哪個檔案就是範例。Worker 寫新功能時照著判斷，結果會跟團隊手寫的一致，不會每個 Agent 各自發揮。

手冊也會跟著程式碼一起長：塔台從做完的工單回報裡挑出新慣例補進手冊。它也會比對手冊和程式碼哪裡已經脫節，清點同一件事目前有幾種寫法、建議統一成哪一種，再開成重構工單。

### 從程式碼抽出視覺規範

讓 Worker 掃描你的樣式設定，整理出色彩、字體、間距和元件樣式，寫成一份 Agent 讀得懂的視覺規範，每一項都標明信心度。之後做畫面的工單都照這份規範走，也能檢查程式碼裡有沒有寫死的色碼，或不在規範內的字級。

這個網站就是這樣做的：動工之前，Worker 先從 BAT 自己的 UI 程式碼抽出品牌紫、Worker 的 ⚠️、?、✓ 狀態符號和分頁標題格式，每個值都附上出處。網站上的每張示意圖，用的都是 App 裡同一套顏色與符號。 {.ct-note}

## 常見問題 {#faq}

### Control Tower 去哪取得？

Control Tower 目前未公開提供。BAT 的派工、回報、提問與查詢介面是公開的，你可以用它們接上自己的流程，見[BAT 提供的整合點](#integration)。

### 沒有 Control Tower，能用 BAT 嗎？

可以。多工作區、Claude Code 面板與狀態列、遠端 WSL / SSH / Docker、檔案瀏覽器與 Git 檢視，這些功能都和 Control Tower 無關，全部功能見[功能](./features)。

### Codex 可以當 Worker 嗎？

可以，也可以當塔台。啟動確認與等人回答偵測需要 Codex CLI 0.163.0 以上；舊版的 Codex 分頁照樣能派工、回報，只是 BAT 無法判斷它有沒有啟動、是不是在等人。

### 塔台被慣壞了怎麼辦？

健康的塔台會守住自己的分工：你要求超出範圍、想跳過驗收時，它會提醒你，甚至拒絕。但如果你一再要它「這行很小，直接幫我改」，它也會被慣壞：不再派工單、什麼都自己動手、不再提醒你驗收條件，甚至把「小改直接在塔台做」記成好做法。

Control Tower 有一份自我檢查清單。照著逐項對過，把被慣壞期間學到的錯誤經驗標記作廢，再重開塔台，讓它從檔案裡的進度接手。真正的防線是使用紀律，不是 AI 的自制力。BAT 的權限不會替你擋這件事：它只管分頁能用哪些 BAT 功能。

### 一個塔台能管幾個子專案？

看子專案之間的關係。常常要一起改的，用一個塔台統一調度：每張工單標明目標子專案，動到共用模組時提醒兩邊都要測。很少互相影響的，各開一個塔台更清爽。BAT 一個工作區可以放好幾個分頁，派工會落在塔台所在的工作區。

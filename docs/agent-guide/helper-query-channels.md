# helper 唯讀查詢 channel（PLAN-047 M1 / T0582）

> 從 CLAUDE.md「helper 唯讀查詢 channel（PLAN-047 M1 / T0582）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **用途**：MCP shim（T0584）/ CT 經 RemoteServer 以**分頁自己的範圍權杖**查詢終端。五個 channel 在 `HELPER_CHANNEL_ROLES`（tower / worker 皆可呼叫，`authorizeHelperInvoke` 直接放行），範圍由 handler 判定；唯一實作 `electron/terminal-query-handlers.ts`（`registerTerminalQueryHandlers`），本機（`main.ts` `registerProxiedHandlers`）與 headless（`createHeadlessTerminalQueryModule`，`electron/remote/headless-entry.ts`）共用。只供 helper 呼叫：列在 `proxied-channels-binding.test.ts` 的 REGISTRY_ONLY 與 `headless-parity.test.ts` 的 HELPER_ONLY，renderer 不能呼叫。`HELPER_CHANNEL_ROLES` 因此是 12 個 channel（`helper-capability.test.ts` 的白名單測試）。
- **身分**：RemoteServer 的 helper 路徑把權杖綁定（`{ terminalId, role, towerId? }`）以 `invokeHandler` 第五參數交給 handler（`HandlerContext.helper`，`electron/remote/handler-registry.ts`）；handler 一律以它為呼叫者，**不接受參數宣告身分**（`whoami` 對 helper 忽略參數）。`terminalId` 省略 = 自己。server token 連線（`ctx.helper` 不存在）不受範圍限制，但必須帶 `terminalId`（否則 `INVALID_ARGS`）。
- **契約**（回傳一律 `{ ok:true, … }` / `{ ok:false, code, message? }`；`code`：`INVALID_ARGS` / `NOT_FOUND` / `NOT_OWNER`，`wait` 另有 `TOO_MANY_WAITS`）：

  | channel | 參數 | 回傳 |
  |---|---|---|
  | `terminal:whoami` | 無 | `terminalId`、`workspaceId?`、`role`（`tower` / `worker` / `shell`）、`towerTerminalId?`、`workorder?`、`yolo`（`isYoloTerminal`）、`towerMode?`、`agent?`（agentPreset；helper 派工（`create-agent-command`）的 Worker 也有，BUG-155 / T0639 前沒有；raw command 模式沒有）、`cwd?`、`claudeSessionName`、`claudeSessionId`（T0642，`string \| null`，見下）；呼叫者 PTY 已結束 → `NOT_FOUND` |
  | `terminal:list` | `{ scope?: 'mine' \| 'workspace' \| 'towers' }`（預設 `mine`；`towers`：T0643） | `mine` / `workspace`：`{ scope, terminals: [{ id, role, workorder?, towerTerminalId?, title?, state, blockedReason?, blockedDetection, agentStarted, pendingQuestions, claudeSessionName, claudeSessionId, alive }] }`，含最近結束者（`alive:false`）；`title` 只有本機（window registry 已存標題）。`towers`：`{ scope: 'towers', terminals: [{ id, workspaceId, workspaceName, title?, claudeSessionName, state, alive: true, self }] }`，只有執行中的已宣告塔台（見下「範圍」）；其他值 → `INVALID_ARGS`（`message: 'scope'`），T0643 前的 BAT 對 `towers` 也是這個回應 |
  | `terminal:get-state` | `{ terminalId? }` | `state`（`working` / `idle` / `exited`）、`lastOutputAt`（null = 本行程未見輸出）、`idleMs`、`exitCode?`、`exitedAt?`、`source:'output'`；`blocked` 見「blocked 狀態偵測（PLAN-047 M1b / T0590）」節；`agentStarted` / `agentStartedAt?`（T0600）見「Worker 啟動確認（T0600，D154）」節；`pendingQuestions`（T0607，該分頁問塔台的待答數，含非 blocking；`blocked` / `tower` / `source: 'question'`）見「Worker 問塔台（PLAN-048 / T0607）」節；`claudeSessionName` / `claudeSessionId`（T0642：注入的 `--name` / 最後一次 `SessionStart` 的 sessionId，`null` 不代表沒有 session，結束紀錄保留）見 [claude-session-name.md](claude-session-name.md)「查詢欄位 R3」 |
  | `terminal:read-output` | `{ terminalId?, cursor?: string, maxLines?: number }` | `lines`、`nextCursor`、`truncated`、`skippedLines`、`partialLine`、`masked`、`state` |
  | `terminal:wait` | `{ terminalId?, until: 'state-change' \| 'exit' \| 'idle' \| 'agent-started', fromState?, timeoutMs? }` | `changed`（條件成立 = true；逾時 = false，不是錯誤）、`state` 等同 get-state（T0642 的兩欄除外）、`waitedMs`；`agent-started`（T0600）= `agentStarted` 不是 `false` 或已結束 |

- **範圍**（唯一實作 `authorizeHelperQueryTarget`，`electron/remote/helper-capability.ts`；`metadata` = whoami / list / get-state，`output` = read-output / wait）：任何權杖 → 自己；tower 權杖（宣告與否）→ + `isWorkerOf(目標, 自己)` 成立的 Worker（已結束的 Worker 以結束時記錄的 `BAT_TOWER_TERMINAL_ID` 判斷）；worker 權杖 → + 綁定的塔台，**只限 metadata**（讀塔台輸出 / wait → `NOT_OWNER`）。`list scope=workspace` 只給已 `--set-role tower` 的塔台（`helperQueryRole` = `tower`；未宣告 = `shell` → `NOT_OWNER`），多列同工作區（`PtyInstance.workspaceId`，本機缺時取已存分頁）的其他分頁，**只有 metadata**，不開放這些分頁的 get-state / read-output / wait。`list scope=towers`（PLAN-050 / T0643，契約 C-6，D167 放寬 D149）同樣只給已宣告的塔台（其他 → `NOT_OWNER`，`message: 'scope=towers needs a declared tower (--set-role tower)'`；server token 連線可列，`self` 一律 `false`），列出**同一個 BAT host（同一 RemoteServer / 主行程）所有工作區**中執行中、已 `--set-role tower` 的分頁（`isTowersScopeMember`），呼叫者自己也列出（`self: true`）；結束的塔台、Worker、一般分頁不列。每列只有 `id` / `workspaceId`（不明 → `null`）/ `workspaceName`（工作區 `alias || name`，與 T0641 session 名稱同一來源，本機取 window registry；不明或 headless → `null`）/ `title?`（本機已存標題）/ `claudeSessionName` / `state` / `alive` / `self`；🔴 **不回** `claudeSessionId`、`cwd`、輸出、`towerMode`、`workorder`、問題內容，這些分頁的 get-state / read-output / wait 範圍不變（仍 `NOT_OWNER`）。誰能列哪個 scope 的唯一實作是 `authorizeHelperListScope`（同檔）。檢查順序：參數 → 存在（`NOT_FOUND`）→ 範圍（`NOT_OWNER`）。
- **state**：`working` = 最近 `TERMINAL_QUERY_IDLE_MS`（= `CLOSE_WORKER_IDLE_MS` 5 s）內有輸出，否則 `idle`；`exited` 來自 PtyManager 的結束紀錄（`recordExit`：exit / kill 時記 metadata、最後輸出時間、`exitCode`（kill 時未知，之後的 exit 補上）與 replay buffer 最後 `EXITED_PTY_TAIL_MAX_CHARS` = 32 KiB），最多 `EXITED_PTY_RECORD_MAX` = 32 筆、保留 `EXITED_PTY_RECORD_TTL_MS` = 10 分鐘，同 id 再執行（restart / 重建）即以執行中為準；超出 → `NOT_FOUND`。PtyManager 新 accessor：`listTerminalIds` / `getTerminalInfo` / `getExitedPty` / `listExitedPtyIds`。
- **read-output**：來源為 replay buffer（`pty:get-buffer` 同一份，256 KiB；已結束取結束紀錄的 tail）→ `plainTextFromOutput`（T0566）→ 遮罩 → 行（去行尾空白、連續空行併為一、頭尾空行去掉）。`cursor` = 該 PTY 整個輸出串流的字元位移（十進位字串）；不帶 = 整個 buffer；cursor 早於 buffer 起點（已捲掉）或超過結尾（PTY 重啟）→ 從 buffer 起點、`truncated:true`。`nextCursor` 停在最後一個 raw `\n` 之後：仍在輸出中的最後一行（≤ `READ_OUTPUT_PARTIAL_LINE_MAX_CHARS` = 4096 字元）本次回傳並標 `partialLine:true`，下次**整行**再回傳一次（讓被讀取切開的權杖下次整個遮罩）；不完整的 escape 序列也留給下次。`maxLines` 預設 `READ_OUTPUT_DEFAULT_LINES` = 200、上限 1000（超過夾到 1000，非正整數 → `INVALID_ARGS`），超出保留最後幾行、`skippedLines` 回報丟掉幾行。
- **遮罩**（唯一實作 `redactTerminalSecrets`，`src/lib/terminal-output-redaction.ts`，read-output 必經；只遮罩不拒絕，`[REDACTED:<kind>]`）：`pem`（`-----BEGIN … PRIVATE KEY-----` 到 END；沒有 END → 到文字結尾；只有 END → 從文字開頭）、`authorization`（`Authorization:` 之後到行尾）、`bearer`、`batcap`、`server-token`（host 傳入的 server token 字面比對 + 43 字元且混大小寫與數字的 base64url）、`sk`（`sk-…`）、`github`（`gh[pousr]_` / `github_pat_`）、`aws`（`AKIA` / `ASIA`）、`secret-env`（名稱以 `TOKEN` / `SECRET` / `PASSWORD` / `API_KEY` / `APIKEY` / `ACCESS_KEY` 結尾的 `NAME=` / `NAME:` 之值）。帶前綴的權杖碰到文字結尾時不論長度都遮。`masked` = 取代次數。
- **wait**：server 端輪詢（`TERMINAL_WAIT_POLL_MS` = 250 ms），`timeoutMs` 預設 / 上限 `TERMINAL_WAIT_MAX_MS` = 45 s（超過夾到 45 s）；`until=idle` 在 `idle` 或 `exited` 成立；`state-change` 以 `fromState`（省略 = 呼叫當下的 state）為基準；條件已成立即回。每個呼叫者同時最多 `TERMINAL_WAIT_MAX_PER_CALLER` = 8 個（→ `TOO_MANY_WAITS`）。RemoteServer 每個 frame 各自 `await` handler，**等待中的 wait 不擋同一連線的其他 invoke**；server 端沒有 invoke 逾時。quit / server stop 時 `dispose()` 讓所有等待中的 wait 回 `changed:false`。
- **稽核**：每次呼叫記 `[helper-query] channel=… caller=<id> target=<id> → ok …|<code>`（caller：helper = terminal id，server token = `client:<connectionId>`；`list` 的 target 為 `scope=…`，`towers` 為 `scope=towers` + `ok count=<n>`，不記名稱；`wait` 在結束時記一行），並以 `mirrorToBatScripts` 寫 `helper-query` 事件（`channel` / `caller` / `callerRole` / `target` / `result`）；**不記輸出內容、不記權杖**。
- **T0584 shim 須知**：helper 端 invoke 逾時要大於 `timeoutMs`（建議 ≥ 50 s）；RemoteServer 每 30 s 對 helper 連線送 WebSocket ping，未回 pong 即斷線（T0451），shim 的 WebSocket 實作必須回 pong（`ws` 套件自動處理；`bat-*.mjs` 的 `MinimalWS` 是短連線，未必適用）；每個權杖同時連線數有上限（`HELPER_MAX_CONNECTIONS_PER_CAPABILITY`）。
- **已知限制**：T0108 replay 註冊的 PTY（BAT 重開、Terminal Server 存活）沒有 `customEnv` / role / workorder：worker 身分仍以還原的權杖判斷（`isWorkerOf`），但 `whoami` / `list` 的 `towerTerminalId` / `workorder` 缺（本機 `list` 的 `towerTerminalId` 取已存分頁），宣告 tower 要再 `--set-role`；這類 Worker **結束後**沒有可比對的塔台紀錄 → 塔台查詢回 `NOT_OWNER`。`lastOutputAt` 只計本行程看到的輸出（replay 不算），重開後未再輸出的分頁 `idle`、`lastOutputAt:null`。headless 沒有標題、也沒有 client 端工作區資料（`workspaceId` 只有建立時帶的）。遮罩是樣式比對，非窮舉。

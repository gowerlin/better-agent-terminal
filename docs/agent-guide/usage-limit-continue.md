# 用量限制自動繼續（PLAN-044 / T0566，D148）

> 從 CLAUDE.md「用量限制自動繼續（PLAN-044 / T0566，D148）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **規格（D148）**：只對 **yolo 分頁**（`PtyManager.isYoloTerminal`，見上節）自動動作，Settings 開關**預設關**。
  - **Codex**：畫面出現 `You've hit your usage limit[ for <model>]. … Try again at <time>.` → 排程「重置時間 + 延遲」→ 到期時 main 再確認畫面、擁有分頁的視窗 renderer 再確認 xterm 畫面 → 輸入 Settings 文字（預設 `繼續`），間隔 `USAGE_LIMIT_ENTER_DELAY_MS` = 300 ms 後送 Enter。重置距今 > 5 h 15 min（`USAGE_LIMIT_SHORT_WINDOW_MS`，視為週限制）、`try again later`（無時間）、非時間型（`Your workspace is out of credits` / `You hit your spend cap` / `Usage limit reached. You've reached your usage limit` / `You're out of credits.`）→ 只提示。
  - **claude**：🔴 **絕不送文字**（CLI 2.1.234 起內建 `autoContinueAtUsageLimit`，雙送會產生兩個續行 turn）。看得到 `continuing automatically at …` → 提示「CLI 將於 … 自動繼續」；`Automatic continue stopped|cancelled` → 提示不會自動繼續；`weekly` / Opus / Sonnet / Fable 限制或重置 > 5 h 15 min → 提示週限制；只有限制句、沒有 `continuing automatically`（API key、舊 CLI、設定或政策關閉、專案層設定使功能失效）→ 只提示（D2）。BAT 不讀 claude 設定檔，一律以畫面為準。CLI 到點自己續行時印 `Usage limit available again · continuing now`，或 `Usage limit reset · continuing automatically`（armed 計時器到點觸發時的通知；CLI 2.1.306 二進位讀出、2.1.300 已有，T0692）→ 兩者都算已恢復（`claude-cli-resumed`），清掉提示、取消等待中的 Enter。唯一補位：休眠跨過重置後 CLI 停在 `Your usage limit has reset` + `Press enter to continue`（stale）→ 依同一套延遲 / 取消規則**只送 Enter**。claude 的 spend limit / shared budget / usage credits / org / seat → 只提示；`fast limit` 與預警句（`You've used 90% …`、`Approaching weekly limit`、`You're now using usage credits …`）不辨識。
  - **非 yolo 分頁**：只提示（徽章 `not-yolo`），不動作。開關關閉時**完全不偵測、不提示、不送**（`onOutput` 立即返回，行為與 T0566 前相同）。
- **句型來源**：T0564 從 CLI 二進位讀出（claude `2.1.300`、codex-cli `0.160.0` / `0.162.1`），**無實測樣本**（不為觸發限制耗額度）；CLI 改字串時需同步改 `src/lib/usage-limit.ts` 與測試。首次真實撞限制時留意 `[usage-limit]` 日誌。
- **辨識規則**（唯一實作 `src/lib/usage-limit.ts`，main / headless / renderer 共用、不 import electron / DOM）：只認**行首完整句型**（允許 TUI 前綴符號如 `■ ` / `⎿ ` / `> ` / 空白，最多 8 個；前面有字母、數字、引號、反引號即不認），取畫面最後 `USAGE_LIMIT_SCREEN_LINES` = 40 個非空行中**最下面**一行被認出的句子；codex 訊息會被 TUI 折行，往下最多併 8 行找 `try again at`。時間：claude `3pm` / `3:30pm` / `Oct 20, 3pm` / `Oct 20, 2027, 3pm` + ` (<IANA>)`（時區不認得 → 本地）；codex `3:05 PM` / `Oct 17th, 2026 3:05 PM`（本地時區）。只有時間 → 下一個該時刻（已過 10 分鐘以上 → 明天）；有日期無年份 → 今年、已過 → 明年；已過 > 10 分鐘（`USAGE_LIMIT_PAST_GRACE_MS`）或 > 7 天 → 視為無時間。
- **偵測位置**（`electron/usage-limit-continue.ts` `UsageLimitContinueScheduler`，本機 main 與 headless 共用；結構比照 `WorkerCloseScheduler`）：`PtyManagerDeps.onPtyOutput`（`enqueuePtyOutput`，direct 與 Terminal Server 的即時輸出；**T0108 replay 不經過**，實測 `handleReplayBuffer` 直接廣播）→ 每分頁維持去 ANSI 的文字尾巴（`plainTextFromOutput`：游標移到別行的 CSI 與單獨 CR 視為換行、`CSI C` 視為空白，跨 chunk 的不完整序列暫存；最多 200 行）→ 分頁安靜 `USAGE_LIMIT_QUIET_MS` = 5 s 後分類。**已處理的行不再算**：使用者輸入或 BAT 自動送出時，當下為止的行都記為已處理（`handledSeq`），所以使用者手動處理過、或 BAT 已送過的那則限制訊息不會再觸發；新的限制訊息才是新的一次。
- **排程與取消**：到期 = `resetsAt + delayMinutes`（stale 為偵測當下 + 延遲）；同一分頁新的限制 → 以最新為準（同一則重繪不重設計時器）。計時器每次最多 `USAGE_LIMIT_MAX_TICK_MS` = 60 s，到點再比對牆上時鐘（電腦休眠跨過到期 → 醒來後下一個 tick 照常再確認後送出，日誌註明晚了幾秒）。取消：等待中**使用者輸入**（本機視窗 / headless client 的 `pty:write`，且非 `isTerminalAutoReply`，與 T0551 同一判斷；`registerPtyHandlers` 的 `onUserInput`）、分頁安靜後畫面已不是同一動作（例 CLI 自己續行 `Usage limit available again`、改顯示非時間型）、到期再確認失敗、分頁結束（`onPtyExit`）、Settings 關閉（`settings:save` → `refreshConfig`）、yolo 被移除。同一分頁連續自動送出上限 `USAGE_LIMIT_MAX_CONSECUTIVE_SENDS` = 2（使用者輸入、或距上次送出 > 30 min 才撞到的新限制重新計算），之後只提示（徽章 `cap`）。排程只在記憶體，BAT / server 重啟即消失。
- **自動寫入不是使用者輸入**：`pty:write` 第三參數 `{ auto: true }`（`handlers/pty.ts`；T0566 前的 server 會忽略多出的參數，只影響「是否算輸入」）不呼叫 `noteUserInput` / `onUserInput`，所以不會取消同一分頁的 `--close-worker` 延遲，也不會取消自己的等待。renderer 的 Enter 走 `bat-notify --submit` 同一條 `dispatchSyntheticEnterKeydown`（`TerminalPanel.tsx` `dispatchEnter`），該次 xterm `onData` 以 `{ auto: true }` 寫入；之後把焦點還給原本的元素（背景分頁送出時使用者打字不會跑去該分頁）。文字為一般寫入（不包 bracketed paste，與 `bat-notify` 預填相同；codex composer 實機行為未驗證）。
- **送出路徑**：main 到期 → `terminal:usage-limit-continue { id, action: 'text' | 'enter', text?, agent, traceId }`；Electron **只送本機視窗**（不經 broadcastHub：連到這台 BAT 的遠端 client 若也顯示同一分頁不會重複送）。renderer（`App.tsx`，以 `ownsTerminalForCloseRequest` 找持有分頁的視窗；`src/stores/usage-limit-store.ts` `runUsageLimitContinue`）：有掛載的 TerminalPanel → 讀 xterm 畫面最後 40 行再確認（`usageLimitRecheckFailure`），通過才輸入；分頁未掛載 → 退回只用 main 的再確認，直接寫文字與 `\r`（`path=pty-write (tab not mounted)`）。
- **提示**：`terminal:usage-limit-status { id, status | null }`（狀態改變才送）→ 縮圖標題後 `.usage-limit-badge`（排程中顯示 `⏳ <到期時刻>`，提示顯示「限制」；`data-usage-limit` = `scheduled-text` / `scheduled-enter` / hint 名；tooltip `usageLimit.*` 三語），只在記憶體、不存 window registry，分頁結束即清除。
- **Settings**（Settings → Advanced「用量限制自動繼續」，三語）：`usageLimitAutoContinue`（預設 `false`）、`usageLimitContinueText`（預設 `繼續`，控制字元轉空白、空白 → 預設、最多 200 字）、`usageLimitContinueDelayMinutes`（預設 2，夾 0–60）；main 讀取唯一入口 `normalizeUsageLimitConfig`。本機在 `settings:save` 時立即生效。
- **遠端 headless**：同一 scheduler 在 server 的 PtyManager（`createHeadlessPtyModule`）；設定讀 `<dataDir>/settings.json`（遠端視窗的 Settings 經 proxied `settings:save` 存在那裡，每 5 s 重讀）。事件在 `PROXIED_EVENTS`，經 `RemoteConnectionRegistry` 送到該 profile 的視窗，由 client renderer 再確認與送出（`pty:write` `{ auto: true }` 回到 server）。使用者輸入只算 client 連線的 `pty:write`。到期時**沒有 client 連著 → 不送**，日誌 `→ not sent (no client connected)`（不補送）。
- **日誌** `[usage-limit]`：main / server — `detected … → scheduled …` / `→ hint …` / `→ cancelled (…)` / `→ send requested: …` / `→ not sent (re-check failed: … | no client connected | terminal no longer exists | turned off in Settings | no longer a yolo tab)`；renderer — `continue received …` / `→ sent … path=dom-keydown|pty-write …` / `→ not sent (re-check failed: …)`，Enter 另有 `[terminal-submit] … source=usage-limit`。
- **已知限制**：T0108 replay 的 PTY（BAT 重開、Terminal Server 存活）沒有 yolo 記錄 → 只提示（見上節）；只辨識 TUI 實際畫在行首的完整句子，agent 回覆在行首引用整句且之後安靜，仍可能誤判（codex yolo 分頁會多送一次文字）；兩台 BAT 互為 remote（一台以另一台為 server）時，server 端 BAT 的本機視窗不持有該分頁 → 不送。

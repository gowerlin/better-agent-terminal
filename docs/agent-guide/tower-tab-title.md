# 塔台分頁標題（T0562，D147）

> 從 CLAUDE.md「塔台分頁標題（T0562，D147）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **契約**（T0562「介面契約」，CT-T013 依此撰寫，不得單方更改）：`"${BAT_HELPER_NODE:-node}" "$BAT_HELPER_DIR/bat-terminal.mjs" --set-role tower [--mode yolo|ask|off|on] [--terminal-id <id>] [--agent <id>]`（`--mode` 為 T0565 / D148 擴充）。`--set-role` 目前只收 `tower`（去前後空白、不分大小寫）；`--terminal-id` 預設 env `BAT_TERMINAL_ID`，兩者皆無 → 用法錯誤；`--agent` 在此模式只是顯示名提示（經 `normalizeAgentAlias`，registry 不認得 → 主行程丟棄、照常成功）。**`--mode`（T0565 / D148）**：選填，去前後空白、不分大小寫，只收 `yolo` / `ask` / `off` / `on`；其他值（含空白、缺值）→ exit 1 `set-role: USAGE`。`--set-role` 模式下不算互斥參數，可寫在 `--set-role` 前後。不帶時不改已記錄的模式（**不清除**，CT 每次都帶）。成功時 stdout 在 `✓ Tower role set: <id>` 之後多印 `  mode: <m>`，值為 BAT 實際記錄的模式（未曾設定則不印）。`bat-scripts.log` 的 `set-role` 事件多記 `mode` / `recordedMode`。建立分頁模式的 `--mode` 文法不變（嚴格小寫）。與建立分頁的參數（`--cwd` / `--workspace` / `--prompt` / `--skill` / `--workorder` / `--interactive` / `--no-interactive` / 位置參數）、`--notify-id`、`--close-worker` / `--delay-ms` 互斥；`--terminal-id` 沒有 `--set-role` 也是用法錯誤。exit code：`0` 已處理（標題已套用，或因使用者命名而保留）/ `3` NOT_FOUND / `1` 用法錯誤、連線失敗、權杖不允許（`FORBIDDEN`）、BAT 太舊（主行程 `No handler for channel` → `UNSUPPORTED`；舊 helper 對 `--set-role` 印 `Unknown option` exit 1，不建立分頁）。stderr 另印 `set-role: <CODE>`（`USAGE` / `NOT_IN_BAT` / `CONNECT_FAILED` / `AUTH_FAILED` / `TIMEOUT` / `UNSUPPORTED` / `FORBIDDEN` / `NOT_FOUND` / `INVALID_ARGS` / `ERROR`），成功 stdout `✓ Tower role set: <id>`。CT 對任何非 0 一律視為不支援、不重試。`bat-scripts.log` 事件 `set-role`（helper 與主行程 `mirrorToBatScripts` 各一筆）。`--close-worker` 的輸出 / exit code 不變（`<mode>: <CODE>` 診斷行改由同一個 `modeTag` 印出）。
- **主行程**（`terminal:set-role`，`electron/terminal-role.ts` `setTerminalRole`，由 `registerTerminalHandlers` 註冊，本機與 headless 共用；只由 helper 經 RemoteServer 呼叫，列在 `proxied-channels-binding.test.ts` 的 REGISTRY_ONLY 與 `headless-parity.test.ts` 的 HELPER_ONLY）：`{ terminalId, role, agent?, mode? }` → 參數不合（含 `mode` 不合法）`INVALID_ARGS`；`PtyManager.isAlive` 為否 `NOT_FOUND`；否則呼叫 `PtyManager.setTerminalRole(id, 'tower', mode?)`，把 `role` / `towerMode` 記在 `PtyInstance`（`electron/ct-mode.ts` `normalizeCtMode`），送 `terminal:role-changed { id, role, ptyAgent?, ptyAgentName?, agent?, agentName?, mode? }`（`ptyAgent` = PTY 建立時的 `agentPreset`，`PtyManager.getAgentPreset`；名稱取 `agentRegistry`）給所有視窗（本機另經 broadcastHub；headless 送連線中的 client），回 `{ ok: true, terminalId, role, mode? }`（`mode` = 記錄後的值；renderer 忽略 `mode`，標題規則不變）。主行程**不**判斷標題，套用與否由 renderer 決定（helper 只知道請求已送出）。
- **yolo 判定（T0565，T0566 調整）**：`PtyManager.isYoloTerminal(id)`（唯一實作，本機與 headless 同一 class；PLAN-044 用）：tower 且有 `towerMode` → 以 `towerMode === 'yolo'` 為準（**塔台宣告優先**，即使 env 帶 `CT_MODE=yolo`）；否則看 `customEnv.CT_MODE === 'yolo'`（Worker 派工 `--mode yolo`）。另有 `getTerminalRole(id)` / `getTowerMode(id)`（只對 tower 回值）。記錄由 `restart` 沿用（create 成功後重新套用）；Terminal Server 冪等重建是同一個 instance、recovery 以 `{ ...inst }` 複製，兩者都保留；PTY kill / exit 即移除。**不持久化**（不寫 window registry）。**已知限制**：BAT 重開但 Terminal Server 存活時（T0108 replay 註冊的 PTY）沒有 role / mode / `customEnv` 記錄，用量限制自動繼續不會套用，直到 CT 在該分頁再次 `--set-role`（Worker 分頁則不會恢復）。
- **renderer**：`App.tsx` 收 `terminal:role-changed`，以 `ownsTerminalForCloseRequest`（與 `terminal:close-requested` 同一判斷：detached 視窗只管自己工作區、主視窗不管 detach 中的工作區）找到持有分頁的視窗，呼叫 `workspaceStore.applyTerminalRole`；日誌 `[set-role] id=… → applied|unchanged|kept|not-found`。標題由 `src/lib/tower-terminal-title.ts`（唯一實作）推得：`<Agent 顯示名> · Tower`，顯示名依序取分頁 `agentPreset` → PTY `ptyAgent` → `--agent` 提示，各自取 renderer preset 名稱（`getAgentPreset`）再取 registry 名稱，都沒有 = `Terminal · Tower`。
- **使用者命名優先**：只在 `isDefaultTerminalTitle` 為真時套用（並 `save()`）；否則保留（`kept`，exit 仍為 0）。BAT 產生的預設標題全部列在 `tower-terminal-title.ts` 開頭：`addTerminal` 的 preset 名稱 / `New Terminal`、已下架 preset 的分頁還原時改成的替代 preset 名稱（T0718：`Claude Agent V2` → `Claude Agent`）、BAT 已不再產生的舊預設標題（T0722 / D194：`Claude Agent V1`、`Claude Agent V2`、`Claude Agent V1 (Worktree)`，`RETIRED_AGENT_PRESET_TITLES` / `isRetiredPresetTitle`，`src/lib/retired-agent-presets.ts`；還原時 `migrateTerminalAgentPreset` 把 `title` / `autoTitle` 改成新名稱，不論 preset；尚未重新存檔的資料或舊版 BAT 給的標題仍可能出現，所以判斷仍認得）、自訂 CLI 的 registry 名稱、遠端工具安裝分頁標題、`externalTerminalTitle`（T0553，含 Worker 格式與 `Terminal`）、T0553 前的 `Remote: …` / `Remote Terminal`、還原時的 `Terminal`，以及既有的 Tower 標題（可重算）。規則認不出的 BAT 標題（helper raw command 的命令檔名，例 `node`；自訂 CLI 名稱；遠端工具安裝分頁）記在 `TerminalInstance.autoTitle`（隨 `workspace:save` 存、還原與 detached adopt 沿用；舊資料沒有此欄位 → 視為使用者命名、保留）。🔴 BAT 程式碼替分頁命名一律用 `workspaceStore.setAutoTitle`；`renameTerminal` 專指使用者改名（`MainPanel` 雙擊），會清掉 `autoTitle`（`workspace-store.towerRole.test.ts` source guard）。使用者改名成與預設相同的字串（例 `Claude CLI`）仍會被視為預設。
- **持久化**：只改 `title`，不另存角色欄位（既有 `TerminalInstance.role` 是 supervisor 功能，未沿用）；隨 `workspace:save` 存進 window registry，重開後仍在；detached 視窗照 `saveDetachedWorkspaceTerminals` 存進父 entry。agent 結束後維持 Tower 標題（不偵測、不還原）。Worker 標題（T0553）不變。
- **遠端 headless**：同一 helper 指令與 handler；權杖 tower 角色可呼叫、`terminalId` 必須是自己（`target-not-bound`），worker 角色 → `Forbidden: role-not-allowed`（helper exit 1 `FORBIDDEN`）；權杖規則只檢查 `terminalId`，`mode` 不影響授權（T0565）。`terminal:role-changed` 在 `PROXIED_EVENTS`，經 `RemoteConnectionRegistry` 送到該 profile 的視窗；沒有 client 連著時事件無人接收（不補送）。

## BAT ↔ CT 契約 v2 版本閘門（PLAN-068 W0 / T0903，D329 / D330）

> 規格：T0902 回報區〈第二版〉§6′、§3.1′、R11（CT 已依此撰寫 6.1.0：BMad-Guide CT D868）。W1–W9（通知保護、回合訊息卡、待辦分頁、hook 註冊）一律以本節的分頁宣告判斷要不要啟用。

- **契約（R11，改 T0562 契約、CT-T013，只增加，不得單方更改）**：`bat-terminal.mjs --set-role tower --bat-contract <n> [--mode …] [--terminal-id …] [--agent …]`。
  - `<n>`：整數 ≥ 1（只收數字，可有前後空白；`02` = 2）。不是整數、`0`、負數、小數、空白、缺值、超過安全整數 → exit 1 `set-role: USAGE`，不連線。沒有 `--set-role` 卻帶 `--bat-contract` → exit 1 `set-role: USAGE`（`--bat-contract is only valid with --set-role`）。可寫在 `--set-role` 前後。
  - stdout：`✓ Tower role set: <id>`、（有模式時）`  mode: <m>`、最後一行 `  bat-contract: 2`；請求值大於 BAT 支援的最大值 → `  bat-contract: 2 (requested <n>: unsupported)`；請求值 1 → `  bat-contract: 2`（BAT 宣告它支援的最大值；分頁記 1、判定 CT 太舊）。
  - 🔴 **不帶 `--bat-contract` 的舊呼叫**：送出的請求、stdout、stderr、exit code 與 T0903 前逐字相同（不印 `bat-contract:` 行；即使主行程的回應帶了契約欄位也不印）。T0902 §3.1′ 表格寫的「不帶參數時 `  bat-contract: none`」與 R11 衝突，塔台裁定以 R11 為準：`none` 只出現在查詢欄位（`towerContract: null`）。
  - 主行程沒有記錄契約（回應沒有 `batContract` / `towerContract`，例如更新前的主行程）→ 不印 `bat-contract:` 行、照常 exit 0，CT 視為 BAT 不支援契約 v2。
  - exit code 不變（`0` / `3` / `1`）。舊 helper 不認得參數 → `Unknown option '--bat-contract'` exit 1、沒有設定角色；CT 6.1.0 此時不帶參數重送一次（契約 C-1）。
  - `bat-scripts.log` 的 `set-role` 事件：帶參數時多記 `batContract`（請求值）、成功時多記 `recordedContract` / `batContract`；不帶參數時事件與 T0903 前相同。
- **主行程**（`electron/terminal-role.ts` `setTerminalRole`，本機與 headless 共用）：請求多 `batContract`（選填）；不合法 → `INVALID_ARGS`（不記錄、不清除、不送事件）。`PtyManager.setTerminalRole(id, 'tower', mode?, towerContract?)` 把值記在 `PtyInstance.towerContract`：🔴 **每次 `--set-role` 都覆寫**，不帶 `batContract` 的呼叫把它清成未宣告（與 `mode` 不同：`mode` 不帶時保留）。回應只在請求帶了 `batContract` 時多 `towerContract`（記錄值）與 `batContract`（`BAT_CONTRACT_VERSION` = 2）；不帶時回應形狀與 T0903 前相同。日誌 `[set-role] … contract=<n>|none`。
- **生命週期**（同 `role` / `towerMode`，T0565）：⏻ 重啟（`restart` 重新套用）、Terminal Server 冪等重建、recovery（`{ ...inst }`）保留；PTY kill / exit 消失；不持久化。BAT 重開但 Terminal Server 存活時（T0108 replay）沒有記錄，直到 CT 再次 `--set-role`。
- **唯一實作**：判定 `src/lib/tower-contract.ts`（`BAT_CONTRACT_VERSION`、`parseBatContract`、`towerContractStatus`、`towerContractMismatch`；main / headless / renderer 共用、不 import electron / DOM；helper `.mjs` 的數字檢查與輸出行是同規則的複本 `batContractLine`）；host getter `PtyManager.getTowerContract(id)`（只對 tower 回值，W1 / W2 / W3 由此判斷）。
- **判定（§6′「分頁宣告」欄）**：`towerContractStatus(role, towerContract)` → `2` = `match`；未宣告 / `1` = `ct-outdated`（CT 太舊，P-1）；`> 2` = `bat-outdated`（BAT 太舊，P-2）；不是已宣告的塔台 = `not-tower`（沒有徽章、沒有提示）。狀態檔 `_tower-state.md` `bat_contract` 的判定（P-3）屬 W4，不在本節。🔴 T0788 的對話框保護不綁版本，所有分頁照舊。
- **查詢欄位**：`terminal:whoami` / `terminal:get-state` / `terminal:list`（`mine` / `workspace` / `towers` 每列）多 `towerContract: number | null`（null = 未宣告、不是塔台、或 PTY 已結束）。`scope: 'towers'` 仍只回 metadata（`towerContract` 屬 metadata）。BAT MCP（`scripts/bat-mcp.mjs`）的 `structuredContent` 原樣帶出，`bat_whoami` 與 `towers` 的摘要在有值時多 `bat-contract=<n>`；仍全唯讀。
- **`terminal:role-changed`**：一律帶 `towerContract: number | null`（另有既有的 `mode`）。
- **renderer**：`src/stores/tower-contract-store.ts`（只在記憶體）：每個視窗都套用事件（`applyTowerContract`），PTY 結束（`pty.onExit`）清除；縮圖 `TerminalThumbnail.tsx` 在 `ct-outdated` / `bat-outdated` 時顯示徽章 `CT↑` / `BAT↑`（`.tower-contract-badge`、`data-tower-contract`），tooltip 為 P-1 / P-2 全文；持有分頁的視窗（`ownsTerminalForCloseRequest`）在第一次不符時以 toast 顯示同一段文字（`<分頁標題>: <P-1 / P-2>`，警告、20 s），🔴 **每個分頁只出一次**（`claimTowerContractHint`，本視窗存活期間；PTY 結束再宣告也不再出）。字串 `towerContract.ctOutdated` / `towerContract.batOutdated`（三語系，`{{supported}}` / `{{requested}}`）。標題規則（`applyTerminalRole`、`setAutoTitle`、使用者命名優先）不變。日誌 `[tower-contract] id=… contract=… status=…`。
- **已知限制**：遠端視窗的 detached / 主視窗都套用 store，徽章只隨 `role-changed` 事件更新；BAT 重開後在 CT 再次宣告前沒有徽章（host 也沒有記錄）。W0 只提供閘門與提示，P-1 / P-2 文字提到的功能由 W1–W4 實作，與 CT 6.1.0 同一版發佈（R10′）。

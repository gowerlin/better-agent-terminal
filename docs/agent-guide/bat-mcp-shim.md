# BAT MCP shim（PLAN-047 M1 / T0584）

> 從 CLAUDE.md「BAT MCP shim（PLAN-047 M1 / T0584）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **用途**：讓 BAT 分頁裡的 claude / codex 以 MCP tool 查詢 BAT（不必解析 helper CLI 文字）。`scripts/bat-mcp.mjs` 是 stdio MCP server（零依賴手寫，不用 MCP SDK），每個 tool 轉接一個唯讀 helper channel，連 `wss://127.0.0.1:$BAT_REMOTE_PORT`、以**分頁自己的範圍權杖**（`BAT_REMOTE_TOKEN`，只從繼承的 env 讀）認證，憑證 pinning 沿用 `_bat-cert.mjs`，回應以 frame id 比對（BUG-114）。身分 = 權杖；`terminalId` 省略 = 自己。範圍、錯誤碼、遮罩全依 T0582 / T0585 的 channel。
- **Tools**（全部 `readOnlyHint: true`；server 名稱 `bat` → client 端 `mcp__bat__<tool>`）：

  | tool | channel | 參數 | invoke 逾時 |
  |---|---|---|---|
  | `bat_whoami` | `terminal:whoami` | 無 | 3 s |
  | `bat_list_terminals` | `terminal:list` | `scope?: 'mine' \| 'workspace'` | 3 s |
  | `bat_get_state` | `terminal:get-state` | `terminalId?` | 3 s |
  | `bat_read_output` | `terminal:read-output` | `terminalId?`、`cursor?`、`maxLines?` | 3 s |
  | `bat_wait` | `terminal:wait` | `terminalId?`、`until`、`fromState?`、`timeoutMs?`（≤ 45 s） | 55 s |
  | `bat_worktree_status` | `worktree:terminal-status`（T0585） | `terminalId?`、`workorder?` | 15 s（同 `bat-terminal.mjs --worktree-status`） |
  | `bat_list_questions` | `question:list`（PLAN-048 / T0608） | `terminalId?`（塔台：自己的某個 Worker；省略 = 範圍內全部）、`status?: 'pending' \| 'all'`（預設 `pending`） | 3 s |
  | `bat_wait_question` | `question:wait`（PLAN-048 / T0608） | `questionId`（必填）、`timeoutMs?`（≤ 45 s）；`idempotentHint: false` | 55 s（同 `bat_wait`） |

  問答的寫入（提問 / 取消 / 答覆）**沒有** MCP tool，一律走 helper（`bat-notify.mjs --ask` / `--cancel-question`、`bat-terminal.mjs --answer`，D155 / D156），BAT MCP 維持全唯讀；server `instructions` 為「Read-only queries about BAT terminals and tower questions: …」。`bat_list_questions` 的 `content` 摘要 `N pending questions: <id> (T####, <前 60 字>)`（`status: all` 時 `N questions: <id> (T####, <status>, <前 60 字>)`），`structuredContent.questions` 是全文；`bat_wait_question` 摘要 `status=<s>[ (<endReason>)] after <ms> ms`，`answered` 時另起行附 `choice: <n>` 與答覆全文，`pending` 逾時附 `(timed out; call again)`。稽核行同其他 tool（只記 tool / ok / code / 耗時），不記問題、答案、問題 id。

  shim 只轉送各 tool 已知的參數鍵（其他鍵丟掉），驗證由 server 做。成功：`structuredContent` = channel 回傳去掉 `ok`，`content` = 一行摘要（`bat_read_output` 另附輸出行，給只讀 `content` 的 client）。channel 回 `{ ok:false, code }` → tool 結果 `isError: true`、`structuredContent: { code, message? }`（不是 JSON-RPC error）。shim 自己的 code：`CONNECT_FAILED`（含非 BAT 環境、憑證讀不到 / 指紋不符、連線中斷）、`AUTH_FAILED`、`UNSUPPORTED`（`No handler for channel` 或 `Forbidden: channel-not-allowed` = 舊 BAT；同一程序內記住該 channel，不再送出，免得累積 helper denial 被節流）、`FORBIDDEN`（其他 `Forbidden: …`）、`TIMEOUT`、`ERROR`、`INVALID_ARGS`（`arguments` 不是物件，不送出）。未知 tool → JSON-RPC `-32602`、未知 method `-32601`、壞 JSON `-32700`。
- **協定（dual-era）**：legacy `initialize`（回請求的版本，不支援則 `2025-11-25`）/ `notifications/initialized` / `ping`；modern `2026-07-28` 的 `server/discover`（`supportedVersions`、`capabilities.tools`、`_meta["io.modelcontextprotocol/serverInfo"]`）+ 每個請求的 `_meta["io.modelcontextprotocol/protocolVersion"]`，modern 結果一律帶 `resultType: 'complete'`，`server/discover` / `tools/list` 帶 `ttlMs` + `cacheScope: 'private'`（claude 2.1.300 的 schema 要求，`public` / `private`）。`_meta` 版本不支援 → `-32022` + `data: { supported, requested }`。Claude Code 2.1.300 走 modern（先 `server/discover`）。
- **連線**：一條 WebSocket，第一次 tool call 才連，並行的 call 共用（frame id 多工），閒置 `IDLE_CLOSE_MS` = 5 s 後關；斷線時進行中的 call 回 `CONNECT_FAILED`，下一次 call 重連。會回 RemoteServer 的 heartbeat ping（T0451，30 s；沒回 pong 即被斷），所以 45 s 的 `bat_wait` 撐得過。理由：每個權杖同時連線上限 `HELPER_MAX_CONNECTIONS_PER_CAPABILITY` = 4（與該分頁的 `bat-terminal` / `bat-notify` 共用），每 call 一條短連線在並行 `bat_wait` 時會撞上限；常駐長連線則一直佔一個名額、BAT 重開後要自己重連。`bat-*.mjs` 的 `MinimalWS` 不回 pong，shim 有自己的 client。
- **注入**（唯一實作 `electron/bat-mcp-launch.ts` `buildBatMcpLaunchArgs`，本機與 headless 共用、不 import electron）：只對 BAT 有組裝權的 `claude-cli` / `claude-cli-worktree` / `codex-cli` 分頁，參數放在 base command 之後、自訂參數之前。
  - claude：`--mcp-config=<dataDir>/bat-mcp/claude.json`（**一定用 `=` 形式**：`--mcp-config <configs...>` 是 variadic，空格形式會把後面的 prompt 當成設定檔，claude 2.1.300 實測）。設定檔 `{"mcpServers":{"bat":{"type":"stdio","command":…,"args":[<shim>]}}}`，**無權杖、無 env 值**；內容不同才重寫（temp + rename）。不加 `--strict-mcp-config`（使用者自己的 MCP 設定照常載入）。
  - codex：`-c mcp_servers.bat.command=<TOML> -c mcp_servers.bat.args=[<TOML>] -c mcp_servers.bat.env_vars=[<名稱>…] -c mcp_servers.bat.tool_timeout_sec=60`（`codexMcpOverrides`），值用 TOML literal string（`'…'`，含 `'` 時改 basic string），整個 `-c` 值再依 shell family `quoteArgForShell`。pwsh / bash / cmd 三種實測 `codex mcp get bat --json` 解析一致（T0584：codex-cli 0.162.1；T0586：0.163.0 含 `env_vars`，`codex.exe`；npm 的 `codex.cmd` shim 未實測）。
  - **codex 的 `env_vars`（T0586 / BUG-148）**：codex 啟動 stdio MCP server 時**只傳預設白名單的 env**（Windows 0.163.0 實測：`PATH` / `PATHEXT` / `SHELL` / `COMSPEC` / `SYSTEMROOT` / `WINDIR` / `SYSTEMDRIVE` / `USERNAME` / `USERDOMAIN` / `USERPROFILE` / `HOMEDRIVE` / `HOMEPATH` / `PROGRAMFILES*` / `PROGRAMDATA` / `LOCALAPPDATA` / `APPDATA` / `TEMP` / `TMP` / `TMPDIR`），分頁的 `BAT_*` 不會傳下去（claude 則傳完整 env），T0586 前 codex 分頁的每個 tool 都回 `CONNECT_FAILED: not running inside a BAT terminal`。`mcp_servers.<name>.env_vars = ["NAME", …]` 只列**名稱**、由 codex 從自己的 env 取值轉送，沒設的名稱直接略過（0.160.0 / 0.163.0 實測；也接受 `{ name, source = "local" | "remote" }`，BAT 只用字串）。轉送清單 `BAT_MCP_CODEX_ENV_VARS`：`BAT_REMOTE_PORT` / `BAT_REMOTE_TOKEN`（端點與權杖）、`BAT_TERMINAL_ID`（稽核日誌）、`BAT_USER_DATA` / `BAT_SERVER_CERT_PATH` / `BAT_HELPER_LOG_DIR` / `BAT_RUNTIME`（憑證與日誌路徑，T0481）、`APPDATA`（Windows userData fallback，已在 codex 預設內，列出無害）、`XDG_CONFIG_HOME`（Linux fallback，codex Unix 預設不含）。= `scripts/bat-mcp.mjs` 與 `_bat-cert.mjs` / `_bat-logger.mjs` 讀的全部 `process.env.*`（`bat-mcp-codex-env.test.ts` source guard）。🔴 不得改用 `mcp_servers.bat.env = { BAT_REMOTE_TOKEN = "…" }`（權杖值會出現在命令列與日誌）；新增 shim 讀的 env 時同步加進清單。
  - node / shim：本機 `node` + `BAT_HELPER_DIR` 同一目錄的 `bat-mcp.mjs`（dev = repo `scripts/`、打包 = `resources/scripts/`）；headless `<installRoot>/bin/node`（存在才用，否則 `node`）+ `<installRoot>/scripts/bat-mcp.mjs`，設定檔在 `<dataDir>/bat-mcp/`。

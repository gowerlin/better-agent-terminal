# 多 remote profile 同時連線（PLAN-039）

> 從 CLAUDE.md「多 remote profile 同時連線（PLAN-039）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

`main.ts` 以 `RemoteConnectionRegistry`（T0462 模組、T0463 接線、T0464 生命週期）取代單一 `remoteClient` 槽位：`Map<profileId, entry>`，每個 profile 一把 mutex（同 profile 的 connect / pin 變更 / release 串行，不同 profile 並行）。

- **路由**：proxied IPC 以 sender 綁定的 profile（detached 視窗用父視窗的）查自己的 entry；無 live 連線 → 拒絕（`no-client` / `reconnecting`），不 fallback 本機。`'other-profile'` 已移除（T0463）。每個 client 的事件只送 `getWindowsForProfile(profileId)`；本機來源事件（本機 PTY 輸出、Claude emit、`system:resume`）仍送所有視窗，renderer 以 id 過濾
- **生命週期**：最後一個視窗關閉後寬限 `IDLE_GRACE_MS = 15 s`，到期在 mutex 內重算仍無視窗才斷；縮到 tray 的 hidden 視窗算 live（`collectProfileWindows()`）；連上但沒建出視窗 → `FIRST_WINDOW_GRACE_MS = 60 s`；quit 全量 `disconnectAll` 等 ≤ 2 s（`DISCONNECT_ALL_TIMEOUT_MS`）。常數皆無注入點，測試不得為縮短等待改產品常數
- **上限 `MAX_CONCURRENT_REMOTE_PROFILES = 8`**（含連線中 / 重連中；`remote:test-connection` / `remote:list-profiles` 的暫時 client 不計）：第 9 個 → main 端原生對話框（`showRemoteProfileFailureDialog`，`reason: 'limit'`，三語）、`openProfileWindows` 回 `error: 'remote-limit'`、`remote:connect` 回 `errorCode: 'remote-limit'`，**不擠掉既有連線**
- **同 target 兩 profile**：允許 + `logger.warn`（見上方雙 Enter 限制）；SSH 動態本機埠 bind 失敗換埠重試一次、固定 `tunnelLocalPort` 重複 warn（T0465）
- **驗證**：單元 / 整合見 `electron/remote/__tests__/remote-connection-*.test.ts`；e2e `e2e/plan039-multi-remote.spec.ts`（T0466）起兩個 isolated 實例互為 server（P → A 自身、Q → B），驗雙視窗 connected、`pty:create` 落在正確 server、第 9 個被拒、關 P 15 s 後才斷且 Q 不受影響、釋放後名額回收；單獨跑 `npx playwright test e2e/plan039-multi-remote.spec.ts`（需先 `npx vite build`，約 25 s）。P 是 loopback 到 A 自身，故 P 的 PTY 是 A 本機 PTY、會經本機廣播送到 A 所有視窗（含 Q 視窗）——spec 只斷言「B 上的 PTY 輸出不進 P 視窗」這個方向
- **實機驗收**（WSL + SSH，AI 無法代驗）步驟見 `docs/remote-dev-overview.md`「Several remote profiles at once (PLAN-039)」
- **失敗對話框三語（T0491）**：main 端 remote profile 失敗對話框（`unreachable` / `trust` / `protocol` / `limit`）全部依設定語言三語化（`electron/remote/remote-profile-error.ts` `getRemoteProfileFailureStrings` / `getRemoteProfileLimitStrings`，與 `src/locales/*.json` `remoteProfileFailure.*` / `remoteProfileLimit.*` 由單元測試保持一致）；原始錯誤文字逐字附在 detail。
- **profile index 序列化（T0509）**：`profiles/index.json` 的讀改寫全部經 `electron/profile-manager.ts` 的 `withIndexLock()` 佇列（模組層，比照 T0491 `WindowRegistry`），`ProfileManager` 每個方法都把 `ensureInitialized()` → 修改 → `writeIndex()` 放在同一個單元（讀取也排隊）。🔴 鎖內程式碼不得呼叫 `ProfileManager` 公開方法（佇列不可重入，會等自己）；新增方法時建立邏輯用 `addProfileEntry()`。`writeIndex` 的 rename 對 `EPERM` / `EBUSY` / `EACCES` 依 `INDEX_RENAME_RETRY_DELAYS_MS`（25–800 ms，重試 6 次、共 7 次嘗試）重試，用盡即拋錯。修正 plan039 e2e M3 在完整回歸組合下的 `EPERM … rename index.json.tmp -> index.json`。驗證：`electron/__tests__/profile-index-serialization.test.ts`。
- **開啟已存在的 profile 視窗（T0750 / BUG-183）**：「配置」的「開啟」（`app:open-new-instance` → `openProfileWindows`）與 `--profile=` second-instance 找到同 profile 的存活視窗時，一律經 `bringWindowToFront`（`src/lib/profile-window-front.ts`）：隱藏（最小化到匣，`win.hide()`，視窗仍在 `windowMap`）→ `show()`；最小化 → `restore()`；再 `focus()`。回傳 `broughtToFront`（`focused` / `restored` / `not-shown`），renderer 以 `profileOpenNotice` 決定通知：`restored`（隱藏或最小化的視窗叫回來了）不顯示；`focused`（視窗本來就在畫面上）照舊顯示 `profiles.alreadyOpen`；`not-shown`（`show()` 後仍不可見）顯示 `profiles.alreadyOpenNotShown`（請改從系統匣選單 → 該視窗 → Show）。主行程記一行 `[profile-window] open <profileId>: existing window <id> <result>`。T0750 前只做 `restore()`（僅最小化時）+ `focus()`，隱藏的視窗不會出現，只跳「已在另一個視窗中開啟」。
- **刪除 profile 時關閉它的視窗（T0750 / BUG-184）**：`profile:delete` 成功後 `closeWindowsOfDeletedProfile`（`electron/main.ts`，選擇邏輯 `planDeletedProfileWindows`）destroy 綁定該 profile 的存活視窗（含隱藏的）、刪掉它們與無存活視窗的 registry entry、重建匣選單；這些視窗若是全部的存活視窗，先開 Default profile（`openProfileWindows('default')`，否則 `minimizeToTray` 關閉時 app 會結束）。呼叫者：「配置」卡片 ✕、WSL 精靈 `write-profile` 刪除前次嘗試 / rollback 的 profile。T0750 前刪除 profile 不碰視窗：視窗留著、綁定已不存在的 profile、照列在匣選單（實例：刪掉後以同名重建 profile，匣選單出現兩個同名 `… - <profile 名稱>:1`）。匣選單的列 = `windowMap` 中未 destroyed 的視窗（`rebuildTrayMenu`），關窗對話框與匣選單的「Remove from profile」本來就 `destroy()`（`closed` → `windowMap.delete` → 重建選單），T0750 未改。
- **匣選單同名視窗標籤（T0752 / D205）**：`rebuildTrayMenu` 的視窗項目標籤 = 視窗標題（空的時候 `Window <id 前 8 碼>`），唯一實作 `trayWindowLabels`（`src/lib/tray-window-labels.ts`）：同一次選單內標籤重複時，第一個不變，之後依 `windowMap` 順序加 ` (2)`、` (3)`…（例：兩個同名 profile 的視窗都叫 `… - <profile 名稱>:1`）；不重複的標籤、視窗標題本身、選單結構與動作都不變。驗證 `src/lib/__tests__/tray-window-labels.test.ts`（含 main.ts 接線 source guard；匣選單 e2e 讀不到）。
- **驗證（T0750）**：`src/lib/__tests__/profile-window-front.test.ts`（含 main.ts 接線 source guard）；e2e `e2e/t0750-profile-window-reopen.spec.ts`（隔離實例、只用本機 profile：`minimizeToTray` 開 → 關 profile B 唯一視窗 → 隱藏 → 卡片「開啟」→ 可見、無通知；開 profile C 視窗 → 卡片 ✕ 刪除 → 視窗消失、存活視窗數 −1、registry 無 C）。
- **WSL profile 的 keep-alive 開關（PLAN-043 / T0830，D271）**：`ProfileEntry.wslKeepAlive`（`electron/profile-manager.ts`，只對 `wsl-linux`）：`false` = BAT 不替這個 profile 的 distro 持有 keep-alive `wsl.exe`；沒有欄位或 `true` = 持有（T0830 前的行為，既有 profile 不變）。寫入經 `profile:update`（`ProfileManager.update` 在 `withIndexLock()` 內，只接受 boolean），之後照舊 `syncWslKeepAlive('profile:update')` 立即生效。要持有的 distro 唯一由 `keepAliveProfileDistros`（`electron/wsl-keepalive.ts`）決定：同一 distro 有多個 profile 時任一個開著就持有；精靈的 `pin()` 與開關無關（精靈執行中照樣持有）。UI：profile 卡片展開後 `WslDetails` 的勾選框＋說明（關閉後 WSL 閒置可能自動關機、下次連線較慢），存檔失敗回復原值並顯示錯誤。`duplicate` 不複製 targetOS 等欄位，也不複製此欄位。驗證：`electron/__tests__/wsl-keepalive-profile-toggle.test.ts`、`src/components/profiles/__tests__/WslDetails.test.tsx`；使用者說明見 `docs/wsl-deployment.md`「After setup」。

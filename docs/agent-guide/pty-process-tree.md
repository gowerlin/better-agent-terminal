# 關閉分頁時的程序樹（T0540 / PLAN-042）

> 從 CLAUDE.md「關閉分頁時的程序樹（T0540 / PLAN-042）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **direct 模式**（`PtyManager.kill`，`electron/pty-manager.ts`）：Windows 的 node-pty 分頁先 `taskkill /F /T /PID <shell>`（同步，3 s timeout），再 `releaseDirectPty`（`releaseExitedPty`：ClosePseudoConsole＋conin＋conout Worker；T0983 / BUG-238 起不呼叫 `pty.kill()`，形狀不符才退回 `pty.kill()`）；`child_process` fallback 與 macOS / Linux 照舊 `kill()` 後（Windows）`taskkill`。
- **Terminal Server 模式**（預設）：✕、`pty:kill`、`pty:restart`（= kill + 同 id create）都送 server `pty:kill`；server `endPty`（`electron/terminal-server/server.ts`）在 Windows **先** `killProcessTree`（`electron/terminal-server/process-tree.ts`：`execFile('taskkill', ['/F','/T','/PID', pid])`，`TASKKILL_TIMEOUT_MS` = 3 s，`windowsHide`，pid 須為正安全整數，否則不執行；失敗 / 逾時只寫 stderr）**再**釋放 pseudo console：T0983（BUG-238）起是 `releaseExitedPty`（同檔：ClosePseudoConsole → destroy conin → dispose conout 轉送），🔴 不再呼叫 node-pty 的 `pty.kill()`（shell 已被 taskkill 結束時，它的主控台清單查詢一定失敗，5 s 後對舊 shell pid 呼叫 `process.kill`，pid 若被重用會結束無關的程序）；只有 PTY 物件不是 node-pty 1.1.0 的形狀時才退回 `pty.kill()`（stderr 一行）。順序不可對調：`taskkill /T` 依父子關係找樹，shell 先死就找不到孫程序。entry 與 registry 仍同步移除，restart 的新 PTY 不受影響（BUG-101 stale exit 邏輯不變）。macOS / Linux 照舊同步 `pty.kill()`。
- **為什麼**（T0540 實測，隔離 server + node 腳本模擬 agent，pwsh / cmd 結果相同）：node-pty 的 Windows `kill()` 只結束 attach 在該 pseudo console 的程序（shell、agent、共用 console 的子程序、`windowsHide` 子程序都會結束），agent 以 `detached`（DETACHED_PROCESS，無 console）啟動的子程序在修正前於 kill / restart / quit 全部殘留；修正後 0 殘留。T0983 前之後 node-pty 的 console list agent 因 shell 已不在而印 `AttachConsole failed`（stderr，server 為 ignore），約 5 s 後走 node-pty 自己的 fallback 對舊 pid `process.kill` 再關閉 pseudo console（實測 7 s 內 conhost 已釋放；T0983 量到 BAT 關閉 20 個分頁 1 s 後仍有 14 個 conhost）；T0983 起 taskkill 後直接收掉，1 s 內 0 個，不再 fork console list agent。
- **自然結束的分頁**（T0983，PLAN-066 F4 選項 D，D522）：shell 自己結束、分頁還開著時保留 conhost；✕（`pty:kill`）、⏻ 重啟 / 同 id `pty:create`、server shutdown 時以 `releaseExitedPty` 收掉，仍附著該主控台的背景程序一起結束（與 live 分頁 ✕ 結束整個程序樹一致）。主行程在 Windows 對自然結束的 id 照樣送 `pty:kill`（`PtyManager.serverExitedIds`）；direct 模式 `exitedDirectPtys`。細節與新舊版本組合見 [terminal-server-recovery.md](terminal-server-recovery.md)「自然結束的分頁：關閉或重啟時收掉」。
- **server shutdown**（quit 勾選停止 Terminal Server、recovery「重新開始」、idle timeout）：`shutdown()` 對每個 PTY 走 `endPty`，**全部 taskkill 結束後**才清 pid / port / registry 檔並 `exit(0)`（main 的 quit Step C 以 pid 檔消失為完成訊號）；重入與 shutdown 期間的訊息一律忽略。
- **quit Step A（Windows）**：`stopTerminalServerGracefully`（`electron/main.ts`）對 fork 出的 server 改送 IPC `server:shutdown`。🔴 不要改回 `child.kill('SIGTERM')`：Windows 上那是 TerminateProcess，server 的 SIGTERM handler / shutdown 都不會執行（實測 detached 孫程序殘留）。macOS / Linux 仍送 SIGTERM。之後的 TCP shutdown / taskkill 後援不變。
- **quit 不停止 Terminal Server**（`stopTerminalServer=false`）：server 與全部 PTY 程序樹保留（實測不變）。
- **⏻ 重啟已結束的分頁**（T0539 / BUG-137）：程序結束後（`pty:kill` 或 shell 自行 `exit`）`PtyManager` 已無 instance，`pty:restart` 回 `false`。`WorkspaceView.handleRestart` 的一般終端分支經 `restartOrCreatePty`（`src/lib/pty-replay.ts`）：`restart` 回 `true` 照舊；否則以**同一 id** `pty:create`（工作區 env、`workspaceId`、`agentPreset`，env 由 `buildPtyEnv` 組裝），只在真的起了新 shell 時重送 terminal-driven agent 啟動命令；仍失敗則分頁內印 `terminal.restartFailedNotice`。補建的 PTY 沒有原 Worker 的 `BAT_TOWER_TERMINAL_ID` / `CT_MODE` / `workorder`（`--close-worker` 仍可經 T0537 已存歸屬找到）。
- **macOS / Linux**（只看程式碼，未實測）：node-pty `UnixTerminal.kill()` 只對 shell pid 送 `SIGHUP`，不對程序群組；互動 shell 收到 SIGHUP 會轉送給自己的 job，shell（session leader）結束時 kernel 對前景程序群組送 SIGHUP，一般 agent CLI 會一起結束。`setsid` / `nohup` / detached 的 daemon 不在範圍內，兩種模式都會殘留（direct 模式在 Unix 也只有 `kill()`）。

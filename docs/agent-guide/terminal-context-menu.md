# 終端分頁右鍵選單與滑鼠追蹤（T0568 / BUG-142）

> 從 CLAUDE.md「終端分頁右鍵選單與滑鼠追蹤（T0568 / BUG-142）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- xterm 分頁（`TerminalPanel.tsx` 的 `contextmenu`）只在分頁內程式**沒有**開滑鼠追蹤時開 BAT 的 複製 / 貼上 選單；`terminal.modes.mouseTrackingMode` 為 `x10` / `vt200` / `drag` / `any`（DECSET 9 / 1000 / 1002 / 1003）時不開（日誌 `[terminal-context-menu] … not shown`），原生選單照樣 `preventDefault`。判斷唯一實作 `shouldShowTerminalContextMenu`（`src/lib/terminal-context-menu.ts`）。每種追蹤模式都會回報右鍵，所以只看模式。
- **Shift + 右鍵**一律開選單：Windows / Linux 的 xterm 在按住 Shift 時不送滑鼠回報、Shift + 拖曳是追蹤模式下的選取方式，選單的「複製」因此可用。macOS 的 xterm 改用 Option 繞過（`macOptionClickForcesSelection`），Shift + 右鍵時程式也會收到回報。
- 原因：claude CLI 2.1.300 的 TUI（alt screen）開 `?1000h ?1002h ?1003h ?1006h`（`CLAUDE_CODE_DISABLE_MOUSE_CLICKS` → 只開 1000 + 1006，`CLAUDE_CODE_DISABLE_MOUSE` → 不開），在 windows / wsl / linux 收到右鍵就複製自己的選取或貼上剪貼簿；BAT 選單疊在上面等於同一次點擊做兩件事。
- 🔴 不改 xterm 寫進 PTY 的滑鼠回報；只決定 BAT 選單要不要出現。Claude / Codex 面板、縮圖、檔案樹等其他右鍵選單不受影響。例外見下方「滑鼠追蹤殘留的重設（T0672 / BUG-166）」：只在本機 xterm 關閉追蹤，回報內容與送出時機都不改。
- **選單開著時的 Esc（T0569 / BUG-143）**：開選單後焦點仍在 xterm textarea，xterm 5.5.0 的 `_keyDown` 會把 Esc 寫進 PTY 再 `stopPropagation`，`document` 的 BUG-011a listener 收不到。改由 `attachCustomKeyEventHandler` 先判斷（`shouldCloseTerminalContextMenuOnKey`，同檔）：選單開著 + Esc → 關選單、回 `false`（不寫 PTY），日誌 `[terminal-context-menu] … closed by Escape`；IME 組字中不算；選單沒開時 Esc 照常送進 PTY（claude CLI 的 Esc 中斷不受影響）。焦點不在終端時仍由 `document` listener 關閉。
- **追蹤中的 Shift + 拖曳選取（T0571 / BUG-144）**：xterm 5.5.0 把滑鼠回報當使用者輸入、送出即清掉選取；開 1003（claude CLI 預設）時每次移動都是回報（按住 Shift 也是），選取撐不到 Shift + 右鍵。`MouseReportSelectionKeeper`（同檔）在「清除後同一個 task 內的 `onData` 是 SGR 滑鼠回報」時以 `terminal.select` 放回同一範圍（回報照常寫進 PTY）；打字 / 貼上、BAT 不知原因的清除（buffer 切換、trim、開追蹤）、Shift + 右鍵以外的滑鼠按下、滾輪之後不放回；範圍讀出的文字不同（Alt 欄選取、resize）也不放回。選單的「複製」寫入**右鍵當下**的選取文字（`ContextMenu.selectionText`），關閉後不留。不按 Shift 的拖曳是 claude 自己的選取（xterm 沒有選取），claude 放開即複製（`copyOnSelect` 預設開）、不按 Shift 的右鍵也複製，BAT 選單不顯示「複製」。**畫面上的藍底反白是 claude 自己的選取**（xterm 選取色是 `#5c5142` 棕色）；Shift + 拖曳不會把按鍵送給 claude，所以 claude 先前的藍底反白會留著，不代表 xterm 有選取。
- **T0571 在真實 claude 實機無效的兩個原因（T0573 / BUG-144）**：
  - **聚焦時重送追蹤模式**：claude CLI 2.1.300 開 DECSET 1004，分頁失焦約 5 秒以上再收到 `ESC [ I` 時重送 `?1000h ?1002h ?1003h ?1006h`（實測失焦 6 s → 重送、2 s → 不重送）。xterm 對每個追蹤 DECSET 都設定一次滑鼠協定（模式沒變也一樣）→ `SelectionService.disable()` → 清掉選取，**不經 `onData`**，T0571 的 keeper 不放回；若讓分頁重新取得焦點的那一下就是 Shift + 拖曳，DECSET 在拖曳中途到達（實測約 20–30 ms），xterm 的拖曳也一併結束。修正：TerminalPanel 以 `terminal.parser.registerCsiHandler({ prefix: '?', final: 'h' })`（在 xterm 處理前執行、回 `false` 不攔）偵測「追蹤已開時又收到 9 / 1000 / 1002 / 1003」（`isMouseTrackingDecset`）→ `handleMouseTrackingSet()`，該次寫入解析完（microtask）若選取被清掉就放回；Shift + 拖曳仍按著時改由 `SelectionDrag.resume()` 在原按下位置以相同修飾鍵補一個 `mousedown`（xterm 視為強制選取，不送回報），選取繼續跟著游標。從關閉打開追蹤不放回（T0571 原規則）；buffer 切換一律 `forget`。
  - **重選同一範圍沒有事件**：xterm 的 `clearSelection()` / `select()` 直接 fire `onSelectionChange`、不更新 `_oldSelectionStart/_oldSelectionEnd`，之後拖出**完全相同**的範圍時 `_fireEventIfSelectionChanged` 判定沒變、不發事件，keeper 不知道有選取，下一個移動回報清掉後就不放回（重試同一段文字必中）。修正：Shift + 拖曳放開時（`document` capture 的 `mouseup`，早於 xterm 自己的處理）呼叫 `handleSelectionDragEnd()` 主動同步。
  - 判斷強制選取的修飾鍵與 xterm `shouldForceSelection` 相同（`forcesTerminalSelection`：macOS 為 Option 且 `macOptionClickForcesSelection`，其他 Shift）。
  - **診斷日誌**：選單開啟時記 `[terminal-context-menu] terminal=… shown: mouseTrackingMode=… shift=… hasSelection=… selectionText=<n> chars keeper=<最近動作>`（`selected` / `restored (mouse report | mouse tracking set again)` / `drag resumed (…)` / `dropped (…)` / `forgotten (mouse press | wheel | buffer switch)` / `not restored (…)`），只在開選單時記。實機再失敗時先看這行。
- 驗證：`src/__tests__/terminal-context-menu.test.tsx`；e2e `e2e/t0571-shift-right-click-copy.spec.ts`（隔離實例，腳本開 alt screen + 1000 / 1002 / 1003 / 1006：Shift + 拖曳 → 移動 → Shift + 右鍵 → 複製 → 剪貼簿 = 反白文字（測試後還原剪貼簿）；打字後 / 一般拖曳 → 只有「貼上」；T0573：腳本另開 1004，失焦 ≥ 1 s 後收到 `ESC [ I` 即重送追蹤 DECSET，步驟 6 = 失焦後以 Shift + 拖曳回到分頁（DECSET 在拖曳中途到達，且與步驟 1 同一範圍）、步驟 7 = 選好後失焦、以 Shift + 右鍵回到分頁（DECSET 在按下與放開之間到達），兩者都要有「複製」且剪貼簿正確；macOS skip）；e2e `e2e/t0568-context-menu-mouse-tracking.spec.ts`（隔離實例，shell 分頁內 node 腳本開 1000 + 1006 並記錄 stdin：一般 shell → 選單、追蹤中 → 腳本收到 `ESC [ < 2 ; … M` 且無選單、Shift → 選單且無回報、關追蹤後 → 選單；T0569：選單開著按 Esc → 選單關閉且腳本 stdin 沒有 `ESC`，選單沒開時 Esc → 腳本收到 `ESC`；macOS skip；需先 `npx vite build`）。

## 滑鼠追蹤殘留的重設（T0672 / BUG-166）

- **原因**（T0671 實測）：codex-cli 0.163.0 以 `/quit`、Ctrl+C、Ctrl+D、Ctrl+Z 離開時會送 `?1006l ?1015l ?1003l ?1002l ?1000l` 與 `?1049l`；被 SIGINT / SIGTERM / SIGHUP / SIGKILL 結束時什麼都不送。claude CLI 只有 SIGKILL 會殘留。xterm 因此停在 `mouseTrackingMode=any`（也還在 alt screen），之後每次滑鼠移動 / 滾輪都把 `ESC[<35;x;yM` / `ESC[<64;x;yM` 寫進 shell；zsh 5.9 與 bash 吃掉 `ESC [ <`，其餘插進命令列（bash `^G35;52;69M…`、zsh `35;52;69M35;55;66M…`，zsh 重繪時另有 `3^H35;…`）。BAT 自己從不寫滑鼠 DECSET / DECRST，也收不到「前景程式結束」的事件（shell 還活著），所以改看症狀。
- **F1 自動關閉**：TerminalPanel 的 `onData` 把送出的 SGR 回報本體（去掉 `ESC[<`，例 `35;52;69M`）交給 `MouseReportEchoDetector.noteInput`（`src/lib/mouse-tracking-reset.ts`，純函式、不 import DOM / electron）；`writeOutput` 每個輸出 chunk 呼叫 `noteOutput`。條件：xterm 處於追蹤（`isMouseTrackingOn(terminal.modes.mouseTrackingMode)`），且某筆回報送出後 `MOUSE_REPORT_ECHO_WINDOW_MS` = 500 ms 內，它的本體出現在輸出中。比對前 `echoMatchText` 去掉 CSI / OSC / 其他 ESC 序列與控制字元（`\x07`、`\x08` 等）；輸出尾巴最多保留 2 048 字元（跨多個 chunk 的回顯也算），最多記 64 筆最近的回報。命中 → `terminal.write(MOUSE_TRACKING_RESET)`（`\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l\x1b[?1015l\x1b[?1016l`，**只寫本機 xterm，不寫 PTY**）、`selectionKeeper.forget('mouse tracking reset')`、清掉進行中的 Shift 拖曳紀錄，日誌 `[mouse-tracking] reset: reports echoed as text terminal=<id> mode=<原模式>`（不記輸出內容）。alt screen（1049）**不**自動離開。
- **誤判邊界**：只有「追蹤中，而且程式把收到的輸入原樣回顯」才會命中（手動 `printf '\e[?1003h'` 後回到 shell、`cat` 這類回顯輸入的工具、滑鼠除錯工具）。codex / claude 執行中會讀走回報、不回顯，行為不變；TUI 輸出的 SGR 顏色（例 `ESC[38;2;35;52;69m`）在比對前已去掉。理論上 TUI 剛好畫出與 500 ms 內某筆回報**完全相同**的字串（含座標）才會誤判。
- **F2 手動**：追蹤中（只能 Shift + 右鍵叫出選單）選單多「重設滑鼠模式」（`terminal.resetMouseMode`），動作同 F1，日誌 `[mouse-tracking] reset: manual …`。alt screen 時另有「離開替代畫面（alt screen）」（`terminal.exitAltScreen`）：本機 `terminal.write('\x1b[?1049l')`，日誌 `[mouse-tracking] alt screen left: manual …`。做成獨立選項的理由：codex 被訊號結束時 alt screen 也殘留，回到的 shell 畫在 alt buffer 上、沒有 scrollback，離開後才看得到 codex 之前的畫面；但它會讓目前畫在 alt buffer 上的提示列消失（按 Enter 重畫），對仍在執行的 TUI（vim、claude fullscreen）則會打亂畫面，所以不併入「重設滑鼠模式」、也不自動執行。兩個選項都在「貼上」之後、以分隔線隔開；追蹤關閉且不在 alt screen 時不出現。
- 與 T0571 / T0573 的互動：`registerCsiHandler` 只攔 `h`，本機送 `l` 不會觸發 keeper；追蹤關閉後不按 Shift 的右鍵恢復開 BAT 選單（正確行為）。
- **已知限制**：命中前的第一筆（幾筆）殘骸仍會進命令列（e2e 實測 3 筆），使用者要 Ctrl+U 清一次；alt screen 不自動離開；DECSET 1004（focus 回報）與 2004 也可能殘留，本單不處理；Windows 原生 ConPTY 分頁（pwsh 裡跑 codex.exe / claude.exe）本來就不會出現殘骸（conhost 把回報轉成 console mouse event），WSL / SSH / Docker / macOS / Linux 分頁才會。
- 驗證：`src/lib/__tests__/mouse-tracking-reset.test.ts`（命中 / 未命中 / 控制字元穿插 / 跨 chunk / 超過時間窗 / 非追蹤 / agent 執行中）、`src/__tests__/terminal-context-menu.test.tsx`「mouse tracking left on (BUG-166 / T0672)」；e2e `e2e/t0672-mouse-tracking-reset.spec.ts`（隔離實例，shell 分頁內 node 腳本開 1003 + 1006 並以 bash readline 的方式回顯 stdin：移動 → 第一批回報後不再收到回報、不按 Shift 的右鍵開 BAT 選單、日誌有 `reset: reports echoed as text`；腳本改為不回顯並重開追蹤 → 回報持續送達、Shift + 右鍵 →「重設滑鼠模式」→ 不再收到回報；macOS skip；需先 `npx vite build`）。Windows pwsh 本身不會重現，所以 F1 e2e 以腳本模擬 shell 的回顯。

# worktree 隔離派工（PLAN-047 W1 / T0583，D150 / D152）

> 從 CLAUDE.md「worktree 隔離派工（PLAN-047 W1 / T0583，D150 / D152）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **契約**（T0583「介面契約」，CT-T015 / CT-T016 依此撰寫，不得單方更改）：派工 `bat-terminal.mjs … --skill ct-exec|ct-done --workorder T#### --isolation worktree`；回收 `bat-terminal.mjs --close-worker T#### --notify-id … [--delay-ms n] [--worktree keep|remove|archive]`。`--isolation` 只收 `worktree`、`--worktree` 只收 `keep` / `remove` / `archive`（皆去空白、不分大小寫），其他值 → exit 1。`--isolation` 只能搭配 `--skill` + `--workorder`（`--prompt` / raw command → exit 1）；不帶 = 不隔離（D152 預設關）。`--worktree` 只在 `--close-worker` 模式有效（其他模式 → exit 1 `close-worker: USAGE`；與 `--set-role` 互斥），不帶 = `keep`。`--close-worker` 與 `--isolation` 互斥（`--isolation` 算建立分頁的參數）。
- **位置與命名**（唯一實作 `electron/ct-worktree.ts` `CtWorktreeService`，本機與 headless 共用、不 import electron）：主 checkout = 派工 cwd 的 `git rev-parse --show-toplevel`（cwd 檢核 T0527 照舊用原 cwd）；worktree = `<主 checkout 上層>/.bat-worktrees/<主 checkout 目錄名>/<T####>`（`ctWorktreeLocation`）；分支 `ct/<T####>`；base = 建立當下主 checkout 的 `HEAD`。已登記在該位置且是 `ct/<T####>` → 沿用（`reused`，不重建）；分支在、worktree 不在 → 在既有分支上建；位置登記了但目錄已不在（prunable）→ `git worktree prune` 後重建；位置被其他東西佔用（一般目錄、別的分支的 worktree）或 `ct/<T####>` 已在別處 checkout → 失敗。沿用 / 既有分支時 base = `git merge-base HEAD ct/<T####>`（fork point）。PTY cwd = worktree 內同一子目錄（不存在則 worktree 根）。工單號經 `normalizeWorkorderId` 後再過 `^[A-Za-z0-9._-]+$`。與 `WorktreeManager`（Agent 面板 / `claude-cli-worktree`，repo 內 `.bat-worktrees`）無關，該功能行為不變。
- **git 呼叫**：一律 `execFile('git', [...])` + timeout（查詢 5 s、`worktree add` 30 s、`worktree remove` 300 s：會刪 ignored 的 `node_modules`），`GIT_TERMINAL_PROMPT=0`。🔴 **Windows 一律帶 `-c core.longpaths=true`**（T0583 實測 git 2.56.0.windows.2：worktree 內路徑 > 260 字元時，沒帶旗標的 `worktree add` 以 `Filename too long` 失敗且**分支已建立**；`status` / `worktree remove` 把長路徑檔看成已刪除，乾淨的 worktree 會被當成髒的而不刪）。headless 用 `createHeadlessGitBinaryResolver()` 與去掉 `BAT_*` 的 env。
- **派工流程**（`createWithCommand`，`electron/terminal-command-handlers.ts`）：參數 / cwd 檢核 → Recovery create hold（T0578 / T0580，順序不變）→ 建立 / 沿用 worktree → `ptyManager.create`。隔離派工**不經** `invokeHandler`；`isolation` 只從 `terminal:create-agent-command` 進來，`terminal:create-with-command` 的 payload 帶 `isolation` 一律拒絕（呼叫者無法指定要記錄 / 清理的 worktree）。失敗 → `{ ok:false, code:'WORKTREE_FAILED', error }`（一行英文、不含權杖），**不建立分頁**；helper exit **7**、stderr `create: WORKTREE_FAILED`。helper 對隔離派工的 invoke 逾時為 40 s（一般 3 s）。
- **env**（BAT 主行程加，不經呼叫者 `customEnv`）：`CT_HOME` = 主 checkout、`CT_WORKTREE` = worktree、`CT_WORKTREE_BRANCH` = `ct/<T####>`、`CT_WORKTREE_BASE` = base SHA；呼叫者 `customEnv` 帶的同名鍵被丟掉。helper 權杖：`authorizeHelperInvoke` 只新放行 `isolation`（只在 `terminal:create-agent-command`、值只能是 `worktree`，否則 `isolation-not-allowed` / `invalid-isolation`），`HELPER_CREATE_ENV_KEYS` 不變（`CT_HOME` 等仍 `custom-env-not-allowed`）。記在 PTY 的 `customEnv`，`pty:restart` / Terminal Server recovery 沿用。
- **輸出**：成功 stdout 在 `✓ Terminal created` / `workspace:` / `agent:` 之後印 `  worktree: <path>`（沿用加 ` (reused)`）、`  branch: ct/T####`、`  base: <sha>`；舊 BAT 忽略 `isolation` 時 stderr 警告「未隔離」。`bat-scripts.log`：helper `terminal-created` 記 `isolation` / `worktree` / `branch` / `base` / `reused`，主行程 `ct-worktree` 事件記同樣欄位 + `mainCheckout` / `createdBranch` / `cwd`，失敗為 `ipc-result` `reason: WORKTREE_FAILED`。主行程日誌 `[ct-worktree]`。
- **回收清理**（`WorkerCloseScheduler`，`electron/close-worker.ts`；`cleanupWorktree` dep = `CtWorktreeService.cleanup`）：`worktree` 參數一路帶到 scheduler（非法值 → `INVALID_ARGS`）；回應多 `worktree: { mode, isolated, path?, branch? }`（只在請求帶 `worktree` 時）。清理在**分頁實際關閉後**才做：close request 送出後每 1 s（`CLOSE_WORKER_TAB_CLOSE_POLL_MS`）查 `isAlive`，連續兩次不在 → 清理；60 s（`CLOSE_WORKER_TAB_CLOSE_WAIT_MS`）後分頁仍在（沒有視窗持有、或使用者 ⏻ 重啟）→ 保留並 warn。延遲 / 等安靜 / 使用者輸入取消（T0545 / T0551）規則不變，取消 = 不清理；延遲中使用者自己關掉分頁 = 不清理。`remove` = `git worktree remove`（不加 `--force`），分支保留；有未提交或未追蹤變更 → 不刪，warn `[ct-worktree] … kept (uncommitted changes)`。`archive` = 同 `remove` 再把分支改名 `ct-archive/<T####>`（已存在則加 `-YYYYMMDD-HHMMSS` 本地時間後綴）。只處理符合位置規則 + `ct/` 分支、且在主 checkout 登記為該分支的 worktree（`parseCtWorktreeRecord` + `git worktree list --porcelain`）；Worker 不是隔離派出的 → 忽略 `--worktree`、照常關分頁，stdout 註明 `worktree: ignored (…)`。exit code 與既有 `--close-worker` 相同（清理晚於 helper 結束，結果只進日誌：`→ removed …; branch kept` / `→ archived …` / `→ … was already gone` / `→ … kept (…)`）。
- **持久化**：worktree 資訊（`path` / `branch` / `base` / `mainCheckout` / `workorder`）記在 `PtyInstance.worktree`（`restart` 與 Terminal Server recovery、冪等 re-create 補齊皆沿用）與分頁 `TerminalInstance.ctWorktree`（`terminal:created-externally` 帶 `ctWorktree`，隨 `workspace:save` 存；detached adopt 沿用；與 Agent 面板的 `worktreePath` / `worktreeBranch` 分開）。BAT 重開後經 T0537 路徑（`withSavedWorkerOwnership` 的 `getWorktree`，`savedWorkerOwnership` 只收符合規則且工單號一致的紀錄）仍可 `--close-worker --worktree`。
- **headless**：同一份實作（server 上的 git、server 上的 repo）；`createHeadlessTerminalModule` 建自己的 `CtWorktreeService`。
- **已知限制**：BAT 不做合併（CT 合併工單負責，CT-T016）、不跑依賴安裝（D152：Worker 依專案規則自己裝，`node_modules` 每個 worktree 約 2 GB）、不提供 `worktree:terminal-status`（T0585）。headless server 重啟後 PTY / 工單 / worktree 紀錄全失（client 存的分頁紀錄不送 server），`--close-worker` 回 `NOT_FOUND`，worktree 留在 server 上需手動清。worktree 若被其他程序佔用（Windows 檔案鎖）`git worktree remove` 失敗 → 保留並 warn（不重試）。主 checkout 本身是 linked worktree 時，位置以該 worktree 的 toplevel 計算。

# 遠端 Tower 通知（PLAN-036 K）

> 從 CLAUDE.md「遠端 Tower 通知（PLAN-036 K）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

遠端視窗（WSL / SSH / Docker profile）裡的 Tower 與本機一樣能派單（`bat-terminal.mjs`）、Worker 能回報（`bat-notify.mjs`，toast + badge + 預填 + `--submit`）。方案 A'（T0420 / D134）：headless bat-server 為**每個 PTY** 簽發範圍權杖，**server token 永不進 PTY env**。實作 T0431（`terminal:*` 上線）/ T0432（權杖）/ T0433（helper 隨 bundle + env 注入）/ T0447-T0450（安全修正）/ T0434（端到端驗收）。

- **遠端 PTY 的 `BAT_*`**（`buildHeadlessHelperEnv`，`electron/remote/headless-entry.ts`）：`BAT_SESSION` / `BAT_TERMINAL_ID` / `BAT_WORKSPACE_ID` + `BAT_REMOTE_PORT`（headless port）/ `BAT_REMOTE_TOKEN`（**= 該 PTY 的權杖**，`batcap.` 前綴，T0449）/ `BAT_SERVER_CERT_PATH`（`<dataDir>/server-cert.json`，helper 指紋釘選用）/ `BAT_HELPER_DIR`（`<installRoot>/scripts`）/ `BAT_HELPER_LOG_DIR`（`<dataDir>/Logs`）/ `BAT_HELPER_NODE`（`<installRoot>/bin/node`，存在才注入，T0456）；另把 `<installRoot>/bin` **附加在 `PATH` 尾端**（不 prepend，使用者自己的 node 仍優先，T0456）。Worker 分頁另有 `BAT_TOWER_TERMINAL_ID`（+ `CT_MODE` / `CT_INTERACTIVE`）。繼承來的 `BAT_*` 一律 scrub（`isHeadlessScrubbedEnvKey` 不變）。`<installRoot>/scripts` 缺 `bat-terminal.mjs` / `bat-notify.mjs`（T0433 前的 bundle、或只部署 JS 的 dev deploy）⇒ **不注入、不簽發、不動 `PATH`**，回到「`BAT_SESSION=1` 但無 helper env」的降級狀態
- **權杖範圍**（`electron/remote/helper-capability.ts`，預設拒絕）：
  | 角色 | 允許 | 限制 |
  |---|---|---|
  | `tower`（無 notify target 的 PTY） | `terminal:create-agent-command`、`terminal:create-with-command`（raw command 模式，本機 T0575、headless T0579）、`terminal:close-worker`（T0536）、`terminal:set-role`（T0562） | set-role：`terminalId` 必須是自己（否則 `target-not-bound`）；close-worker：`towerId` 必須是自己（否則 `tower-not-bound`），只能關 `isWorkerOf(候選, 自己)` 成立的 Worker（不屬於 → `NOT_OWNER`，自己永遠不是自己的 Worker）；create-agent-command 與 create-with-command 同一套檢查：只能建**新** id；create-with-command 的 `command` 須為字串（否則 `invalid-payload`）；`BAT_TOWER_TERMINAL_ID` 只能是自己；`customEnv` 限 `BAT_TOWER_TERMINAL_ID` / `CT_MODE` / `CT_INTERACTIVE` / `MSYS_NO_PATHCONV`；不得指定 `shell`；agent 必須是 registry 已知 id（T0450，未知 → `agent-not-allowed`）；同時存活子 PTY ≤ 8、建立間隔 ≥ 1 s、server 有 PTY 上限時保留 8 個名額給 client（T0450） |
  | `worker`（帶 `BAT_TOWER_TERMINAL_ID` 的 PTY） | `terminal:notify` / `pty:write` / `terminal:keypress` | target 只能是綁定的 tower；`pty:write` 只收可列印文字（控制字元 → `control-character-not-allowed`，送出走 keypress，T0450） |
  | `worker`（T0607） | `question:ask` / `question:cancel` | 沒有目標參數：問題一律送給綁定的 tower，只能取消自己的（`NOT_OWNER`）；`args[0]` 必須是物件（`invalid-payload`） |
  | `tower`（T0607） | `question:answer` | `towerId` 必須是自己（否則 `tower-not-bound`），只能答送給自己的問題（`NOT_OWNER`） |
  | 兩者（T0607） | `question:list` / `question:wait`（唯讀） | 範圍由 handler 判斷（worker：自己提出的；tower：送給自己的），見 [tower-questions.md](tower-questions.md) |
  | 兩者（T0582） | `terminal:whoami` / `list` / `get-state` / `read-output` / `wait`（唯讀） | 範圍由 handler 判斷（`authorizeHelperQueryTarget` / `authorizeHelperListScope`）；`list scope=workspace` / `towers` 只給已宣告的塔台，`towers`（T0643，D167 放寬 D149）列出同一 host 所有工作區的已宣告塔台、只有識別欄位，見 [helper-query-channels.md](helper-query-channels.md) |
  其餘 channel（`pty:create` / `fs:*` / `git:*` / `claude:*` …）一律 `Forbidden: channel-not-allowed`。helper 連線不收廣播、不計入 T0404 孤兒回收的 client 數。上表是 `HELPER_CHANNEL_ROLES`，本機與 headless 共用（T0579 起；`LOCAL_HELPER_CHANNEL_ROLES` 是同一個物件，只為 main.ts 保留名稱）。兩個建立 channel 共用 `HelperTowerSpawnQuota`（`HELPER_CREATE_CHANNELS`）
- **本機 PTY（PLAN-047 A1 / T0575，D149）**：本機 Electron 的 PTY 也改用同一套範圍權杖，**server token 不再進本機 PTY env**（server token 仍持久化在 `server-token.json`，供遠端 client / QR / 行動端認證，`RemoteServer` 照常接受）。
  - **接線**（`electron/main.ts`）：模組層 `localHelperCapabilities`（`HelperCapabilityRegistry`）；`new RemoteServer({ helperCapabilities, helperChannelRoles: LOCAL_HELPER_CHANNEL_ROLES, isTerminalAlive, isKnownAgent（經 normalizeAgentAlias 查 registry，與 headless 同語意）, getPtyCapacity })`；`createElectronPtyDeps()` 的 `helperEnv` = `buildLocalHelperEnv`（`electron/remote/helper-capability.ts`：`BAT_REMOTE_PORT` + 簽發的權杖；`customEnv.BAT_TOWER_TERMINAL_ID` → worker 綁該 tower，否則 tower；RemoteServer 未監聽 → 不簽發、PTY 沒有 `BAT_REMOTE_*`），`onPtyExit` → `revokeTerminal`。三條 spawn 分支、`pty:restart`（保留角色，T0448）、Terminal Server recovery 都經 `buildPtyEnv` 重新簽發；冪等 re-create（含 T0108 replay 後的 `pty:create`）不簽發，執行中的權杖不受影響。
  - **raw command 模式**：本機 tower 可呼叫 `terminal:create-with-command`（`bat-terminal.mjs claude "/ct-exec T####"`），限制與 `terminal:create-agent-command` 相同（只能建新 id、不得指定 `shell`、`customEnv` 白名單、`BAT_TOWER_TERMINAL_ID` 只能是自己、registry agent、`HelperTowerSpawnQuota`：存活子 PTY ≤ 8、間隔 ≥ 1 s；兩個建立 channel 共用配額，`HELPER_CREATE_CHANNELS`）。headless 自 T0579 起同樣允許（見「限制」的遠端 Tower 派單）。本機 `getPtyCapacity` 為 `max: 0`（無上限），不保留 client 名額。
  - **`--close-worker`**：本機 scheduler 的 `isOwnedBy` = `capabilityOrSavedTabOwnership`（`electron/close-worker.ts`），優先序（T0576）：① 候選持有任何 worker 權杖（`hasWorkerCapability`，含 BAT 重開後還原的）→ 只看它是否綁定該塔台（`isWorkerOf`），不符即 `NOT_OWNER`，不論已存分頁怎麼寫；② 否則本行程記錄過工單的 Worker 須有該塔台的 worker 權杖（T0575，同 headless T0536）；③ 否則以已存分頁為準（T0537：Terminal Server 未存活、分頁還原成空 shell — 那是 tower 權杖 — 或 T0575 前的 PTY）。工單號仍來自已存分頁（權杖不記工單）。
  - **行為改變**：非 Worker 分頁（tower 權杖）手動執行 `bat-notify.mjs` → `terminal:notify` / `pty:write` 皆 `Forbidden: role-not-allowed`，exit 1（T0575 前用全權 token 可通知任意分頁）；本機分頁的程式不能再呼叫 `fs:*` / `settings:save` / `claude:*` / 對任意 id 的 `pty:write` / `pty:get-buffer`，也收不到廣播。
  - **升級相容**：升級當下仍存活的舊分頁（Terminal Server 跨版本存活）env 仍是全權 server token，維持可用直到分頁重開（**不輪替** server token，避免既有遠端 client 失效；T0576 不改這點）。舊 helper 不分辨權杖種類，搭配新 BAT 照常可用。
  - **跨 BAT 重開保留（PLAN-047 A2 / T0576，與 T0575 同版，D149）**：Terminal Server 在 BAT 關閉時保留 PTY 與其 env，所以本機權杖紀錄要跟著保留。`HelperCapabilityRegistry` 的 `onChange` 把 `records()`（token 的 SHA-256 digest、`terminalId`、`role`、`towerId`、`issuedAt`；**不含 token**）寫進 `<userData>/helper-capabilities.json`（`writeHelperCapabilityStore`：同目錄 temp 檔 + rename，原子；`{ version: 1, capabilities: [...] }`），簽發 / 撤銷即重寫。路徑在 whenReady 才以 `app.getPath('userData')` 取得（`loadLocalHelperCapabilities`，早於 PtyManager 建立與 `startTerminalServer`）。
    - **還原**：啟動時 `restoreHelperCapabilitiesFromStore` 把紀錄載入為 **pending**（立即可認證）；之後由 `settleRestoredHelperCapabilities` 決定去留：T0108 replay 清單（`PtyManagerDeps.onSurvivingPtys`，`handleReplayList` 呼叫）上的 id 保留、其餘撤銷；沒有存活的 Terminal Server（`startTerminalServer` 走到 fork 前，含 Recovery 選「重新開始」、orphan 清理、direct 模式）→ 全部撤銷；Terminal Server 死掉走 T0112 recovery（`handleServerDeath`）→ 以 `[]` 通知、全部撤銷，重建的 PTY 照常重新簽發。Recovery 提示未回答前 pending 紀錄維持有效（PTY 確實還在 server 上，但 PtyManager 還不認得它們，`--set-role` 會回 `NOT_FOUND`）。
    - **時序**：Recovery 提示回答前，renderer 還原分頁的 `pty:create` 就已送到主行程。T0575 實測當時尚未連上 Terminal Server，`create` 走 **direct node-pty**，同 id 另起一個 shell 並替它簽權杖（日誌 `Created terminal using node-pty`，早於 `user chose recovery`）。**T0578 / T0580 起** Recovery 期間不再 direct spawn：`pty:create`、`pty:restart`、helper 派工（`terminal:create-with-command` / `create-agent-command`）都等 create hold 放行（見「Recovery 提示期間的 `pty:create`」節），所以期間不經 `helperEnv`、不新簽權杖。`issue()` 對 pending 的還原紀錄**不撤銷**（`CapabilityEntry.pending`）、settle 時 id 在 replay 清單 → 保留還原的、撤銷期間新簽的（不在清單 → 反之）的機制保留，涵蓋仍可能在 hold 外同步呼叫 `create` 的路徑。
    - **損毀 / 無效**：檔案讀不出、JSON 壞掉、版本不符 → `logger.warn` + 寫回空檔，不 crash（該批分頁回到 T0576 前：需重開分頁）；個別無效紀錄（digest、id 白名單、角色與 `towerId` 不一致）略過並重寫。
    - **日誌**：`[helper-cap] restored <n> capability record(s) from helper-capabilities.json — pending …` / `kept restored: terminal=<id> (<原因>)` / `dropped restored: terminal=<id> (<原因>)`；只記 id 與角色，不記 token 或 digest。
    - **不持久化**：`role` / `towerMode`（T0565，PtyManager 的 `setTerminalRole`）、`customEnv`、工單仍只在記憶體；重開後 yolo 判定與用量限制自動繼續照 T0565 已知限制，直到塔台再 `--set-role`。

- **生命週期**：registry 只存 SHA-256 digest，token 不寫檔、不記日誌；PTY exit / kill 即撤銷（已認證 socket 上後續 frame 一律不執行、連線 terminate，T0447）；`pty:restart` 保留角色（T0448）。**headless**：只在記憶體，server 重啟全失效。**本機**（T0576）：digest 紀錄存在 `<userData>/helper-capabilities.json`，跨 BAT 重開保留到 PTY 結束（Terminal Server 存活時），見上方「本機 PTY」的「跨 BAT 重開保留」。撤銷 10 分鐘內再用 → `Authentication failed: Capability revoked`；權杖認證失敗**不**計入 server-token 暴力破解封鎖（T0449）
- **限制**：
  - **遠端 Tower 派單兩種模式都可用**（T0579 起，與本機相同）：agent 模式 `bat-terminal.mjs --skill ct-exec --workorder T#### --notify-id "$BAT_TERMINAL_ID" --workspace "$BAT_WORKSPACE_ID"`（或 `--prompt`），以及 raw command 模式 `bat-terminal.mjs [--notify-id …] claude "/ct-exec T####"`（`terminal:create-with-command`，限制同 agent 模式，含 server 有 PTY 上限時保留 8 個 client 名額）。差異：raw command 是把命令原樣打進遠端 login shell，`claude` 取遠端使用者自己的 `PATH`（bundle 內嵌的 claude 在 `<installRoot>/node_modules/@anthropic-ai/claude-code/bin/claude`，不在 `PATH` 上；agent 模式經 runtime router 才會用到它），也不經 `AGENT_UNAVAILABLE` 偵測、不記工單（`--close-worker` 找不到，同本機 raw command）。T0579 前 headless 對 raw command 一律 `Forbidden: channel-not-allowed`
  - `--submit` 的 Enter 由 client renderer 合成：**沒有任何 BAT client 連著時** keypress 回 `no-client`，`bat-notify` exit 1（yolo 不會假裝已送出；預填文字仍寫進 Tower PTY）
  - **遠端 PATH 不一定有 `node`**（WSL 測試機 smoke S10 實測 `node=missing`）：遠端呼叫 helper 用 `"${BAT_HELPER_NODE:-node}"`（T0456；T0456 前部署的 server 無此變數，改用 `"$BAT_HELPER_DIR/../bin/node"`，`scripts/` 與 `bin/` 同在 `<installRoot>`）。T0456 起 `PATH` 尾端也有 `<installRoot>/bin`，但 login shell 的 profile 可能重設 `PATH`（如 Debian `/etc/profile`），`BAT_HELPER_NODE` 才是可靠寫法
  - **`bat-terminal.mjs` 未建立即 exit 1**：server 回 `{ ok:false }`（T0433）或單純 `false`（T0456 起；之前會印 `✓ Terminal created` 並 exit 0）都 exit 1。本機 `false` 情境：無 PtyManager（`no-pty-manager`）、`shell` 被拒（`invalid-shell`，headless `validateShell`）、node-pty 與 child_process 皆 spawn 失敗、`create-agent-command` 同時/皆未給 prompt 與 skill+workorder、或無法為該 agent 組出啟動命令。塔台 auto-session 只信 exit code
  - server bundle 不含 codex：server 上偵測不到 codex 時遠端派 codex 回 `AGENT_UNAVAILABLE`（偵測未完成為 `AGENT_CHECK_PENDING`，稍後重試），T0433
  - 遠端 `~/.claude/skills` 須自行安裝 control-tower 系列 skill
  - 遠端事件只送到收到它的那條連線所屬 profile 的視窗。PLAN-039 起每個 remote profile 各自持有連線（`RemoteConnectionRegistry`，`electron/remote/remote-connection-registry.ts`），WSL + SSH 同時開窗兩邊的 Tower / Worker 通知都正常（T0463 前的「全域只有一個 `remoteClient`、非當前綁定 profile 收不到事件」限制已解除）。已知限制：兩個 profile 指向**同一** server 會各持一條連線，Worker `--submit` 會到兩邊 renderer，Tower PTY 可能收到兩次 Enter（連上時 `logger.warn`）
- **helper 回應必須以 frame id 比對**（BUG-114 / T0490 / T0497）：以 server token 連 RemoteServer 的 helper（T0575 前的本機 PTY、升級時仍存活的舊分頁、BAT 外以 server token 執行的 helper / e2e）屬一般 client，會收到全部 `PROXIED_EVENTS` 廣播（含每個 PTY 的 `pty:output`）。等待 `auth-result` / `invoke-result` 時只接受 `frame.id === 送出的 id`，其餘 frame 一律忽略（`scripts/bat-notify.mjs` `waitForMessageById` / `scripts/bat-terminal.mjs` `waitForMessage`）。auth 等待另接受 `type: 'auth-result'`（`acceptType`）：伺服器 pre-auth 拒絕（banned IP / auth timeout）帶 `id: '0'`，banned IP 在連線時即送、可能與 101 同一 chunk；兩支 helper 的 `MinimalWS` 會暫存 `onMessage` 註冊前抵達的 text frame（`#pending`，T0499 / T0501），該拒絕回報為 `auth-failed`，不再顯示成 `auth-timeout`。T0490 前的 `bat-terminal.mjs` 收「下一個任意 frame」，廣播搶先抵達時誤報 `✓ Terminal created`（exit 0），並在伺服器讀到 invoke 前退出（RST），派發遺失（2026-09-25 起 471 次中 8 次）。新增 helper 腳本時沿用此規則；helper 測試須設 `BAT_HELPER_LOG_DIR` / `BAT_USER_DATA` 到 temp（否則寫入使用者真實的 `bat-scripts.log`）。

# Worker 分頁回收（PLAN-041 / T0535，D144；等安靜 T0545，D145）

> 從 CLAUDE.md「Worker 分頁回收（PLAN-041 / T0535，D144；等安靜 T0545，D145）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **契約**（PLAN-041「介面契約」，CT-T011 依此撰寫，不得單方更改）：`node "$BAT_HELPER_DIR/bat-terminal.mjs" --close-worker T#### --notify-id "$BAT_TERMINAL_ID" [--delay-ms <n>]`。`--close-worker` 格式同 `--workorder`（BAT 去前後空白、轉大寫後比對）；`--notify-id` 必填；`--delay-ms` 預設 0，BAT 夾在 0–300000；與建立分頁的參數（`--cwd` / `--workspace` / `--agent` / `--prompt` / `--skill` / `--workorder` / `--mode` / `--interactive` / `--no-interactive` / 位置參數）互斥。exit code：`0` 已排程（delay 0 且分頁已安靜 = 已送出關閉）/ `3` NOT_FOUND / `4` NOT_OWNER / `5` AMBIGUOUS / `6` BUSY（T0545 起 BAT ≥ 0.6.1-pre.4 不再回，保留供舊 BAT 相容）/ `1` 用法錯誤、連線失敗、BAT 太舊（舊 helper 對 `--close-worker` 印 `Unknown option` exit 1，不建立分頁；新 helper 對舊 BAT 主行程收到 `No handler for channel` → `close-worker: UNSUPPORTED`）。stderr 另印 `close-worker: <CODE>`（診斷用，CT 只看 exit code）；成功 stdout `✓ Worker close scheduled: <id> (in <n> ms)`，T0545 起下一行補「分頁仍在輸出時 BAT 會等安靜（最多再 60 s）」。`bat-scripts.log` 事件 `close-worker`。
- **BAT 檢查**（`terminal:close-worker`，`electron/close-worker.ts` `WorkerCloseScheduler`，main.ts 接線；只由 helper 經 RemoteServer 呼叫，列在 `proxied-channels-binding.test.ts` 的 REGISTRY_ONLY）：參數不合 → `INVALID_ARGS`；先只以工單找 Worker（`PtyManager.findWorkerTerminals(null, workorder)`）→ 0 個 `NOT_FOUND`；再比 `customEnv.BAT_TOWER_TERMINAL_ID` → 都不是此塔台 `NOT_OWNER`、>1 個 `AMBIGUOUS`（Renew 重派等）。**T0545 / D145**：最近有輸出**不再**回 `BUSY`，照常排程（exit 0），日誌 `→ scheduled delayMs=<n> (output <m> ms ago; will wait for quiet)`；`BUSY` 只留在型別與 helper 契約。**不加 Settings 開關**（D144：要不要回收、延遲多久由 CT `*config` 決定）。
- **工單記錄**：`terminal:create-agent-command` 的 skill 模式把 `workorder` 帶到 `PtyInstance.workorder`（`createWithCommand` → `ptyManager.create`），`pty:restart`、Terminal Server 冪等重建（T0108 replay 後補齊）與 recovery 沿用（比照 T0525 `customEnv`）。prompt / raw command 模式不記錄。
- **BAT 重開後（T0537）**：`terminal:created-externally` 帶 `workorder`（正規化後），`addExternalTerminal` 把 `towerTerminalId` / `workorder` 寫進分頁（`TerminalInstance`），隨 `workspace:save` 存進 window registry（detached 視窗的分頁照 `saveDetachedWorkspaceTerminals` 存進父 entry，語意不變）。主行程的 scheduler 經 `withSavedWorkerOwnership`（`electron/worker-ownership.ts`，main.ts 接線）查詢：本行程沒記錄工單的**執行中** PTY，改用 registry 已存分頁的歸屬（`savedWorkerOwnership(windowRegistry.getCachedEntries())`），本行程有記錄者優先；命中時記 `[close-worker] id=… workorder=…: ownership from the saved tab (tower=…)`。因此 Terminal Server 存活（T0108 replay 重新註冊、無 `customEnv`）或未存活（分頁還原成空 shell）都能回收。工單號一律來自已存分頁；歸屬檢查（`isOwnedBy`）自 T0576 起：Terminal Server 存活的 Worker PTY 保有還原的 worker 權杖時，以權杖綁定的塔台為準（見「遠端 Tower 通知」節「本機 PTY」的 `--close-worker`）。歸屬只來自 BAT 視窗存的資料（`workspace:save` 需 `ctx.windowId`，helper 無法寫），不接受請求參數宣告。塔台分頁關閉 / 改名不影響已存歸屬；Worker 分頁 ✕ 後歸屬隨分頁移除。BAT 重開後尚未開啟過的工作區，Worker 分頁的 PTY 還沒還原（Terminal Server 未存活時）→ `NOT_FOUND`，切到該工作區或 detach 後即可。
- **延遲、等安靜與取消（T0545 / D145 改寫）**：計時在 main。延遲期間的**輸出不取消**（agent 回報後常再輸出數秒收尾，T0542 實測）；只有排程後的**使用者輸入** → 取消 `→ cancelled (user input during the delay)`。**使用者輸入**（T0551 / BUG-140 起）= **本機視窗**的 `pty:write`（`handlers/pty.ts` 在 `ctx.connectionId` 為空時呼叫 `noteUserInput`；helper 經 RemoteServer 的寫入不算），且該筆寫入**不是**完全由終端自動回應組成（`isTerminalAutoReply`，`electron/close-worker.ts`）：focus in / out（`ESC [ I` / `ESC [ O`，程式開了 DECSET 1004 時 xterm 在切換分頁 / 工作區時送出，claude CLI 的 TUI 會開）、游標位置回報（`ESC [ <r> ; <c> R`、DECXCPR）、DSR（`ESC [ … n`）、DA1 / DA2 / DA3（`ESC [ ? / > / = … c`）、DECRQM（`… $ y`）、XTWINOPS（`ESC [ … t`）、kitty 鍵盤旗標（`ESC [ ? … u`）、滑鼠回報（SGR / urxvt / X10）、OSC / DCS 回覆。整筆只含這些序列（可多個相連）才不算；夾帶任何其他字元（打字、Enter、貼上含 bracketed paste、IME 確認、單獨 Esc、方向鍵 / 功能鍵）仍算輸入。寫入本身照常送進 PTY，只改「是否算輸入」。滑鼠點擊 / 滾輪（程式開滑鼠模式時）因此也不算。已知重疊：帶修飾鍵的 F3（`ESC [ 1 ; <m> R`）與游標位置回報同形，不算輸入。T0551 前切換焦點會讓回收被取消（實測延遲期間 Worker PTY 只收到 `ESC [ I` / `ESC [ O`）。到期時最近 `CLOSE_WORKER_IDLE_MS` = 5 s 內沒有輸出 → 送 `terminal:close-requested { id }` 給所有視窗（含 detached）；有輸出 → `→ still printing (output <m> ms ago): waiting for quiet (at most 60 s)`，等到連續安靜 5 s 再送（`→ close requested after waiting <x> s for quiet`），從到期起最多再等 `CLOSE_WORKER_MAX_QUIET_WAIT_MS` = 60 s，屆時仍在輸出 → 放棄、分頁保留 `→ cancelled (still printing 60 s after the delay; tab kept)`；等待中有使用者輸入 → `→ cancelled (user input while waiting for quiet)`。delay 0 同理（請求當下即「到期」）。兩個常數皆無注入點，測試用 fake timers。分頁已不存在（延遲中或等待中）→ 靜默結束；同一分頁再次成功請求 → 以最新一次為準（重設計時器，等待中的也取代），被拒的請求不動既有排程。
- **關閉路徑**：renderer 由 `App.tsx` 處理（`ownsTerminalForCloseRequest`：detached 視窗只關自己工作區的分頁，主視窗只關未 detach 的工作區），呼叫 `workspaceStore.closeTerminalNow(id, { cleanWorktree: false })`——不跳確認框、不清 worktree。✕（`WorkspaceView` 的閒置 shell 直接關與確認框確認）也改走 `closeTerminalNow`，逐項與 T0535 前相同（integrated agent → `claude.stopSession`，其他 → `pty.kill`；worktree 只在使用者勾選時清；`removeTerminal` + `save()`）。🔴 改 ✕ 行為時同步看 `src/stores/__tests__/workspace-store.closeTerminalNow.test.ts`（含 T0535 前邏輯的對照與 source guard）。
- **分頁標示與手動批次關閉（T0538，UI）**：有 `towerTerminalId` + `workorder` 的分頁在縮圖列標題後顯示工單小標籤（`.worker-badge`，例 `T0535`；T0553 起標題已含工單號時只在已回報時顯示 `✓`，見下一條），tooltip「`<工單>` 的 Worker，由 `<塔台分頁標題>` 派出」+ 回報狀態；標題 / alias / 拖曳 / 縮圖內容不變。**已回報**：renderer 收到 `terminal:notified`，`targetId` = 該 Worker 的 `towerTerminalId` 且 `source`（去空白、轉大寫，文法同 `--workorder`）= 其 `workorder`（ct-exec 以 `bat-notify --source "T####"` 回報）→ `workspaceStore.markWorkerReported` 把 `TerminalInstance.workerReport = { message（≤ 200 字）, reportedAt }` 寫上並 `save()`，標籤變 `✓ T####`（只顯示，不自動關閉；同塔台同工單的多個 Worker（Renew 重派）一併標示；比對唯一實作 `findReportingWorkers`，`src/stores/workspace-store.ts`）。`workerReport` 隨 T0537 欄位存進 window registry，BAT 重開後仍顯示；detached 視窗照 `saveDetachedWorkspaceTerminals` 存進父 entry，reattach 時 `replaceWorkspaceTerminals` 保留。每個視窗都收到事件、各自標示自己的副本。**右鍵選單**（`TerminalThumbnail`）：Worker 分頁「關閉此 Worker」= ✕（`WorkspaceView.handleCloseTerminal`，確認規則不變）；有 Worker 的塔台分頁「關閉已回報的 Worker 分頁（N）」，N = `reportedWorkersOfTower`，N = 0 停用。點選後先顯示頁內確認（`.worker-batch-close-dialog`，列出工單編號 + 標題，🔴 不得改用 `window.confirm`），確認後逐一 `workspaceStore.closeTerminalNow(id, { cleanWorktree: false })`（不再逐分頁確認、不清 worktree），日誌 `[T0538]`。範圍：清單只取**同一工作區**（該 `WorkspaceView` 的分頁），所以一定在持有分頁的視窗執行（detached 視窗的塔台在 detached 視窗裡操作）；塔台與 Worker 落在不同工作區（T0523 前的舊分頁、或 `--workspace` 落點不同）時，該 Worker 不列入，請在 Worker 分頁用「關閉此 Worker」。
- **外部建立分頁的標題（T0553）**：`addExternalTerminal` 的預設標題由 `externalTerminalTitle`（`src/lib/external-terminal-title.ts`，唯一實作）推得：Worker（`towerTerminalId` + `workorder`）= `<Agent 顯示名> · Worker · <工單號>`（例 `Claude CLI · Worker · T0551`）；其他（raw command 模式）= Agent 顯示名，否則命令檔名（去路徑、引號、pwsh `&`、`.exe` / `.cmd` / `.bat` / `.com` / `.ps1`，例 `node`），沒有命令 = `Terminal`。Agent 顯示名依序取 renderer preset 名稱（`getAgentPreset`，與 Settings 下拉一致）→ main 帶來的 registry 名稱（自訂 CLI）→ 由命令檔名認出的已知 CLI（`claude` / `codex` / `gemini` / `copilot`、`gh copilot`）；都沒有時用命令檔名、再用 agent id。`terminal:created-externally` 自 T0553 起多帶 `agent`（`terminal:create-agent-command` 解析出的 agent id）與 `agentName`（`agentRegistry` 名稱），只供標題，**不**寫進 PTY（`agentPreset` / env 不變）；raw command 模式不帶。本機與 headless 共用 `createWithCommand`。**不再有 `Remote:` 前綴**：只有遠端 server 建立的分頁（事件帶 `remote: true`）記 `TerminalInstance.remoteOrigin`（隨 `workspace:save` 存），縮圖標題後顯示 `.remote-origin-badge`（`profiles.remote`，tooltip `workerTabs.remoteOriginTooltip`）。**工單小標籤**：標題含工單號（`titleShowsWorkorder`）時未回報不顯示、已回報顯示 `✓`（tooltip 不變；未回報時 tooltip 掛在標題上）；使用者改過名（標題不含工單號）時照 T0538 顯示 `T####` / `✓ T####`。縮圖根元素帶 `data-workorder`（e2e 以它找 Worker 分頁）。**使用者命名優先**：改名（`MainPanel` 雙擊 → `renameTerminal` 寫 `title`）後一律不動。**舊分頁**：還原時（`toTerminalInstance`，含 detached adopt）標題若是 T0553 前的預設格式（`Remote: <命令第一個字>` / `Remote Terminal`，`legacyExternalCommand`）即重算成新格式，下次 save 存回；舊格式把含空白的路徑截斷（`'C:\Program`）或 pwsh 的 `&` 時認不出檔名，Worker 顯示 `Terminal · Worker · T####`；舊分頁沒有 `remoteOrigin`，不顯示遠端標籤。驗證：`src/lib/__tests__/external-terminal-title.test.ts`、`src/stores/__tests__/workspace-store.externalTitle.test.ts`、`src/components/__tests__/worker-tab-title.test.tsx`、`electron/__tests__/terminal-handlers.test.ts`（payload `agent` / `agentName`）；e2e `e2e/t0553-worker-tab-title.spec.ts`（隔離實例，自訂 CLI 跑 node 腳本：舊標題還原、Worker 標題、raw command 標題、回報 ✓、改名後保留與 `✓ T####`、重開後仍在；需先 `npx vite build`）。
- **已知限制**：遠端 headless 見下一條；Windows Terminal Server 模式下關閉分頁的程序樹處理見下一節「關閉分頁時的程序樹」（T0540）；Worker 若持續有輸出（例如 TUI 週期重繪、間隔都短於 5 s），到期後等滿 60 s 仍不安靜 → 放棄回收、分頁保留（T0545；helper 已 exit 0，CT 不會得知，只在主行程日誌）。
- **遠端 headless（T0536）**：遠端視窗的 Tower 用同一個 helper 指令（`"${BAT_HELPER_NODE:-node}" "$BAT_HELPER_DIR/bat-terminal.mjs" --close-worker …`），契約與 exit code 不變。headless 的 `terminal:close-worker` 是同一個 `WorkerCloseScheduler`（`createHeadlessTerminalModule`，`electron/remote/headless-entry.ts`），工單記錄同本機（skill 模式派工寫進 headless PTY）；權杖：tower 角色可呼叫、`towerId` 須為自己（`authorizeHelperInvoke`），handler 另以 `HelperCapabilityRegistry.isWorkerOf` 驗證候選（scheduler `isOwnedBy` dep，與 `BAT_TOWER_TERMINAL_ID` 比對同時成立才算；不成立 → `NOT_OWNER`），worker 權杖 → `Forbidden: role-not-allowed`。等安靜（T0545）行為與本機相同；延遲期間與等安靜期間的「使用者輸入」只算 **client 連線**的 `pty:write`（`registerPtyHandlers` 的 `isUserInput` dep → `RemoteServer.isClientConnection`），helper 的寫入不算；終端自動回應的排除（T0551，`isTerminalAutoReply`）與本機同一處判斷（`registerPtyHandlers` 本機與 headless 共用），舊版 client 也適用。`terminal:close-requested` 在 `PROXIED_EVENTS`，經 `RemoteConnectionRegistry` 送到該 profile 的視窗，renderer 沿用 `App.tsx` 的處理。已知限制：到期時沒有任何 client 連著 → 事件無人接收，分頁在下次連線時仍在（不補送）；server 重啟後權杖與工單記錄全失，回 `NOT_FOUND`（client 端存的歸屬（T0537）不送 server、headless 也不讀；只有 client BAT 重開而 server 未重啟時，記錄仍在 server 記憶體，照常可用）。

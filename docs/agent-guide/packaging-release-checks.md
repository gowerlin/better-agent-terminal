# Packaging / Release 前置檢查

> 從 CLAUDE.md「Packaging / Release 前置檢查」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **Squash merge 後打包前必做**：在 main repo 根目錄跑 `npm install`（CI 跑 `npm ci`）確保 `node_modules/` 與 `package-lock.json` 一致。Squash merge 只更新 lock file，不同步實際 `node_modules/`，遺漏此步會導致 native module 缺失（見 BUG-056 / T0242 / T0243）。
- **Build fail-fast**：`npm run build` / `npm run build:release` / `npm run build:dir` 會先執行 `scripts/verify-native-modules.js`，檢查 `@kutalia/whisper-node-addon`、`@lydell/node-pty` 等關鍵 native modules 是否存在於 `node_modules/`（`better-sqlite3` 已於 T0492 移出清單）。缺失即 abort，不會進 vite build 或 electron-builder。新增關鍵 native module（特別是 `build.asarUnpack` 內的）時請同步更新 `REQUIRED_NATIVE_MODULES` 清單。`verify-native-modules.js` 也檢查 **host 平台**的 whisper binary（`@kutalia/whisper-node-addon/dist/<dir>/whisper.node`，`<dir>` 規則與 `electron/whisper-addon-loader.ts` 同步：macOS 為 `mac-<arch>` 優先、`darwin-<arch>` fallback；T0468 / BUG-116）。T0472 起另檢查內嵌 claude：`@anthropic-ai/claude-code/bin/claude.exe` 必須是 host 格式的原生執行檔（PE / ELF / Mach-O），不能是 npm 的 500 bytes stub。T0472 同時加的 `better-sqlite3/build/Release/better_sqlite3.node` 檢查已於 T0492 隨套件移除。desktop host（`win32-x64` / `linux-x64` / `darwin-arm64`）缺失即 exit 1，其他 host（含 `darwin-x64`：mac 只打 arm64，D136 / D137）只 warn。
- **打包產物檢查**（`scripts/verify-packaged-native.js`，T0470 → T0475）：`verify-native-modules.js` 只看打包前 host 的 `node_modules`，看不到 electron-builder 實際打進去的東西（BUG-117 的 x64 `.app` 帶 arm64 binary、BUG-118 的非 Windows 包缺 `claude-code/bin/claude.exe` 都曾讓它假綠燈）。`pre-release.yml` / `release.yml` 在打包之後、上傳 artifact 之前執行，只讀檔頭、不執行產物內任何程式：
  - **mac**（`--platform mac --out release --arch arm64`，`Package for macOS` 之後）：對 `release/mac-arm64/*.app`（x64 會是 `release/mac/`）檢查 (a) `Contents/MacOS/<exe>` 的 cputype 符合 `--arch`，作為基準；(b) `Contents/Resources/app.asar.unpacked` 下所有 Mach-O（含 fat）都是基準 cputype 或 fat 內含基準，ELF / PE 不查，允許清單只有 whisper `dist/{mac,darwin}-<其他 arch>/`（`isCrossArchAllowed`）；(c) 內嵌 claude 依 runtime 規則找到且 cputype 符合；(d) whisper `dist/{mac,darwin}-<arch>/whisper.node` 存在。缺 `.app` 也算失敗
  - **Linux**（`--platform linux --out release --arch x64`，`Package for Linux` 之後）：`release/linux-unpacked/resources/app.asar.unpacked/node_modules/@anthropic-ai/claude-code-linux-x64/claude`（或 fallback `claude-code/bin/claude.exe`）必須存在且為 ELF x86-64
  - **Windows**（T0546，`--platform win --out release --arch x64`，`Package for Windows` 之後）：`release/win-unpacked/resources/app.asar.unpacked/node_modules/@anthropic-ai/claude-code/bin/claude.exe` 必須存在且為 x64 PE（npm 500 bytes stub 會被擋）
  - **三平台共同的瘦身檢查**（T0546，`verifyPackagedLayout`）：讀 `app.asar` 索引（不解壓），問題 id：`duplicate-claude`（Windows 有 `claude-code-win32-*/claude.exe`）、`sdk-binary`（任何 `@anthropic-ai/claude-agent-sdk*`）、`whisper-platforms`（whisper `dist/` 有 `js/` 與本平台以外的目錄）、`server-bundle-baseline`（`resources/bat-server-baseline` 存在，含空目錄；D146 / T0547，T0546 時為 `baseline`：只擋 D092 以外的 target）、`runtime-require`（打包後 `dist-electron` 從 `main.js` / `preload.js` / `terminal-server.js` 可達的字串字面 `require` / `require.resolve` / `<createRequire>.resolve("<pkg>/package.json")`，加上 `dynamicRuntimePackages()` 的計算路徑套件，連同各自 `dependencies` 閉包，必須都在 asar 或 unpacked 內）、`helper-scripts`（T0689：`resources/scripts`（mac 為 `.app/Contents/Resources/scripts`）必須正好是 `serverBundleHelperScripts` 那組，缺一個或多出任何檔案（含子目錄）都失敗並逐檔列出 `missing:` / `extra:`；期望清單由 `runtimeHelperScripts()` 從 `scripts/build-server-bundle.mjs` 解析）、`helper-version`（T0691 / BUG-169：`resources/package.json`（mac 為 `.app/Contents/Resources/package.json`）必須存在、可解析、只有 `name` / `version`、`version` 非空且不是 `0.0.0`，並等於 `app.asar` 內 `package.json` 的 `version`（讀不到時只查檔案本身）；格式判斷 `versionManifestProblems`，`scripts/version-manifest.cjs`）
  - 內嵌 claude 候選規則是 `electron/claude-runtime-router.ts` `embeddedClaudeCandidates` 的 JS 複本（`packagedEmbeddedClaudeCandidates`），router 單元測試斷言兩者一致；改 `build.mac.target` arch、whisper 目錄規則或內嵌路徑規則時同步改此腳本與 workflow 的 `--arch`
- **安裝檔瘦身規則**（T0546，T0544 第一階段）：
  - **node_modules 白名單**：`build.files` 以一條否定 extglob `!node_modules/!(<保留名單>){,/**}` 表示白名單（electron-builder 對 node_modules 只採用 `files` 的**排除** pattern，`app-builder-lib` `getNodeModuleFileMatcher`；寫正向 `node_modules/<pkg>/**` 不會有作用）。保留：`ws`、`opencc-js`、`ajv` / `ajv-formats` 與 `fast-deep-equal` / `fast-uri` / `json-schema-traverse` / `require-from-string`、`node-abi` / `semver` / `node-addon-api`（whisper 的 dependencies，electron-builder 會攤平到頂層）、`@lydell/*`、`@openai/*`、`@kutalia/*`、`@anthropic-ai/claude-code*`。renderer 函式庫（mermaid、highlight.js、react、xterm、i18next…）已被 vite 打包進 `dist/`，main 端的 simple-git / selfsigned / js-yaml / uuid 已被 rollup 打包，都不再進 asar（app.asar 159 → 13.5 MiB）。🔴 **新增執行期依賴**（main 端 `require` 的外部套件，或新的 rollup external）時，把它與其 `dependencies` 閉包加進白名單；`scripts/__tests__/asar-runtime-deps.test.mjs` 以 electron-builder 自己的 matcher 驗證（需先 `npx vite build`，否則跳過 dist-electron 那一項），CI 打包後 `verify-packaged-native.js` 的 `runtime-require` 再驗一次。**動態 require 盲點**：非字串字面的 require（template literal、變數、`createRequire`、`process.dlopen`）掃不到；`electron/` 原始碼出現這種寫法的檔案必須登記在該測試的 `DYNAMIC_REQUIRE_SITES` 並列進 `dynamicRuntimePackages()`（目前：`claude-runtime-router.ts` / `codex-agent-manager.ts` / `whisper-addon-loader.ts`），否則測試失敗
  - 🔴 **不得使用 `build.<platform>.files`**：平台層 `files` 的字串會變成另一個只有排除 pattern 的 matcher，electron-builder 自動補 `**/*`，整個 repo（src/、.claude/、dist-baseline/…）被打進 asar（T0546 實測 508 MiB）。平台差異一律用頂層 `files` 的 `${os}`（目標平台 `win` / `mac` / `linux`）與 `${arch}` 巨集；`${platform}` 是**建置主機**的 `process.platform`，不要用
  - **`claude-agent-sdk*` 不打包**（desktop：白名單不含；server bundle 見下方「bundle 內容限制」）：每個 spawn 點都傳 `pathToClaudeCodeExecutable`，SDK js 已被 rollup 打包進 `dist-electron`，SDK 自帶 claude 不會執行；router 單元測試守住「embedded 缺檔不 fallback 到 SDK binary、packaged / server-bundle layout 不回空路徑」
  - **Windows 只保留 `claude-code/bin/claude.exe`**：`claude-code-win32-*/claude.exe` 是 install.cjs hardlink 的同一檔，electron-builder 會複製成兩份（各 258 MiB），router 在 Windows 只用 `bin/claude.exe`（BUG-052）
  - **不內建 server bundle baseline**（D146 / T0547，T0544 第二階段；取代 T0546「Linux AppImage 只收 `linux-x64` baseline」）：三平台 `extraResources` 沒有 `dist-baseline` / `bat-server-baseline`，`prebuild` 已刪除，`build` / `build:dir` / `build:release` 不跑 `fetch:baseline`。打包前 `verify-helper-bundle.js` 擋任何 baseline 項目（頂層或 `build.<platform>` 的 `extraResources` / `extraFiles`：`from` 為 `dist-baseline`、`to` 為 `bat-server-baseline`、或 filter 為 `bat-server-*.tar.gz[.sha256]`），打包後 `verify-packaged-native.js` 的 `server-bundle-baseline` 再擋一次。runtime 改隨需下載 + 匯入，見「Server bundle baseline（PLAN-031）」
  - **壓縮**：頂層 `compression: "maximum"`（D146 / T0547，T0544 D1），`build.win.compression: "normal"`（T0548）。平台值優先（`platformPackager.compression`：平台值 → 頂層值 → `normal`），所以 mac / Linux 是 maximum、Windows 是 normal。maximum：AppImage → squashfs xz（`AppImageTarget`）、dmg → UDBZ（`dmg-builder`）。Windows 改回 normal 的原因（T0547 實測）：**NSIS 不受影響**，electron-builder 26.8.1 的 `compute7zCompressArgs` 對非 zip 一律 `-mx=9`，normal 已是最高等級（exe 312,525,518 → 312,525,436 bytes、25 → 23 s）；zip 在 maximum 是 7z deflate `-mx=9 -mfb=258 -mpass=15`、normal 是 `-mx=7`，maximum 只小 0.3%（432,395,748 → 431,119,545 bytes），打包 47 → 375 s。`scripts/__tests__/server-bundle-helpers.test.mjs` 以 app-builder-lib 的 `compute7zCompressArgs` 斷言 Windows zip 為 `-mx=7`。dmg 掛載 / AppImage 啟動的影響由 CI / 實機確認
  - **`build` / `build:dir` 先清 `dist-electron`**（T0547）：`npm run clean:dist-electron`（`node -e` 呼叫 `fs.rmSync`，跨平台，不用 shell `rm -rf`）。vite 不清 outDir，舊 chunk 會整批打進 asar。CI 是乾淨 checkout，`build-version.js` 在 CI 只跑 `npm run compile`，不經這一步
  - **whisper 只收本平台**：`!node_modules/@kutalia/whisper-node-addon/dist/!(js|${os}-${arch}|${os}32-${arch}|darwin-${arch}){,/**}`，與 `whisperAddonDirCandidates` 對應（`darwin-${arch}` 因 glob 無法依平台條件，在各平台都會保留；addon 1.1.0 沒有此目錄，若日後出現由 CI 的 `whisper-platforms` 擋下）
  - **產物大小**：`scripts/report-artifact-sizes.mjs`（只讀、無門檻）在三平台 build job 打包後輸出安裝檔大小與 unpacked app 組成（app.asar / unpacked 套件 / baseline（D146 起應為空）/ Electron），D094 復議的資料來源
  - 本機實測（Windows `--dir`，0.6.1-pre.3 程式碼）：`win-unpacked` 2036 → 1354 MiB；linux-x64 server bundle tarball 229.0 → 158.6 MiB
- **Helper bundle fail-fast**：同一條 pipeline 也會跑 `scripts/verify-helper-bundle.js`。安裝檔的 `resources/scripts` 只收**執行期 helper**（T0689）：`package.json` `build.extraResources` 的 `{ from: 'scripts', to: 'scripts' }` 以 `filter` 逐一列出檔名，與 `scripts/build-server-bundle.mjs` 的 `serverBundleHelperScripts` 是同一組（本機 PTY 的 `BAT_HELPER_DIR` = `<resources>/scripts`，`electron/main.ts` `localHelperDir()`，`bat-mcp.mjs` / `bat-hook.mjs` 也從這裡找，`electron/bat-mcp-launch.ts`；headless PTY 的 = `<installRoot>/scripts`）。檢查項目：
  - `scripts` 項目只能有一個，`filter` 每一項都是字面檔名（出現 `*` / `?` / `[` / `{` / `!` 或路徑即失敗：T0247 的 `*.mjs` 會把 `run-legacy-tests.mjs`、`build-server-bundle.mjs` 等建置 / 開發腳本一起打進去）
  - 列出的檔案都存在，且清單對 relative `.mjs` static import 封閉（BUG-058：漏了 `_bat-logger.mjs` / `_bat-cert.mjs`，安裝版 helper `ERR_MODULE_NOT_FOUND`）
  - `filter` 的集合等於 `serverBundleHelperScripts`（任一邊多或少都失敗，訊息寫明兩處都要加）；`serverBundleHelperScripts` 本身仍檢查必備 helper、存在、import 封閉、`copyHelperScripts()` 有被呼叫（T0433）
  - 新增執行期 helper（含它 import 的 `_bat-*.mjs`）：兩處都加檔名，跑 `npm run verify:helpers`。開發 / 建置腳本不必登記，也不會進安裝檔；`bat-server.mjs` 與 `_bat-server-helpers.mjs` 只在建置 server bundle 時從 repo 讀（前者複製到 bundle 的 `bin/`）
  - 打包後 `verify-packaged-native.js` 的 `helper-scripts` 再驗一次實際產物（見上方「打包產物檢查」）
  - 範圍刻意縮小到 top-level `.mjs` + static import；子目錄 / 動態 `import()` 不在掃描內。
- **helper 的版號來源**（T0691 / BUG-169）：`bat-terminal.mjs` / `bat-notify.mjs` / `bat-mcp.mjs` 的 `--version` 與 BAT MCP `initialize` 的 `serverInfo.version` 讀 `join(<helper 目錄>, '..', 'package.json')`，讀不到 fallback `0.0.0`（三個 helper 寫法相同，本單未改）。開發時是 repo 根目錄的 `package.json`；server bundle 是 bundle 根目錄的 `package.json`（`build-server-bundle.mjs`）；安裝版是 `<resources>/package.json`，由 electron-builder `afterPack` hook 寫入（`package.json` `build.afterPack` = `./scripts/version-manifest.cjs`）。兩邊都用 `versionManifestContent(name, version)` 產生只含 `name` / `version` 的檔，不要再另寫一份格式。
  - 版號 = 實際打包的版號：hook 取 `packager.appInfo.version`（即寫進 `app.asar` 的 app `package.json`，含 `extraMetadata`），不讀 repo `package.json` 字面值。CI 先跑 `build-version.js`（`VERSION` env 改寫 `package.json`、不還原）再跑 `electron-builder`，本機 `build` / `build:dir` 直接讀 `package.json`，兩條路都由同一個 hook 寫檔。hook 在 extraResources 複製之後、簽章之前執行（mac 的 `.app` 簽章會涵蓋此檔）；拿不到 name / version 時 throw，打包失敗。
  - 🔴 不得放進 `resources/scripts`（T0689：只放 6 個執行期 helper，`helper-scripts` 會擋），也不得改用 `build.<platform>.extraResources`。
  - Electron 不會把 `<resources>/package.json` 當 app 載入：Electron 41 的 `lib/browser/init.ts` 只依序試 `<resources>/app`、`app.asar`、`default_app.asar` 底下的 `package.json`（`appSearchPaths`，`shell/common/node_bindings.cc`；T0691 以 electron 41.2.1 執行檔內嵌的 init 程式碼查證）。`app.asar.unpacked/` 根目錄沒有 `package.json`，所以 unpacked 的 `dist-electron/terminal-server.js` 往上找到的 package scope 會是這個檔；它沒有 `type` / `exports` / `imports`，Node 的判定與「找不到 package.json」相同（CommonJS）。🔴 不要在這個檔加 `type` 或其他欄位（`helper-version` 擋多出欄位）。
  - 打包後 `verify-packaged-native.js` 的 `helper-version` 驗實際產物（見上方「打包產物檢查」）。
- **CI pipeline**：`.github/workflows/pre-release.yml` 三平台 build job 依序為 `npm ci` → `@electron/rebuild` → `verify-native-modules.js` → `verify-helper-bundle.js`（在 `build-version.js` 開頭自動 require） → `build-version.js` → `electron-builder` → `verify-packaged-native.js`（三平台，Windows 自 T0546）→ `report-artifact-sizes.mjs`（T0546，`continue-on-error`）→ 上傳 artifact。新增 CI job 時請沿用相同順序。D146 / T0547 起 build job 不下載 `server-bundle-baseline`、`needs` 只有 `[prepare, typecheck]`（與 server-bundle 並行；T0686 起為 `[prepare, typecheck, tests]`）；`release` job 改 `needs: [prepare, build, server-bundle-manifest]`，server bundle 建置失敗仍不發版，也不會只發 desktop。
- **Typecheck gate**（T0495 / T0496）：`pre-release.yml` / `release.yml` 有獨立 `typecheck` job（`ubuntu-24.04`，`npm ci --ignore-scripts` → `npm run typecheck` → `npm run typecheck:electron`，無 `needs`，與 server-bundle 並行），列在 `build.needs`。typecheck 失敗 → `build` skipped → `release`（及 `choco`）skipped，不發版。`--ignore-scripts` 足夠：`tsc` 只讀套件內的 `.d.ts`（T0495 實測無 electron `dist/` 時 exit 0）。改 `tsconfig.json` / `tsconfig.node.json` 的 `include` 或新增依賴 postinstall 產物的型別時，先以 `npm ci --ignore-scripts && npm run typecheck && npm run typecheck:electron` 確認。
- **Test gate**（T0686，BUG-168 / D177）：`pre-release.yml` / `release.yml` 有 `tests` job，`uses: ./.github/workflows/tests.yml`（`tests.yml` 同時有 `workflow_dispatch` 與 `workflow_call`，測試定義只有這一份），無 `needs`，與 typecheck、server-bundle 並行，列在 `build.needs`。
  - 內容（`tests.yml` 的 `unit-tests` job，`ubuntu-24.04`）：`npm ci --ignore-scripts` → `node node_modules/electron/install.js`（只跑 electron 的 postinstall：部分測試未 mock 就 `require('electron')`）→ `npm run test:unit` → `npm run test:legacy`（unit 失敗時仍跑，`!cancelled()`）→ summary（兩者的 passed / failed 寫進 job summary）。`BAT_HELPER_LOG_DIR` / `BAT_USER_DATA` 指到 `runner.temp`。任一步失敗 job 即失敗。
  - 時間：約 4 分鐘（T0685 後第二次試跑 run `39609350106`：`test:unit` 5760 passed / 0 failed / 6 skipped（326 檔）、`test:legacy` 33 檔 472 / 0），比 build 短，正常情況不拖慢發版。
  - 失敗的影響：`tests` 失敗 → `build` skipped → `release`（及 `choco`）skipped，不建 GitHub Release（pre-release 的 tag 由 `release` job 建立，也不會產生；release 的 tag 是使用者推的，留著）、也不發 `server-bundle-v<版號>`；`server-bundle` / `server-bundle-manifest` 照跑但不發佈。修好後重跑：pre-release 重新 `workflow_dispatch`；release 對同一 tag「Re-run failed jobs」，或修正後重新推 tag。
  - 權限：呼叫端 job 設 `permissions: contents: read`、不傳 secret（沒有 `secrets: inherit`）；被呼叫的 workflow 拿到的權杖不會超過呼叫端 job 給的範圍。
  - 觸發與 ref：本地 `uses: ./…` 取用呼叫端同一個 commit 的 `tests.yml`。release（push `v*` tag）測的是該 tag 的 commit，pre-release（`workflow_dispatch`）測的是觸發時選的 ref；被呼叫端的 `github.event_name` / `github.ref` 沿用呼叫端，`tests.yml` 不讀這些值，所以行為與手動試跑相同。Actions 頁面上顯示為 `tests / unit-tests`。
  - 本機重現：`npm run test:unit`、`npm run test:legacy`（後者見 CLAUDE.md「Frontend unit tests」節）。Linux 與 Windows 的路徑、時區差異已由 T0684 處理；本機在 Windows 全過不代表 ubuntu 全過，有疑慮時手動 `workflow_dispatch` `tests.yml` 試跑（不會發版）。
  - 🔴 新增 / 改測試步驟只改 `tests.yml`，不要在 `pre-release.yml` / `release.yml` 內另寫一份；要加 `inputs` / `secrets` 時兩個呼叫端一起改。驗證 workflow 用 actionlint（本機沒有時 `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.7`），它會檢查被呼叫端有沒有 `workflow_call` 與 `needs` 名稱。
- **Release 驗收必跑 NSIS 完整重裝**：`--dir` mode 和 `zip` smoke 不是 production 等價；release 前必須完整「uninstall → 跑 installer → 啟動 UI → 踩 voice input / terminal 路徑」驗收（BUG-056 盲點記錄；原清單的 sqlite 路徑隨 better-sqlite3 於 T0492 移除，app 本來就沒用它）。

# Server bundle baseline（PLAN-031；D146 起安裝檔不內建）

- **不內建、隨需下載 + 匯入**（D146 / T0547，0.6.1-pre.4 起；推翻 D092 的「安裝檔內建 baseline」，D093 / D095 / D120 保留）：安裝檔沒有 `resources/bat-server-baseline`（打包規則見「Packaging / Release 前置檢查」的安裝檔瘦身規則）。WSL / SSH wizard 的 `install-server-bundle` 經 distributor（`electron/remote/server-bundle-distributor.ts`）依序：
  1. **cache + 自帶 sidecar**：`userData/bat-server-bundles/bat-server-<target>-v<版號>.tar.gz` 以同目錄 `<tarball>.sha256`（sha256sum 格式）驗證，**不連網、不需 baseline**（`lookupCachedTarball`，`electron/remote/server-bundle-cache.ts`）；不符 → tarball 與 sidecar 一併刪除。sidecar 只在 tarball 以已驗證來源進 cache 時寫入：下載（release manifest，`server-bundle-download.ts`，cache 命中時也補寫）、匯入（使用者的 `.sha256`）、baseline 複製（baseline manifest）

  3. **下載** `server-bundle-v<版號>`（`stripSnapshotSuffix`，T0492；`BAT_SERVER_BUNDLE_BASE_URL` 覆寫不變）。T0547 前留下、沒有 sidecar 的 cache 由下載路徑以 release manifest 驗證（命中只抓 manifest）並補 sidecar。**連線錯誤的重試**（T0548，`toAttemptError`，`electron/remote/server-bundle-download.ts`）：Node fetch 丟 `TypeError('fetch failed')`，socket 錯誤在 `cause`（多位址主機如 `localhost` 為 `AggregateError`，各位址錯誤在 `errors`）；錯誤碼沿整條 `cause` 鏈與 `errors` 找，每層依序取 `code` → `errno`（字串，或負數經 `util.getSystemErrorName`）→ `message` 內的 `E…` / `UND_ERR_…` 字樣，`UND_ERR_CONNECT_TIMEOUT` 視為 `ETIMEDOUT`，取第一個重試表接受者。重試次數 / 間隔（500 / 1500 / 3000 ms）與可重試錯誤碼不變。沒有任何錯誤碼的錯誤不重試，例如 fetch 規範封鎖的連接埠（`bad port`，如 9）；T0547 觀察到的「`127.0.0.1:9` 0 秒失敗」就是這個，不是 ECONNREFUSED（Electron 41 / Windows 的 ECONNREFUSED 本來就帶 `cause.code`，T0548 實測）

# blocked 狀態偵測（PLAN-047 M1b / T0590）

> 從 CLAUDE.md「blocked 狀態偵測（PLAN-047 M1b / T0590）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **用途**：CT 斷點 D 要知道 Worker 停在**等人回答**（權限確認、AskUserQuestion、MCP elicitation），而不是在工作或已結束。claude-cli 分頁以 claude 的 hooks 回報（立即、可信）；codex 分頁以 codex 自己送的 OSC 7501 回報（T0621 / D158，見下方「codex（OSC 7501）」；T0574 規劃的 OSC 9 + 句型後援經 T0619 實測後不採用）。
- **契約**（T0590「介面契約」，CT 斷點 D 依此撰寫，不得單方更改）：`terminal:get-state` / `terminal:list` 的 `state` / `terminal:wait` 多一個 `blocked`，優先序 `exited` > `blocked` > `working` / `idle`。`blocked` 時另回 `blockedReason`（`permission` / `question` / `elicitation`）、`blockedSince`（ms）、`source: 'hook'`（其他狀態 `source: 'output'`）。**每個** state 回傳（get-state / wait / list 每一列）都帶 `blockedDetection`：`hook` = 這個分頁注入了 BAT hooks（或曾經回報過）/ `none` = 沒有（非 claude-cli、Settings 關閉、自訂參數已含 `--settings`、找不到 `bat-hook.mjs`、raw command 模式、BAT 重開後未再經過啟動決策…）。`none` 的分頁永遠不會回 hook 的 reason（`permission` / `question` / `elicitation`），CT 據此知道它的 `idle` 不代表「沒有在等人」。**T0607 / D156**：`blockedReason` 另有 `tower`（Worker 有 blocking 的待答問題在等塔台答覆，`source: 'question'`，`blockedSince` = 最早那個問題的建立時間）；它由 BAT 自己的問答 store 判斷、不靠 hook，所以 `none` 分頁（codex）也會回；優先序 `exited` > hook 的 `blocked` > `blocked` / `tower` > `working` / `idle`；使用者輸入不清除它；每個 state 回傳另帶 `pendingQuestions`。細節見 [tower-questions.md](tower-questions.md)。`terminal:wait` 參數不變：`until: 'state-change'` 在進入 / 離開 `blocked` 時成立，`fromState` 可為 `blocked`；`until: 'idle'` 以「不是 `working`」判斷，所以 `blocked` 也成立（`exited` 同）。唯一實作：狀態機 `TerminalBlockedTracker`、handler `registerReportHookHandler`（`electron/terminal-blocked-state.ts`），讀取在 `terminal-query-handlers.ts` 的 `stateOf`；本機與 headless 共用。
- **事件表**（`BAT_CLAUDE_HOOKS`，`electron/bat-mcp-launch.ts`）：

  | claude hook | matcher | `bat-hook.mjs <event>` | 效果 |
  |---|---|---|---|
  | `PermissionRequest` | — | `permission-request` | → `blocked` / `permission`（`tool_name` 不回傳）；`tool_name` = `AskUserQuestion` → `question`（T0597，見表下說明） |
  | `PreToolUse` | `AskUserQuestion` | `ask-user-question` | → `blocked` / `question` |
  | `Notification` | `elicitation_dialog\|elicitation_url_dialog` | `elicitation` | → `blocked` / `elicitation` |
  | `PostToolUse`（`async`，T0594） | `AskUserQuestion` | `ask-user-question-done` | 只在 `blockedReason` = `question` 時清除；其他 reason / 未 blocked → `unchanged`（`HOOK_EVENT_CLEARS_ONLY`） |
  | `ElicitationResult`（`async`，T0620） | — | `elicitation-done` | 只在 `blockedReason` = `elicitation` 時清除；其他 reason / 未 blocked → `unchanged`（`HOOK_EVENT_CLEARS_ONLY`） |
  | `Notification`（`async`，T0620） | `elicitation_response` | `elicitation-done` | 同上 |
  | `UserPromptSubmit`（`async`） | — | `user-prompt-submit` | 清除 |
  | `Stop`（`async`） | — | `stop` | 清除 |
  | `SessionStart`（`async`，T0600） | — | `session-start` | 不影響 `blocked`；記 `agentStarted`（見「Worker 啟動確認（T0600，D154）」節 / [worker-launch-confirmation.md](worker-launch-confirmation.md)） |

  進入類同步執行（claude 等 hook 結束才顯示對話框，回報一定早於使用者回答）；清除類 `async: true`（claude 不等，不增加每次送出 / 結束的延遲）。`PostToolUse` 只掛 matcher `AskUserQuestion`（T0594：問題回答後該工具才執行完，**滑鼠**回答也觸發；不加全工具 matcher，每次工具呼叫都要啟動 node）。**不掛 `PermissionDenied`**（T0594 查證 claude 2.1.300 二進位：summary 為 `After auto mode classifier denies a tool call`，只在 `decisionReason.type === 'classifier'` 且 `classifier === 'auto-mode'` 時執行，payload `tool_name` / `tool_input` / `tool_use_id` / `reason`；使用者在權限對話框按拒絕走的 deny 路徑不呼叫任何 hook，也沒有 `PostToolUse` / `PostToolUseFailure`。classifier 拒絕時沒有對話框，平行工具呼叫中另一個工具的權限對話框仍開著時收到它反而會誤清）；`Notification` 的 `permission_prompt`（約 6 s）/ `idle_prompt`（約 60 s）不採用。`elicitation_url_dialog` 是 claude 2.1.300 對 URL 型 elicitation 的類型（二進位實讀），契約只寫 `elicitation_dialog`，T0590 一併算 `elicitation`。已在 `blocked` 再收到同一 reason → `unchanged`（`blockedSince` 不變）；不同 reason → 換成新的。**AskUserQuestion 的 `PermissionRequest`**（T0597 / BUG-150）：claude 2.1.300 / 2.1.302 的 AskUserQuestion `requiresUserInteraction()` 為真、`checkPermissions` 一律回 `behavior: "ask"`，問題對話框本身走權限提示路徑，所以**任何權限模式**（含 `--dangerously-skip-permissions`）下都會在 `PreToolUse` 之後約 90 ms 執行 `PermissionRequest` hook（`tool_name: AskUserQuestion`；T0596 二進位字串與實機日誌查證）。reason 由 `hookEventReason(event, toolName)`（`electron/terminal-blocked-state.ts`）決定：這個組合記為 `question`，所以已是 `question` → `unchanged`（`blockedSince` 保留 `PreToolUse` 的時間）、沒有先收到 `PreToolUse` → 直接 `question`；`question` 期間收到其他工具（`Bash` 等）的 `PermissionRequest` 照舊換成 `permission`。T0597 前它把 reason 換成 `permission`，`ask-user-question-done` 因此永遠是 `unchanged`。依賴 `tool_name` 字串：claude 改名、或不帶 `tool_name` 的舊 `bat-hook.mjs`，退回 `permission`。
- **elicitation 結束（T0620）**：查證內嵌 claude 2.1.300 二進位（靜態閱讀，未實機觸發 elicitation）。互動模式的 elicitation handler 依序：`Elicitation` hook（若由 hook 直接回應 → 不顯示對話框，也不送 `elicitation_dialog`）→ 顯示對話框（`requestDialog`，送 `Notification` `elicitation_dialog` / `elicitation_url_dialog`）→ 對話框結束（接受 / 拒絕 / 取消；MCP 請求被中止時 `requestDialog` 回對話框預設值 `{ action: "cancel" }`）→ `runElicitationResultHooks`：先跑 `ElicitationResult` hook（payload `mcp_server_name` / `elicitation_id` / `mode` / `action` / `content`；hook runner 在請求 signal 已中止時 `if (signal.aborted) return []`，所以**請求被取消 / 逾時時不執行**），**之後一律**送 `Notification` `elicitation_response`（訊息 `Elicitation response for server "<名稱>": <action>`；`ElicitationResult` hook 擋下或出錯的分支也送；Notification runner 不帶請求 signal）。所以兩個都掛、都對應 `elicitation-done`：`elicitation_response` 涵蓋全部結束路徑（含中止 / 逾時），`ElicitationResult` 不必等使用者自己設定的 `ElicitationResult` hook 跑完（`elicitation_response` 在它們之後才送），兩者任一改名另一個仍有效；同一次結束收到兩次 → 第二次 `unchanged`。**不掛 `elicitation_complete`**：它是 URL 型 elicitation 的伺服器端完成通知（`notifications/elicitation/complete`），只關閉接受後的「等待完成」畫面，可能在原對話框還開著時就到，會誤清。`content` / `action` / 訊息一律不送（`content` 是使用者在表單填的值）。
- **清除規則**：上表的 `user-prompt-submit` / `stop`（任何 reason）、`ask-user-question-done`（只清 `question`：問題回答後權限對話框接著出現時不被誤清；T0594）與 `elicitation-done`（只清 `elicitation`，同理；T0620）；該分頁的**使用者輸入**（`PtyManager.noteUserInput`：本機視窗 / headless client 的 `pty:write`，非 `{ auto: true }`、非 `isTerminalAutoReply`，與 T0551 / T0566 同一判斷，`handlers/pty.ts` 不變）；PTY 結束（exit / kill，所以 `pty:restart` 也清）；Terminal Server recovery（全部清）。
- **回報 channel** `terminal:report-hook`（只供 helper 經 RemoteServer 呼叫；`proxied-channels-binding.test.ts` REGISTRY_ONLY、`headless-parity.test.ts` HELPER_ONLY；`HELPER_CHANNEL_ROLES` tower / worker 皆可，因此是 14 個 channel（T0607 加 5 個 `question:*` 後為 19 個），未宣告的 shell 分頁拿的是 tower 權杖也能回報；`authorizeHelperInvoke` 直接放行）：參數 `{ event, toolName? }`，目標**永遠是呼叫者自己**（`ctx.helper.terminalId`，沒有 `terminalId` 參數，帶了也忽略）。回 `{ ok: true, terminalId, result: 'blocked' | 'cleared' | 'unchanged', state: 'blocked' | 'not-blocked', blockedReason? }`；參數不合（含沒有 helper 權杖的 server token / 本機呼叫、`toolName` 不符 `^[A-Za-z0-9_.:-]{1,128}$`）→ `INVALID_ARGS`；呼叫者 PTY 不在 → `NOT_FOUND`。`toolName` 只在 `permission-request` 保留（進日誌；`AskUserQuestion` 決定 reason 為 `question`，T0597）。每次回報 O(1)；日誌只記轉換，`bat-scripts.log` 的 `unchanged` 每分頁每 5 s 最多一筆（`REPORT_HOOK_UNCHANGED_LOG_INTERVAL_MS`），不另設配額（RemoteServer 既有的 helper denial 節流照舊）。一次被接受的回報也把該分頁的 `blockedDetection` 設為 `hook`（證明它真的在回報），所以「`none` 不會回 hook reason」恆成立（`tower` 不在此限，T0607）。
- **注入**（`buildBatMcpLaunchArgs`，與 BAT MCP 同一入口、同一組條件，本機與 headless 共用）：只對 `claude-cli` / `claude-cli-worktree`，`--mcp-config=` 之後接 `--settings=<dataDir>/bat-mcp/claude-settings.json`（`=` 形式：claude 2.1.300 的 `--settings <file-or-json>` 只收一個值，`=` 兩種情況都安全，比照 `--mcp-config=`）。用檔案不用 JSON 字串：hook 命令本身含引號，放命令列要再為 pwsh / bash / cmd 各包一層。設定檔只有 `hooks`（**不得**有 `disableAllHooks`、權限、模型或其他鍵；無權杖），內容不同才重寫（temp + rename，`ensureBatMcpFile`）。每個 hook：`{ type: 'command', command, timeout: 5[, async: true] }`，`command` = `<node> '<helperDir>/bat-hook.mjs' <event>`（`batHookCommand`）：claude 以 bash（Windows 為 Git Bash）執行 hook、Windows 沒有 Git Bash 時用 PowerShell，同一字串要兩邊都對 → node 命令是裸字（本機 `node`；headless `<installRoot>/bin/node`，POSIX 路徑含空白時單引號）、腳本路徑單引號（兩種 shell 都是字面值）、Windows 路徑轉 `/`（node 接受 `C:/…`，bash 會吃掉反斜線）；路徑含 `'`、或 Windows 的 node 命令需要引號 → 不注入 hooks。不用 claude 2.1.300 的 exec form（`args`）：較舊的 system claude 若不認得會把 `node` 當 REPL 跑。不注入 hooks：Settings「BAT MCP」關閉（MCP 一起關）、自訂參數已含 `--settings`（MCP 照常）、找不到 `bat-hook.mjs`（MCP 照常）、RemoteServer 未監聽、非 claude。自訂參數已含 `--mcp-config` 只略過 MCP，hooks 照注入。結果型別 `BatMcpLaunchResult` 多 `mcp` / `hooks` / `mcpReason` / `hooksReason`；日誌 `[bat-mcp] tab|dispatch agent=<id> terminal=<id> → injected: <args>[; mcp=no (<原因>)]; hooks=yes|no (<原因>)`（codex 不印 hooks）。
- **`blockedDetection` 記錄**：`createBatMcpLaunchArgs` 在請求帶 `terminalId` 時呼叫 host 的 `recordBlockedDetection` → `PtyManager.setBlockedDetection`（`hook` = 注入了 hooks，否則 `none`；codex 的啟動決策一律記 `none`，T0621 起再由派工的版本判定或觀察到 OSC 7501 改成 `osc`，見下方 codex 節）。renderer 的 `withBatMcpLaunchArgs` 第 5 參數帶分頁 id（`agent:bat-mcp-launch-args` 第 4 參數；T0590 前的 server 忽略多出的參數，T0590 前的 renderer 不帶 → 不記錄），helper 派工由 `createAgentPromptCommandBuilder` 帶新分頁 id。記錄以 terminal id 為鍵、**與 PTY instance 分開**（`TerminalBlockedTracker`，最多 `BLOCKED_DETECTION_MAX` = 512 個 id），所以 claude-cli 分頁「先決定、後 `pty:create`」、`restart`、Terminal Server recovery 都沿用，PTY 結束後 `exited` 的回傳也還有；同一 id 之後的啟動決策取代它。PtyManager 的接點只有 `reportHookEvent` / `getBlockedState` / `setBlockedDetection` / `getBlockedDetection`，與 `clearActivity` / `noteUserInput` / `handleServerDeath` / `dispose` 內各一行（T0600 另加 `getAgentStartedAt`、`recordExit` / `clearActivity` 各一行與方案 B 的 `LaunchSuspectWatcher`）。
- **hook 腳本** `scripts/bat-hook.mjs`：🔴 **不得影響 claude**：一律 exit 0、stdout 不輸出任何東西（`PermissionRequest` / `PreToolUse` 印 JSON 會替使用者做決定）、任何失敗靜默、總時限 `HOOK_DEADLINE_MS` = 1.8 s（stdin 300 ms、連線 1 s、invoke 1 s）。沒有 `BAT_REMOTE_PORT` / `BAT_REMOTE_TOKEN` → 立即 exit 0。從 stdin 只取 `hook_event_name` / `tool_name` / `notification_type`（`hookReport`：`hook_event_name` 與 argv 事件不符、`elicitation` 的 `Notification` 不是 `elicitation_dialog` / `elicitation_url_dialog`、`elicitation-done` 的 `Notification` 不是 `elicitation_response`（`elicitation-done` 接受 `ElicitationResult` 與 `Notification` 兩種 `hook_event_name`）、`PreToolUse` / `PostToolUse` 不是 `AskUserQuestion` → 不送），只送事件名與（權限事件的）`tool_name`，**不送** `tool_input`、`tool_response`（AskUserQuestion 的答案）、elicitation 的 `content` / `action`、prompt、訊息或權杖。連線重用 `scripts/bat-mcp.mjs` 的 `BatConnection`（憑證 pinning `_bat-cert.mjs`、frame id 比對 BUG-114；新增 `clientName` 選項，auth label `bat-hook`）。`bat-scripts.log`：helper `script: 'bat-hook'`、`event: 'report-hook'`、`hook`、`result`、`code?`、`durationMs`、`terminalId`；主行程 `mirrorToBatScripts('report-hook', { terminalId, hook, result })`（欄位名用 `hook`：兩個 logger 都把 data 展開在 `event` 之後，`event` 會被蓋掉）。出貨：安裝檔 `extraResources` `*.mjs` 已涵蓋；server bundle `serverBundleHelperScripts` 多 `bat-hook.mjs`（6 個，`verify-helper-bundle.js` 的必要清單也加了它）。
- **日誌** `[blocked]`：`[blocked] terminal=<id> → blocked reason=<r> (hook <event>[ tool=<name>])` / `→ cleared (<原因>)`（`hook user-prompt-submit` / `hook stop` / `user input` / `the PTY ended` / `Terminal Server recovery`）；被拒的回報 `[blocked] report-hook caller=<id> event=<e> → INVALID_ARGS|NOT_FOUND`。不記內容、不記權杖。

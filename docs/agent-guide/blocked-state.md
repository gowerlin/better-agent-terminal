# blocked 狀態偵測（PLAN-047 M1b / T0590）

> 從 CLAUDE.md「blocked 狀態偵測（PLAN-047 M1b / T0590）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **用途**：CT 斷點 D 要知道 Worker 停在**等人回答**（權限確認、AskUserQuestion、MCP elicitation），而不是在工作或已結束。claude-cli 分頁以 claude 的 hooks 回報（立即、可信）；codex（OSC 9 + 句型後援）是 M1b-2，本節不含。
- **契約**（T0590「介面契約」，CT 斷點 D 依此撰寫，不得單方更改）：`terminal:get-state` / `terminal:list` 的 `state` / `terminal:wait` 多一個 `blocked`，優先序 `exited` > `blocked` > `working` / `idle`。`blocked` 時另回 `blockedReason`（`permission` / `question` / `elicitation`）、`blockedSince`（ms）、`source: 'hook'`（其他狀態 `source: 'output'`）。**每個** state 回傳（get-state / wait / list 每一列）都帶 `blockedDetection`：`hook` = 這個分頁注入了 BAT hooks（或曾經回報過）/ `none` = 沒有（非 claude-cli、Settings 關閉、自訂參數已含 `--settings`、找不到 `bat-hook.mjs`、raw command 模式、BAT 重開後未再經過啟動決策…）。`none` 的分頁永遠不會回 `blocked`，CT 據此知道它的 `idle` 不代表「沒有在等人」。`terminal:wait` 參數不變：`until: 'state-change'` 在進入 / 離開 `blocked` 時成立，`fromState` 可為 `blocked`；`until: 'idle'` 以「不是 `working`」判斷，所以 `blocked` 也成立（`exited` 同）。唯一實作：狀態機 `TerminalBlockedTracker`、handler `registerReportHookHandler`（`electron/terminal-blocked-state.ts`），讀取在 `terminal-query-handlers.ts` 的 `stateOf`；本機與 headless 共用。
- **事件表**（`BAT_CLAUDE_HOOKS`，`electron/bat-mcp-launch.ts`）：

  | claude hook | matcher | `bat-hook.mjs <event>` | 效果 |
  |---|---|---|---|
  | `PermissionRequest` | — | `permission-request` | → `blocked` / `permission`（`tool_name` 只進日誌，不回傳） |
  | `PreToolUse` | `AskUserQuestion` | `ask-user-question` | → `blocked` / `question` |
  | `Notification` | `elicitation_dialog\|elicitation_url_dialog` | `elicitation` | → `blocked` / `elicitation` |
  | `PostToolUse`（`async`，T0594） | `AskUserQuestion` | `ask-user-question-done` | 只在 `blockedReason` = `question` 時清除；其他 reason / 未 blocked → `unchanged`（`HOOK_EVENT_CLEARS_ONLY`） |
  | `UserPromptSubmit`（`async`） | — | `user-prompt-submit` | 清除 |
  | `Stop`（`async`） | — | `stop` | 清除 |

  進入類同步執行（claude 等 hook 結束才顯示對話框，回報一定早於使用者回答）；清除類 `async: true`（claude 不等，不增加每次送出 / 結束的延遲）。`PostToolUse` 只掛 matcher `AskUserQuestion`（T0594：問題回答後該工具才執行完，**滑鼠**回答也觸發；不加全工具 matcher，每次工具呼叫都要啟動 node）。**不掛 `PermissionDenied`**（T0594 查證 claude 2.1.300 二進位：summary 為 `After auto mode classifier denies a tool call`，只在 `decisionReason.type === 'classifier'` 且 `classifier === 'auto-mode'` 時執行，payload `tool_name` / `tool_input` / `tool_use_id` / `reason`；使用者在權限對話框按拒絕走的 deny 路徑不呼叫任何 hook，也沒有 `PostToolUse` / `PostToolUseFailure`。classifier 拒絕時沒有對話框，平行工具呼叫中另一個工具的權限對話框仍開著時收到它反而會誤清）；`Notification` 的 `permission_prompt`（約 6 s）/ `idle_prompt`（約 60 s）不採用。`elicitation_url_dialog` 是 claude 2.1.300 對 URL 型 elicitation 的類型（二進位實讀），契約只寫 `elicitation_dialog`，T0590 一併算 `elicitation`。已在 `blocked` 再收到同一 reason → `unchanged`（`blockedSince` 不變）；不同 reason → 換成新的。
- **清除規則**：上表的 `user-prompt-submit` / `stop`（任何 reason）與 `ask-user-question-done`（只清 `question`：問題回答後權限對話框接著出現時不被誤清；T0594）；該分頁的**使用者輸入**（`PtyManager.noteUserInput`：本機視窗 / headless client 的 `pty:write`，非 `{ auto: true }`、非 `isTerminalAutoReply`，與 T0551 / T0566 同一判斷，`handlers/pty.ts` 不變）；PTY 結束（exit / kill，所以 `pty:restart` 也清）；Terminal Server recovery（全部清）。
- **回報 channel** `terminal:report-hook`（只供 helper 經 RemoteServer 呼叫；`proxied-channels-binding.test.ts` REGISTRY_ONLY、`headless-parity.test.ts` HELPER_ONLY；`HELPER_CHANNEL_ROLES` tower / worker 皆可，因此是 14 個 channel，未宣告的 shell 分頁拿的是 tower 權杖也能回報；`authorizeHelperInvoke` 直接放行）：參數 `{ event, toolName? }`，目標**永遠是呼叫者自己**（`ctx.helper.terminalId`，沒有 `terminalId` 參數，帶了也忽略）。回 `{ ok: true, terminalId, result: 'blocked' | 'cleared' | 'unchanged', state: 'blocked' | 'not-blocked', blockedReason? }`；參數不合（含沒有 helper 權杖的 server token / 本機呼叫、`toolName` 不符 `^[A-Za-z0-9_.:-]{1,128}$`）→ `INVALID_ARGS`；呼叫者 PTY 不在 → `NOT_FOUND`。`toolName` 只在 `permission-request` 保留。每次回報 O(1)；日誌只記轉換，`bat-scripts.log` 的 `unchanged` 每分頁每 5 s 最多一筆（`REPORT_HOOK_UNCHANGED_LOG_INTERVAL_MS`），不另設配額（RemoteServer 既有的 helper denial 節流照舊）。一次被接受的回報也把該分頁的 `blockedDetection` 設為 `hook`（證明它真的在回報），所以「`none` 不會 `blocked`」恆成立。
- **注入**（`buildBatMcpLaunchArgs`，與 BAT MCP 同一入口、同一組條件，本機與 headless 共用）：只對 `claude-cli` / `claude-cli-worktree`，`--mcp-config=` 之後接 `--settings=<dataDir>/bat-mcp/claude-settings.json`（`=` 形式：claude 2.1.300 的 `--settings <file-or-json>` 只收一個值，`=` 兩種情況都安全，比照 `--mcp-config=`）。用檔案不用 JSON 字串：hook 命令本身含引號，放命令列要再為 pwsh / bash / cmd 各包一層。設定檔只有 `hooks`（**不得**有 `disableAllHooks`、權限、模型或其他鍵；無權杖），內容不同才重寫（temp + rename，`ensureBatMcpFile`）。每個 hook：`{ type: 'command', command, timeout: 5[, async: true] }`，`command` = `<node> '<helperDir>/bat-hook.mjs' <event>`（`batHookCommand`）：claude 以 bash（Windows 為 Git Bash）執行 hook、Windows 沒有 Git Bash 時用 PowerShell，同一字串要兩邊都對 → node 命令是裸字（本機 `node`；headless `<installRoot>/bin/node`，POSIX 路徑含空白時單引號）、腳本路徑單引號（兩種 shell 都是字面值）、Windows 路徑轉 `/`（node 接受 `C:/…`，bash 會吃掉反斜線）；路徑含 `'`、或 Windows 的 node 命令需要引號 → 不注入 hooks。不用 claude 2.1.300 的 exec form（`args`）：較舊的 system claude 若不認得會把 `node` 當 REPL 跑。不注入 hooks：Settings「BAT MCP」關閉（MCP 一起關）、自訂參數已含 `--settings`（MCP 照常）、找不到 `bat-hook.mjs`（MCP 照常）、RemoteServer 未監聽、非 claude。自訂參數已含 `--mcp-config` 只略過 MCP，hooks 照注入。結果型別 `BatMcpLaunchResult` 多 `mcp` / `hooks` / `mcpReason` / `hooksReason`；日誌 `[bat-mcp] tab|dispatch agent=<id> terminal=<id> → injected: <args>[; mcp=no (<原因>)]; hooks=yes|no (<原因>)`（codex 不印 hooks）。
- **`blockedDetection` 記錄**：`createBatMcpLaunchArgs` 在請求帶 `terminalId` 時呼叫 host 的 `recordBlockedDetection` → `PtyManager.setBlockedDetection`（`hook` = 注入了 hooks，否則 `none`；codex 一律 `none`）。renderer 的 `withBatMcpLaunchArgs` 第 5 參數帶分頁 id（`agent:bat-mcp-launch-args` 第 4 參數；T0590 前的 server 忽略多出的參數，T0590 前的 renderer 不帶 → 不記錄），helper 派工由 `createAgentPromptCommandBuilder` 帶新分頁 id。記錄以 terminal id 為鍵、**與 PTY instance 分開**（`TerminalBlockedTracker`，最多 `BLOCKED_DETECTION_MAX` = 512 個 id），所以 claude-cli 分頁「先決定、後 `pty:create`」、`restart`、Terminal Server recovery 都沿用，PTY 結束後 `exited` 的回傳也還有；同一 id 之後的啟動決策取代它。PtyManager 的接點只有 `reportHookEvent` / `getBlockedState` / `setBlockedDetection` / `getBlockedDetection`，與 `clearActivity` / `noteUserInput` / `handleServerDeath` / `dispose` 內各一行。
- **hook 腳本** `scripts/bat-hook.mjs`：🔴 **不得影響 claude**：一律 exit 0、stdout 不輸出任何東西（`PermissionRequest` / `PreToolUse` 印 JSON 會替使用者做決定）、任何失敗靜默、總時限 `HOOK_DEADLINE_MS` = 1.8 s（stdin 300 ms、連線 1 s、invoke 1 s）。沒有 `BAT_REMOTE_PORT` / `BAT_REMOTE_TOKEN` → 立即 exit 0。從 stdin 只取 `hook_event_name` / `tool_name` / `notification_type`（`hookReport`：`hook_event_name` 與 argv 事件不符、`Notification` 不是 elicitation、`PreToolUse` / `PostToolUse` 不是 `AskUserQuestion` → 不送），只送事件名與（權限事件的）`tool_name`，**不送** `tool_input`、`tool_response`（AskUserQuestion 的答案）、prompt、訊息或權杖。連線重用 `scripts/bat-mcp.mjs` 的 `BatConnection`（憑證 pinning `_bat-cert.mjs`、frame id 比對 BUG-114；新增 `clientName` 選項，auth label `bat-hook`）。`bat-scripts.log`：helper `script: 'bat-hook'`、`event: 'report-hook'`、`hook`、`result`、`code?`、`durationMs`、`terminalId`；主行程 `mirrorToBatScripts('report-hook', { terminalId, hook, result })`（欄位名用 `hook`：兩個 logger 都把 data 展開在 `event` 之後，`event` 會被蓋掉）。出貨：安裝檔 `extraResources` `*.mjs` 已涵蓋；server bundle `serverBundleHelperScripts` 多 `bat-hook.mjs`（6 個，`verify-helper-bundle.js` 的必要清單也加了它）。
- **日誌** `[blocked]`：`[blocked] terminal=<id> → blocked reason=<r> (hook <event>[ tool=<name>])` / `→ cleared (<原因>)`（`hook user-prompt-submit` / `hook stop` / `user input` / `the PTY ended` / `Terminal Server recovery`）；被拒的回報 `[blocked] report-hook caller=<id> event=<e> → INVALID_ARGS|NOT_FOUND`。不記內容、不記權杖。
- **耗時**（T0590 實測，Windows）：一次回報（node 啟動 + TLS + 一個 invoke，分頁內 `spawnSync` 量）約 60 ms；連線失敗（死 port）3 ms 內結束。
- **實機查證**（T0590，內嵌 claude 2.1.300、Windows、`-p` + `--model claude-haiku-5-5` + `--settings=<file>`，hook 指向本 repo `scripts/bat-hook.mjs`、`BAT_REMOTE_PORT` 指向死 port、`BAT_HELPER_LOG_DIR` 暫存目錄）：`UserPromptSubmit` 與 `Stop` 都執行了 `bat-hook.mjs`（`bat-scripts.log` 各一筆 `CONNECT_FAILED`，async 照常跑），claude 輸出 `ok` 不受影響。權限 / AskUserQuestion / elicitation 在真實 claude 下未實測（yolo 的 `--dangerously-skip-permissions` 沒有權限提示；其餘需互動），由使用者實機驗收。
- **已知限制**：
  - 使用者 / 專案設定 `disableAllHooks: true`、或 managed settings 的 `allowManagedHooksOnly` → BAT hooks 也停用：`blockedDetection` 仍是 `hook`，但不會有事件。🔴 不得在 `--settings` 寫 `disableAllHooks: false` 反制。
  - `--dangerously-skip-permissions`（本機 CT yolo Worker 的自訂參數）下沒有權限提示，只會有 AskUserQuestion / elicitation。
  - **清除漏洞**（滑鼠回報屬 `isTerminalAutoReply`，不算輸入）：AskUserQuestion 以滑鼠回答 → T0594 起由 `PostToolUse(AskUserQuestion)` 清除。仍未涵蓋、`blocked` 維持到該回合 `Stop`（或使用者鍵盤輸入）的情況：**權限對話框以滑鼠允許或拒絕**（允許：不加全工具 `PostToolUse`，成本；拒絕：claude 2.1.300 不呼叫任何 hook，`PermissionDenied` 只給 auto-mode classifier，見事件表下方說明；以滑鼠拒絕通常結束回合，`Stop` 是否執行未查證）、AskUserQuestion 被拒絕 / 取消（tool 未執行，沒有 `PostToolUse`；以 Esc 取消算鍵盤輸入，會清）、elicitation 以滑鼠回答或逾時自行關閉。可補的候選（未實作，需塔台決定）：claude 2.1.300 有 `ElicitationResult` hook（`After a user responds to an MCP elicitation`）與 `Notification` 的 `elicitation_complete` / `elicitation_response` 類型，可清 `elicitation`；`PostToolBatch`（`Fires once after every tool call in a batch has resolved`）可在權限允許 / 拒絕後清 `permission`，但每批工具呼叫都要啟動 node，成本同全工具 `PostToolUse`。另：清除類為 async，理論上 `UserPromptSubmit` / `PostToolUse(AskUserQuestion)` 的回報可能晚於緊接著出現的下一個 `PreToolUse(AskUserQuestion)` 而誤清（之間至少一次模型回應、數百 ms 以上；hook 約 60 ms，實務上不會發生）。
  - codex 未支援（M1b-2）；Claude Agent SDK 面板不注入；raw command 模式不注入。
  - T0108 replay 的 PTY（BAT 重開、Terminal Server 存活）：重開前的 `blocked` / `blockedDetection` 只在記憶體、已遺失；分頁還原時 `startClaudeCliPty` 照樣以分頁 id 問一次啟動參數（PTY 存活、命令不重送），所以 `blockedDetection` 以**當下**設定重新記錄（設定沒變即與原啟動一致），存活 claude 的 hooks 用還原的權杖（T0576）照常回報。headless server 重啟後全部遺失。

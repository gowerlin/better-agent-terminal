# worktree 狀態查詢（PLAN-047 W1 / T0585）

> 從 CLAUDE.md「worktree 狀態查詢（PLAN-047 W1 / T0585）」節搬出（T0595）。本檔為該節完整原文；CLAUDE.md 該節保留用途、必守規則、唯一實作位置與本檔連結。

- **用途**：塔台決定合併順序、能否直接 `--ff-only`、是否派合併工單（D150：BAT 只提供唯讀信號，不合併）。唯一實作：git 查詢 `CtWorktreeService.status`（`electron/ct-worktree.ts`），handler `registerWorktreeStatusHandler`（`electron/worktree-status-handlers.ts`），本機（`main.ts`）與 headless（`createHeadlessTerminalQueryModule`）共用。只供 helper 經 RemoteServer 呼叫（`proxied-channels-binding.test.ts` REGISTRY_ONLY、`headless-parity.test.ts` HELPER_ONLY），`HELPER_CHANNEL_ROLES` 因此是 13 個 channel。
- **契約**（T0585「介面契約」，T0584 的 `bat_worktree_status` 與 CT 依此撰寫，不得單方更改）：channel `worktree:terminal-status`，參數 `{ terminalId?, workorder? }`（擇一；都沒給 = 呼叫者自己；兩者都給 → `INVALID_ARGS`）。`workorder` 以 `--close-worker` 的方式找 Worker（`findWorkerTerminals`；本機經 `withSavedWorkerOwnership`，BAT 重開後以已存分頁找到並取其 `ctWorktree`）；執行中的分頁：0 個 → 往下找（T0589，見下一條；T0585 為 `NOT_FOUND`）、範圍內 0 個 `NOT_OWNER`、範圍內多個 `AMBIGUOUS`（帶 `terminalIds`）。範圍 = T0582 `authorizeHelperQueryTarget`（`output` 存取）：tower 權杖 → 自己 + 自己的 Worker；worker 權杖 → 只有自己（讀不到塔台）；本機另以 `capabilityOrSavedTabOwnership` + 已存分頁的塔台補判（同 `--close-worker`，T0537 / T0576）。server token 連線不受範圍限制，但必須帶參數。
- **分頁關閉後（PLAN-047 Q3 / T0589）**：依序找，第一個有目標者即用，回傳 `source` 標明來源：
  - `live`：執行中的分頁（T0585 原行為，含 T0537 已存分頁）
  - `exited`：T0582 已結束分頁紀錄（`PtyManager.recordExit`，10 分鐘 / 32 筆內）**加記** `worktree`（`PtyInstance.worktree` 的複本；restart / 同 id 重建 → 以執行中為準，紀錄隱藏），另回 `exited: true`、`exitedAt`。`terminalId` = 已結束的 id；`workorder` = 比對已結束紀錄的工單號（正規化同 `--workorder`），範圍內多筆 → 取最近結束者，但來自不同塔台（只有 server token 會同時看到）→ `AMBIGUOUS`。範圍沿用 `authorizeHelperQueryTarget`，已結束的 Worker 以紀錄的 `towerTerminalId` 判斷（同 T0582）；有紀錄但不在範圍內 → `NOT_OWNER`，**不**往 git 走（與執行中分頁一致）
  - `git`：**只限 `workorder` 參數 + tower 權杖 + 呼叫者 PTY 仍在執行**（worker 權杖、server token、`terminalId` 參數都不走這一步 → `NOT_FOUND`）。`CtWorktreeService.statusFromGit`：主 checkout = 呼叫者 PTY 的 cwd（`PtyInstance.cwd`，建立時的 cwd）的 `git rev-parse --show-toplevel`；位置 = `ctWorktreeLocation(主 checkout, T####)`、分支 `ct/<T####>`、`base` = `git merge-base <主 checkout HEAD> ct/<T####>`；`git worktree list --porcelain` 在該位置登記為該分支（非 prunable）→ 照常讀 `dirty`；沒有登記（已 `--worktree remove`；或位置上是別的東西）→ 不讀該目錄，`dirty: null`、`dirtyCount: null`、`worktreeMissing: true`，其他欄位照算（`status(record, { unregistered: true })`）；分支不在 / cwd 不是 git repo → `NOT_FOUND`。`terminalId: null`。查詢與計算共用一個 10 s 逾時。**範圍理由**：資訊全部來自呼叫者自己 cwd 所在 repo 的 git，塔台本來就能自己跑 git；不放寬任何分頁的 metadata / 輸出範圍
  - 都沒有 → `NOT_FOUND`（同 T0585）
  - `ExitedPtyRecord.worktree` 只出現在 `worktree:terminal-status`；`terminal:list` / `whoami` / `get-state` 不帶它。BAT 重開後 T0108 replay 的 Worker 沒有 `worktree` 紀錄（T0537 的已存分頁在分頁關閉時一併移除），關閉後只能經 `git`
- **回傳**：非隔離分頁 → `{ ok:true, terminalId, source, isolated:false }`（不跑 git；`exited` 另帶 `exited` / `exitedAt`）。隔離分頁 → `{ ok:true, terminalId, source, isolated:true, workorder, path, branch, base, mainCheckout, head, mainHead, ahead, behind, dirty, dirtyCount, changedFiles, changedCount, outOfScopeFiles, touchesCtWorkorders, conflicts, computedAt, cached }`，視情況另有 `worktreeMissing` / `dirtyError` / `outOfScopeCount` / `workorderFile` / `conflictsError`。錯誤另有 `TIMEOUT`（整次查詢 `CT_WORKTREE_STATUS_TIMEOUT_MS` = 10 s）與 `GIT_FAILED`（`ct/<T####>` 分支或主 checkout 已不在；契約外新增，helper exit 1）。
- **欄位**（git 一律在主 checkout 執行，worktree 的 `status` 在 worktree 內；`execFile` + array args + 每個 5 s timeout，win32 帶 `-c core.longpaths=true`，沿用 `CtWorktreeService.git`）：
  - `head` = `refs/heads/ct/<T####>` 目前 SHA；`mainHead` = 主 checkout（`record.mainCheckout`）目前 `HEAD`
  - `behind` / `ahead` = `git rev-list --left-right --count <mainHead>...<head>` 的左 / 右
  - `dirty` = worktree 內 `git --no-optional-locks status --porcelain=v1 -z`（未追蹤目錄照 git 預設收合成 `dir/`；rename 取新路徑），最多 `CT_STATUS_DIRTY_MAX` = 100 筆、`dirtyCount` = 全部；worktree 目錄不在 → `dirty: null`、`dirtyCount: null`、`worktreeMissing: true`；status 失敗 → `null` + `dirtyError`
  - `changedFiles` = `git diff --name-only --no-renames -z <mainHead>...<head>`（三點 = 自 merge-base；`--no-renames` 讓改名的新舊路徑都列出），最多 `CT_STATUS_CHANGED_MAX` = 500 筆、`changedCount` = 全部
  - `conflicts` = 兩邊都前進（`ahead > 0` 且 `behind > 0`）時 `git merge-tree --write-tree --name-only --no-messages -z <mainHead> <head>`：exit 0 → `[]`、exit 1 → 衝突檔（第一個 NUL 欄位是結果 tree，略過、去重）、其他（例：無共同祖先、git < 2.38）→ `null` + `conflictsError`；任一邊沒前進（可 fast-forward）→ `[]`，不跑 merge-tree
  - `touchesCtWorkorders` = `changedFiles`（全部）是否含 `_ct-workorders/**`
- **`affects_files` 解析**（純函式 `parseWorkorderAffectsFiles` / `affectsFilePatterns` / `matchesAffectsPattern` / `outOfScopeFiles`）：工單檔 = `<mainCheckout>/_ct-workorders/<T####>-*.md`（不分大小寫，多個取檔名排序第一個，`workorderFile` 回報相對路徑），每次查詢重讀。frontmatter 的 `affects_files` 支援 block list（`- item`，引號 / 未引號、`#` 註解、折行）與 flow list（`[a, "b"]`，可跨行）；沒有工單檔、沒有 frontmatter、沒有該 key、值為 `null` / `~` / 空 → `outOfScopeFiles: null`（不是空陣列）；`[]` → 全部（`_ct-workorders/**` 除外）都算範圍外。每項取路徑：去掉全形（`（…）`）/ 半形（`(…)`）括號說明（未閉合則到結尾）與引號、反引號、「」『』，取第一個空白分隔 token；token 內以 `、` / `，` / `,` / `；` / `;` 列出多個路徑時**每個都算**（契約只寫「第一個 token」，本單擴充，例：`electron/main.ts、electron/remote/headless-entry.ts（接線）` 兩檔都在範圍內；分隔符兩側的空白先收掉，所以 `a/**（說明）、e2e（說明）` 也得到 `e2e`）；反斜線轉 `/`、去開頭 `./` / `/`。比對：`**` 任意字元（含 `/`）、`**/` 零或多層目錄、`*` / `?` 不跨 `/`；沒有萬用字元的路徑 = 該檔或其底下（目錄前綴，例 `e2e` 涵蓋 `e2e/**`）；win32 / darwin 不分大小寫。`_ct-workorders/**` 一律不算範圍外。
- **唯讀**：只有 `merge-tree --write-tree` 寫入物件庫（不建 ref、不動 index / 工作樹），`status` 帶 `--no-optional-locks`（不寫回 index 的 stat 快取）；不 checkout / merge / commit / 改分支。
- **快取**：`(mainCheckout, path, head, mainHead)` 相同即沿用 ahead / behind / changedFiles / conflicts（`cached: true`，`computedAt` 為當初計算時間），最多 `CT_STATUS_CACHE_MAX` = 64 筆（先進先出）；`dirty` 與工單 `affects_files` 每次重讀。只在記憶體。
- **helper**：`"${BAT_HELPER_NODE:-node}" "$BAT_HELPER_DIR/bat-terminal.mjs" --worktree-status [<T####> --notify-id "$BAT_TERMINAL_ID"]`。帶 `T####`（`--close-worker` 同文法，去空白、轉大寫）必須給 `--notify-id`（helper 端規則，不送 BAT）；不帶 = 查自己，此時給 `--notify-id` 為用法錯誤。與建立分頁的參數（含 `--isolation`）、`<command>`、`--close-worker`、`--delay-ms`、`--worktree`、`--set-role`、`--terminal-id` 互斥。stdout 一行 JSON（回傳去掉 `ok`）；exit `0` 成功（含 `isolated:false`）/ `3` NOT_FOUND / `4` NOT_OWNER / `5` AMBIGUOUS / `1` 其他（用法、連線、`UNSUPPORTED`（舊 BAT `No handler for channel`）、`FORBIDDEN`、`TIMEOUT`、`GIT_FAILED`、`INVALID_ARGS`）；stderr 另印 `worktree-status: <CODE>`。helper invoke 逾時 15 s。`bat-scripts.log` 事件 `worktree-status`（`workorder` / `notifyId` / `result` / `terminalId` / `source`（T0589；舊 BAT 沒有 → `null`）/ `isolated` / 各計數，不含檔名）。T0589 起參數、exit code、stdout 格式不變（新欄位直接出現在 JSON）；`NOT_FOUND` 訊息改為「執行中或 10 分鐘內關閉的分頁都沒有，且本塔台 repo 沒有 `ct/<T####>` 分支」。MCP `bat_worktree_status` 摘要在 `exited` / `git` 時註明 `(tab closed)` / `(no tab; from git)`。
- **稽核**：沿用 T0582 格式 `[helper-query] channel=worktree:terminal-status caller=<id|client:…> target=<id|workorder=T####> → ok source=<live|exited|git> isolated=true ahead=… behind=… dirty=… changed=… outOfScope=… conflicts=… cached=… ms=…`，與 `bat-scripts.log` 的 `helper-query` 事件；不記檔名。
- **耗時**（T0585 實測，Windows、git 2.56.0.windows.2，本 repo 的 temp clone：2618 個追蹤檔、2142 commits，中位數）：`rev-parse` ×2 各 35 ms、worktree `status` 87 ms、`rev-list --left-right --count` 36 ms、`diff --name-only` 37 ms、`merge-tree --write-tree` 37 ms；循序執行，未快取約 270 ms、快取命中約 160 ms（e2e 含 node 啟動的 helper 一次約 220 ms）。
- **已知限制**：分頁關閉後（T0589）：10 分鐘 / 32 筆內由已結束紀錄回答（任何在範圍內的呼叫者）；之後只有 tower 權杖以 `workorder` 查詢、且塔台分頁仍在執行時能經 `git` 找回（依呼叫者 PTY 建立時的 cwd 找主 checkout，塔台在別的 repo 開分頁則找不到；server token 的 helper / e2e 拿不到 `git` 來源）；`--worktree archive` 把分支改名為 `ct-archive/<T####>` 後，已結束紀錄的查詢回 `GIT_FAILED`、`git` 來源回 `NOT_FOUND`（分支已不在 `ct/` 名下）；已結束紀錄只在記憶體（BAT / server 重啟即消失）；headless 的範圍只有權杖（server 重啟後權杖與紀錄全失）；`outOfScopeFiles` 以主 checkout 工作樹中的工單檔為準（未提交的修改也算）；`affects_files` 解析是常見寫法的近似，不是完整 YAML；`conflicts` 預測不含 rerere / 自訂 merge driver；git < 2.38 沒有 `merge-tree --write-tree` → `conflicts: null`。
- **給合併判準（CT-T016）**：可直接 `git merge --ff-only ct/T####` 的條件 = `behind == 0` 且 `dirty` 為空（未提交的變更不會進分支）；`behind > 0` 時看 `conflicts`：`[]` 表示 merge-tree 預測可乾淨合併（仍需 merge commit 或 rebase），非空 / `null` 交給合併工單；`outOfScopeFiles` 非空或 `touchesCtWorkorders` 為真時先人工 / 塔台確認；`cached` 只表示 git 結果沿用，`head` / `mainHead` 永遠是當下值。分頁關閉後仍可查（T0589：`--close-worker --worktree keep|remove` 之後照樣 `--worktree-status T####`，`source` 為 `exited` 或 `git`；`worktreeMissing: true` 時 `dirty` 不可得；BAT 的 `--worktree remove` 遇未提交變更不會刪，所以經它移除的 worktree 沒有遺漏的變更，以 `behind` / `conflicts` 判斷即可），不必改用 git 自行重算。

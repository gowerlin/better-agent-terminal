# PLAN-069 — 待辦分頁：推薦項與放棄

## 動機

PLAN-068 把塔台的提問搬到側邊欄「待辦」分頁後，使用者發現兩件事（2026-11-25 第一百三十二 session）：

1. 終端的互動選單會把推薦項排第一並標「(Recommended)」；契約 v2 的 `awaiting_user[]` 沒有推薦欄位，待辦分頁看不出塔台建議哪一項。自由回答欄仍在（T0908），不受影響。
2. 有時整批不做、或原問題已經不合時宜、要改變方向，所有選項都不適用。現在只能逐筆打自由文字，沒有「放棄」或「全部清除」。

## 契約草案（BAT 提案，待 CT 塔台同意；不得單方更改）

詳見交辦稿 `_handover-2026-11-25-inbox-recommended-dismiss.md`。要點：

- **C-1 `awaiting_user[].recommended`**：選填字串，值是同一筆 `options` 裡的代號（不分大小寫比對）；沒有或對不到 = 沒有推薦（BAT 不報錯）。CT 仍把推薦項排第一。
- **C-2 單筆放棄的回答**：`U-n：放棄[ <原因或新方向>]`、`A-n：略過[ <原因>]`。「放棄」「略過」是保留字，只在冒號後第一個詞時成立。
- **C-3 批次放棄的回答**：一行列出明確編號，例 `U-1、U-3、U-4：放棄 <原因>`、`A-2、A-3：略過 <原因>`。「全部放棄」由 BAT 在送出當下展開成明確編號，**不送萬用字元**（避免把使用者還沒看到、剛寫入的項目一起放棄）。
- **C-4 塔台收到放棄**：從 `awaiting_user` / `user_actions` 移除該筆、記決策；不套用任何選項；相關工單維持暫停；有文字時依文字重新對齊；整批放棄只寫一筆決策。
- **C-5 版本閘門**：BAT 只在塔台宣告支援的契約版本時顯示放棄 / 批次控制項與推薦標記（是升 `--bat-contract 3`，還是 v2 的相加欄位，由兩方協商）；舊 CT 收到 `U-n：放棄` 會當成自由回答「放棄」處理，批次格式舊 CT 不認得 → 不顯示。

## 0. 診斷：為什麼 W1 首頁看不出整合優勢

1. **定位被稀釋**：首頁以「跨平台終端機聚合器」為主標，CT 只是三張卡之一。BAT 最有差異化的地方（塔台 / Worker 自動協作）被放在次要位置。
2. **只列名詞，沒有動詞與結果**：功能卡描述「有什麼」，沒有描述「原本卡在哪、現在怎麼不卡」。整合的價值在於**整個循環自動閉合**，靜態功能清單表達不出來。
3. **沒有對照**：讀者不知道「只用 BAT」「只用 CT」「兩個一起用」差在哪，也就看不出為什麼要一起用。
4. **沒有證據**：沒有真實畫面、沒有實際使用數據。

## 3. 定位與訊息層級

- **一句話（hero 主標，待使用者選定，見 § 11 Q1）**：推薦「**一個塔台，指揮整隊 AI Agent**」
- **副標**：「你做決定，Agent 做事。開單、派工、回報、提問、收尾——Better Agent Terminal 與 BMad Control Tower 幫你串成一個會自己推進的循環。」
- **三根支柱**（貫穿全站）：
  1. **自動閉環**：派工 → 執行 → 回報 → 驗收 → 回收，不用在視窗之間搬文字
  2. **自動，但不失控**：自主程度可調；範圍變更、不可逆、對外發布一定停下來問你；每個分頁權限分離
  3. **看得見、留得住**：每個 Agent 的狀態一眼看清；每個決定與結果都寫在 repo 裡
- **分工比喻（機場）**——用在 `/control-tower` 一張圖，首頁只點到一句「Control Tower 定規則，BAT 提供跑道、無線電和雷達」：

| 機場 | BAT × Control Tower |

| 塔台的調度規則 | Control Tower：對齊需求、開單、派工、驗收、決策 |
| 飛行計畫 | 工單（目標、範圍、驗收條件、禁止事項） |
| 跑道與登機門 | BAT 的工作區與分頁：每個 Worker 一條跑道 |
| 無線電 | BAT 的完成通知與提問通道 |
| 雷達 | BAT 的狀態偵測與縮圖標示 |

### 4.2 故事：「AI 協作開發的 7 個卡關時刻」（`#story`）

開場一句：「一個虛構但真實的早上：你要替 **demo-shop** 的結帳頁加上**折扣碼**。」

版面：垂直時間軸；每章 = 時間標籤 + 標題 + 左「**以前**」卡（灰階、問題情境）+ 右「**BAT + CT**」卡（品牌色、解法）+ 一張小插圖 + 分工標籤（`BAT：…` / `CT：…`）。手機版改上下堆疊（先以前、後解法）。

| 時間 | 卡關時刻（以前） | BAT + CT 怎麼解 | 分工標籤 | 插圖 |
|---|---|---|---|---|
| 09:00 | **一個對話，越聊越長**：從需求聊到實作再聊到除錯，兩小時後 Agent 開始忘記一開始說好的規則，改 A 壞 B，你只好重新解釋一次 | 你只跟**塔台**談需求。塔台把工作拆成三張**工單**——每張寫清楚目標、範圍、驗收條件與不准碰的東西——再為每張開一個**全新的 Worker**。每個 Worker 只帶一張工單的脈絡上工，塔台只保留進度與決定 | CT：拆工單、管脈絡／BAT：每張工單一個獨立分頁 | 一條長對話 vs 塔台 + 三個乾淨分頁 |
| 09:20 | **你成了人肉剪貼簿**：開新終端、切到專案目錄、貼 prompt、等它做完、把結果複製回來，再開下一個 | 塔台一個指令，BAT 就在**同一個工作區**開好 Worker 分頁，帶上這個專案設定的 Agent 與參數，並確認 Agent 真的啟動了。Worker 做完，通知**直接送回塔台**，塔台自動接手驗收 | BAT：派工、啟動確認、完成通知／CT：何時派、派給誰 | 塔台 → 分頁的箭頭，通知回流 |
| 10:05 | **五個終端，三個在等你——是哪三個？**：有的停在權限確認、有的在問問題、有的早就做完，只能一個一個點進去看 | Worker 分頁標題就是它的工單編號；縮圖直接標出 **⚠️ 在等你**、**? 在等塔台答覆**、**✓ 已回報**。做完的分頁等輸出安靜後自動關閉，也能一鍵關閉所有已回報的分頁 | BAT：狀態偵測、縮圖標示、自動回收 | 縮圖列 ⚠️ / ? / ✓ |
| 10:40 | **Agent 停下來問你，而你正在開會**：它問完就停著，你回來時一小時過去了 | Worker 用結構化通道**問塔台**。「金額四捨五入還是無條件捨去？」這種範圍內的技術選擇，塔台依工單與專案慣例直接回答並記下理由；「折扣碼能不能和會員折扣疊加？」屬於需要你決定的商業規則，塔台才停下來問你（yolo 模式） | BAT：提問通道／CT：代決邊界 | 兩個問題泡泡：一個塔台代答、一個轉給你 |
| 11:15 | **兩個 Agent 改了同一個檔案**：為了快讓它們同時開工，合併時才發現都改了 `cart.ts` | 派工前塔台先比對每張工單會動到的檔案，有重疊就提醒你。需要平行時，Worker 在**獨立的 git worktree**（自己的分支）裡做；收單前塔台查清楚領先多少、落後多少、有沒有未提交的變更，再決定合併順序 | CT：重疊檢查、合併判斷／BAT：worktree 隔離、合併前狀態 | 主線 + 兩條 `ct/` 分支 |

結尾一句（獨立大字）：「**12:30，三張工單都收單，Worker 分頁已經關閉，決定都寫在 repo 裡。這個早上你只做了三個決定：要做什麼、折扣能不能疊加、要不要合併。**」

### 4.3 為什麼要一起用（三欄對照）

標題：「BAT 提供跑道，Control Tower 提供調度——少一個，循環就斷了」

| | 只用 BAT | 只用 Control Tower | **BAT + Control Tower** |
|---|---|---|---|
| 拆工作、定範圍 | 你自己想 | 塔台拆成工單 | 塔台拆成工單 |
| 開 Worker | 手動開分頁、輸入指令 | 塔台給你指令去開（部分終端能自動開分頁），沒有啟動確認 | 塔台直接開好分頁、放進對的工作區、確認啟動 |
| 做完之後 | 你自己去看 | Worker 印出訊息，你貼回塔台 | 通知自動送回塔台，塔台接手驗收 |
| Agent 有問題 | 停下來等你 | 寫進工單，等你轉告塔台 | 結構化問塔台：範圍內代答，其餘轉給你 |
| 誰在等你 | 縮圖標示 ⚠️ | 逐一查看 | 縮圖 ⚠️ / ? / ✓ 一眼看清 |
| 平行開工 | 自己避開衝突 | 有重疊檢查，隔離要自己做 | 重疊檢查 + worktree 隔離 + 合併前狀態 |
| 收尾 | 手動關分頁 | 手動關分頁 | 已回報的分頁自動回收 |
| 紀錄 | 聊天紀錄 | 工單與決策紀錄 | 工單與決策紀錄 |

手機版：改成三張可左右切換的卡片或「以 BAT + CT 欄為主、其他兩欄收合」，不得出現水平捲動的整頁。

### 4.4 自動，但不失控

- **自主程度（`<AutonomyDial>`）**：`off` 只給你指令 → `ask` 每次先問你 → `on` 自動派工 → `yolo` 塔台自主推進，遇到斷點才停
- **一定會停下來問你的時候（斷點）**：範圍要擴大、刪除或不可逆的操作、對外發布（push、發版）、需要你偏好的選擇、連續失敗
- **權限分離**：每個分頁有自己的權杖——塔台只能派工、關閉自己派出的 Worker；Worker 只能回報給自己的塔台
- **不代你按鍵**：BAT 與塔台都不會在 Worker 分頁替你輸入或按鍵
- **問答不落地**：Worker 問塔台的內容只存在 BAT 記憶體、會遮罩祕密，日誌只記長度與結果

### 4.5 實績：「BAT 自己就是這樣開發的」（是否放數據待使用者決定，見 § 11 Q2）

- 數字（四捨五入，避免頻繁更新；標「截至 2026 年 10 月」）：**600+ 張工單、150+ 張 bug 單、60+ 個預覽版、5,000+ 個單元測試**，2026 年 4 月起

## 7. 視覺設計方向

- **設計語言單一來源**：實作前先產出 `docs/design/site-design-language.md`（不放 `site/`，避免被渲染成頁面），從 BAT 本身的 UI 抽取：分頁標題格式、縮圖狀態符號與顏色（⚠️ / ? / ✓）、Stepper 設計語言（`docs/design/bat-stepper-design-language.md`）、品牌色。網站插圖與 App 外觀一致
- **品牌色**：取自 App 圖示 `assets/icon.svg` 的紫（`#a855f7` / `#c084fc` / `#e9d5ff`）設為 VitePress `--vp-c-brand-*`；圖示中的暖色（`#feca57`、`#ff6b6b`、`#ff9ff3`）只做點綴；狀態色以 BAT UI 實際值為準
- **Hero**：深色漸層帶（淺色模式也保留），營造終端機氛圍
- **插圖**：先用 HTML / CSS / SVG 做「BAT UI 風格示意」（分頁列、縮圖、事件紀錄、分支圖）——清晰、跟著深淺色切換、沒有隱私風險、不需維護截圖；真實截圖與短片由 W3 補充，不取代示意
- **動態**：CSS keyframes / Vue；`prefers-reduced-motion` 一律靜態；捲出畫面暫停
- **版面**：手機寬度 16 px 邊距、無整頁水平捲動；故事章節手機版上下堆疊；表格窄螢幕改卡片
- **無障礙**：每個插圖有文字等價說明（`aria-label` / 隱藏描述）；狀態不只靠顏色（符號 + 文字）；對比 ≥ WCAG AA
- **元件清單**（`site/.vitepress/theme/components/`）：`TowerDemo`、`StoryTimeline`（+ `StoryChapter`）、`CompareMatrix`、`AutonomyDial`、`StatsCounter`、`FeatureGrid`；`DownloadLinks` 沿用

## 8. 文案與內容規則

- 繁中、第二人稱「你」、寫給使用者；名詞統一：塔台、Worker、工單、派工、回報、回收、提問、斷點、工作區、分頁
